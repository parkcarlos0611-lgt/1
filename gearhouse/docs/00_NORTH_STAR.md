# GEARHOUSE 기준 설계서 (North Star)

> 2026-11-24 작성. **앞으로의 모든 작업은 이 문서를 기준으로 한다.** 방향이 바뀔 때만 이 문서를 고친다. 세부 결정은 `docs/decisions.md`, 지금 상태와 다음 할 일은 `docs/STATUS.md`에 있다.

## 1. 이 게임은 무엇인가
- **자동차 회사 경영 + 차 설계 + 3D 주행**을 하는 게임이다.
- 핵심 재미는 **차를 자유롭게 만드는 것**이다. 플레이어가 차의 모양을 직접 정하고, 엔진과 기계를 얹고, 직접 몰아 보고, 팔고, 경주한다.
- **자유도가 생명이다.** 보이지 않는 세부 수치보다 **눈에 보이는 부분의 자유도**를 먼저 한다.

## 2. 차를 만드는 방식 (가장 중요)
1. **실루엣:** 차체는 "바탕 차"가 아니라 **곡선으로 정의된 실루엣**이다.
   - 실루엣 라이브러리에서 고르고, 두 실루엣을 섞고, 손잡이를 끌어 자연스럽게 변형한다.
   - 여러 차의 **형태 조각**(코, 캐빈, 데크, 꼬리, 버팀벽 등)을 이어 붙일 수 있다.
2. **창문(글라스하우스):** 실루엣과 따로 고른다.
3. **붙이는 부품(장식물):** **미리보기가 있는 수백 종의 라이브러리**에서 골라 차체 표면 어디에나 붙인다.
   - 예: 헤드·테일램프, 그릴, 흡기구, 루버, 미러, 윙, 배기구, 휠, 배지, 범퍼
   - 위치, 크기, 각도, 깊이를 조절하고, 좌우 대칭은 자동이다.
   - 표면형은 곡률을 따라 붙고, 파는 부품은 차체에 구멍을 내고 그 안을 막는다.
4. **엔진·기계:** 엔진 공방에서 엔진을 설계해 보관함에 두고 얹는다. 구동계, 서스펜션, 장비도 정한다.
5. **보이는 것이 곧 성능:** 실루엣과 부품에서 앞면적, 공기 저항, 다운포스, 냉각, 무게를 계산한다.
- **라이브러리는 실제 차에서 수확한다.**
  - 실차를 하나 추가할 때마다 순서대로 따온다: 차체 형상 → 창문 → 장식물 → 엔진.
  - 실차 수백 종이 부담되면 특징 부품만 따온다.
  - 지금까지 만든 차(NSX, F355, EB110, 디아블로, 1930년대 차들)는 **수확할 원본**이다. 완성품으로 쓰는 것이 목적이 아니다.
  - 절차는 `docs/systems/107_car_intake_pipeline.md`에 있다.
- Automation(자동차 회사 경영 게임)과 비교하면:
  - 부품을 자유롭게 붙이는 방식은 같다.
  - 차체는 그보다 더 자유롭다. 실루엣을 섞고, 조각을 잇고, 직접 끌어 변형한다.
  - 부품은 우리가 만든 실차에서 따온다.

## 3. 시대와 범위
- **1990년대부터 시작한다.** 출력에 상한을 두지 않는다. 1990년대에도 400 km/h급 시판차가 있었다.
- 1930년대 차는 나중에 **클래식카·리스토어** 콘텐츠로 쓴다. 녹과 바랜 칠 효과를 입히고, 경매와 원형 보존 점수를 둔다(0.4).
- 버전 계획:

| 버전 | 내용 |
|---|---|
| 알파 0.1x | 설계·시험 샌드박스: 차 만들기, 엔진, 시험장, 레이스 |
| 0.20 | 회사: 제작 공정, 돈과 시간, 3D 회사 허브 |
| 0.30 | 시장: 손님층, 차종, 판매, 레이스 규정 |
| 0.40 | 클래식: 1930년대 리스토어 |

## 4. 화면과 스타일
- **화면:** 한 페이지 게임이다. 타이틀 → 차고 → 빌더 / 엔진 공방 / 시험장 / 레이스 / 설정 / 정보로 이어진다. 시험 주행도 새 창 없이 같은 페이지에서 한다.
- **모델 스타일:** FR Legends처럼 깔끔한 로우폴리. 곡선이 필요한 차는 곡선을 살리고, 램프 같은 부품은 실제 형상으로 만든다.
- **그래픽 효과:** 사실적으로 한다. 카툰 모드도 둔다. 카툰 그래픽 향상은 상세 계획을 따로 세운다.
- **휴대폰과 PC** 모두 된다.

## 6. 작업 원칙
1. **보이는 자유도가 먼저**이고, 보이지 않는 세부는 그다음이다.
2. **한 번에 1~2개 작업만** 한다.
3. 단계마다 **직접 보실 수 있는 미리보기 링크**를 만들고, 확인받은 뒤 넘어간다. 이 환경에는 그래픽 카드가 없어서 화면 확인은 실제 기기가 빠르고 정확하다.
4. 모양 품질은 **Fable**이 맡고, 구조·물리·화면은 **Opus**가 맡는다.
5. 큰 작업 전에는 계획을 보고하고 검토받는다. 검토만 요청하면 구현하지 않는다.
6. 답은 한국어로 한다. 커밋에는 정해진 트레일러를 붙이고, 지정된 브랜치에만 올린다.
