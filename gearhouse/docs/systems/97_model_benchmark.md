# 97 · 제작 모델 기준점: F355 키트판 Opus 대 Fable (검토 172)

같은 차(F355), 같은 시트와 자료, 같은 지시(문서 93의 디테일 목록 + 키트 확장)로 두 에이전트가 따로 만든다. 결과를 같은 기준으로 매겨, 앞으로 어떤 모델에 무엇을 맡길지 정하는 **기준점**으로 삼는다.

## 두 판
| | Opus판 | Fable판 |
|---|---|---|
| 키트 | `render/car/kit/` (원래 키트를 확장) | `render/car/kitb/` (같은 시점 키트의 복사본을 확장) |
| 조립 명세 | `render/car/cars/f355.kit.ts` | `render/car/cars/f355.kitb.ts` |
| 메시 | `render/car/mesh_f355_kit.ts` | `render/car/mesh_f355_kitb.ts` |
- 키트를 따로 두는 이유: 두 에이전트가 같은 키트 파일을 동시에 고치면 서로 덮어쓴다. 고른 쪽의 키트 확장을 나중에 `kit/`로 합친다.

## 평가 기준 (점수표)
| 항목 | 재는 법 | 비중 |
|---|---|---|
| 1. 실차 닮음 | 렌더 대비 정면·후면·측면 나란히 보기(사람 판단), 4면도 윤곽 오차(mm) | 30 % |
| 2. 디테일 목록 | 문서 93의 8개 항목(파낸 그릴·안개등, 홈 안의 원형 램프, 덕테일과 들어간 패널, 옆 홈, 루버와 V8, 팝업 램프, 별 휠, 보닛 하이라이트)을 하나씩 됨/부분/안 됨으로 매긴다 | 25 % |
| 3. 이음매와 품질 | 이음매 검사(열린 가장자리, 과다 사용, 겹친 면, 접힌 면), 실시간 렌더러 하이라이트 | 15 % |
| 4. 키트 확장의 일반성 | 새 형태(뾰족한 코, 루버 데크 등)에 F355 숫자가 박혀 있지 않은지, 다른 차가 쓸 수 있는지, 교체 시험(늘이기, NSX 꼬리·휠 끼우기) | 15 % |
| 5. 비용 | 토큰(대화 길이), 시간, 도구 사용 횟수 | 15 % |
- NSX 일치 테스트가 그대로 통과해야 한다(필수).

## 결과를 쓰는 법
- 앞으로 차 제작에서 **누가 무엇을 맡을지**를 이 결과로 정한다.
  - 예: 키트 구조(형태 추가)는 점수가 좋은 쪽, 마지막 디테일 다듬기는 닮음 점수가 좋은 쪽.
