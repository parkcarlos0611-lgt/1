# 검토 20 — 평면도를 함께 만들기, 크롬과 명암의 구분, 200종을 게임에 넣기

기획자 지시(2026-11-19)에 대한 검토다. 1장의 그리기 수정은 적용했고, 나머지는 결정을 기다린다.

## 1. 크롬 장식과 명암이 섞여 보이는 문제

### 1-1. 원인

| 요소 | 고치기 전 |
|---|---|
| 칠의 반사띠 | 칠 색을 65% 하늘 회색과 섞은 거의 흰 색, 1~2px 가는 선 |
| 크롬 줄(몰딩) | 크롬의 흰 색, 1px 선 |

둘 다 "어두운 칠 위의 가는 흰 선"이라 눈으로 가려지지 않았다. 실제로는 성질이 다르다.

| | 칠의 반사 | 크롬 |
|---|---|---|
| 색 | 그 칠의 색이 밝아진 것(녹색 차면 밝은 녹색) | 차가운 푸른 흰색, 칠 색과 무관 |
| 모양 | 넓고 부드러운 띠, 가운데가 가장 밝고 위아래로 흐려진다. 끝이 흐려진다 | 단단한 선, 끝이 또렷하다 |
| 그림자 | 없음 | 위에 얇은 어두운 선(턱), 아래에 그림자 |
| 위치 | 둥근 면의 등성이(펜더, 지붕, 보닛) | 정해진 부품 자리(허리선, 보닛 옆, 빗물받이, 창틀) |

### 1-2. 적용한 것

- 반사띠의 가장 밝은 색을 칠 색 62% + 옅은 회색 38%로 바꿨다. 녹색 차의 반사는 밝은 녹색, 크림색 차는 밝은 크림색이 된다.
- 반사띠를 너비 2~4px의 부드러운 띠로 그린다: 가운데가 가장 밝고, 위아래와 양 끝으로 한 단계씩 흐려진다.
- 크롬 줄은 바로 위 1px를 어둡게(턱), 아래 1px를 어둡게(그림자) 해 단단한 선으로 보이게 했다.
- 그릴 살을 곱고 어둡게 바꿨다(밝은 줄무늬처럼 보이던 것).
- 부품 라이브러리: 전조등에 받침대 없는 탄환형(세단), 범퍼 끝 둥글림을 키우고 뒤쪽 두 번째 가드를 더했다.

### 1-3. 규칙으로 남길 것

- 칠의 가장 밝은 단계는 반사띠에만 쓴다. 크롬 줄과 같은 밝기의 흰색을 칠에 쓰지 않는다.
- 크롬은 부품 자리에만 둔다. 반사는 둥근 면에만 둔다.
- 비교 도구에서 두 가지를 따로 센다: 원본의 크롬 줄(차가운 흰색, 칠 색과 무관)과 반사(칠 색이 밝아진 것)를 분석 도구가 나눠서 뽑는다(지금은 한데 뽑는다. 고칠 일).

## 2. 평면도(위에서 본 그림)를 함께 만들기

### 2-1. 쓰임

탑뷰 주행(트랙 경주, 랠리, 조종성 시험), 공방 바닥에 놓인 차, 설계 화면의 평면도, 주차장.

### 2-2. 한 설계에서 네 그림

정면·후면 검토(19)와 같은 원칙이다. 평면은 측면의 길이 방향 값과 정면의 폭 방향 값을 나눠 쓴다.

| 평면이 가져오는 것 | 평면이 따로 갖는 것 |
|---|---|
| 측면: 각 부분의 앞뒤 위치(범퍼, 그릴, 보닛, 앞창, 지붕, 뒷창, 트렁크), 바퀴 위치 | 길이 방향으로 본 폭의 변화(보닛이 앞으로 좁아짐, 객실의 폭, 꼬리가 좁아짐) |
| 정면·후면: 각 부분의 폭(지붕 폭, 펜더 폭, 윤거) | 펜더의 평면 모양(물방울꼴), 앞창·뒷창이 위에서 보이는 모양 |

- 반쪽 윤곽(좌우 대칭)을 길이 방향으로 적는다. 측면·정면과 같은 랜드마크 이름(카울, 객실 끝, 바퀴 중심)을 쓰므로 비례를 고치면 네 그림이 함께 바뀐다.
- 높이는 평면에 없지만, 색(위가 밝음)과 지붕·보닛의 둥근 정도를 측면 높이에서 계산해 음영을 준다.
- 탑뷰 주행의 스프라이트 스태킹(높이별 단면 쌓기)은 이 평면 + 측면 + 정면에서 높이별 단면을 계산해 만든다. 따로 그리지 않는다.

### 2-3. 품과 순서

- 참고 시트에 평면이 있으므로 같은 방법(격자 실측, 분석 도구)으로 잰다.
- 차 한 대의 품: 측면 1, 정면·후면 합쳐 0.5, 평면 0.3 정도. 측면이 정해 둔 위치를 쓰므로 평면은 가장 가볍다.
- 순서: 정면·후면과 함께 만든다. 정면이 정한 폭을 평면이 그대로 쓰기 때문이다.

## 3. 200종을 게임에 넣기 (시스템이 붙은 형태)

### 3-1. 한 종이 게임에 들어가면 갖는 것

| 묶음 | 내용 | 어디서 |
|---|---|---|
| 그림 데이터 | 측면·정면·후면·평면 윤곽, 부품(라이브러리 형식과 값), 특징(반사, 크롬, 이음새) | 참고 시트 실측 |
| 제원 | 전장·전폭·전고·축간거리·윤거, 무게, 엔진 형식·배기량·출력, 변속기, 최고 속도 | 목록표(확인 필요) + 구동계 계산 |
| 정체 | 지은 이름, 지은 업체, 차종, 값대, 출시·단종 해, 나라 | 검토 16 |
| 쓰임 | 플레이어가 고를 수 있는 뼈대인지, 보이기만 하는 차인지, 경쟁 모델인지 | 아래 |

### 3-2. 세 가지 역할

| 역할 | 설명 | 대수(제안) |
|---|---|---|
| 뼈대 | 플레이어가 설계에서 고르는 차체 뼈대. 11자리 부품 교체와 치수 편집이 된다 | 시대와 차종마다 고루, 1930년대 약 40, 1940년대 약 40 |
| 경쟁 모델 | 동네 등록부의 업체 라인업. 신문, 손님의 지금 차, 판매 경쟁, 품평회에 나온다 | 업체 10곳 × 시기 2~4 = 약 60 |
| 길 위의 차 | 배경. 낡음 4×5단계, 칠 색 | 모든 종 |

한 종이 여러 역할을 겸한다. 실제로 그 시대에 잘 팔린 대중차는 세 역할을 모두 한다.

### 3-3. 시스템 연결

| 시스템 | 200종이 주는 것 |
|---|---|
| 설계 | 시대·차종으로 거른 뼈대 목록. 그해까지 나온 뼈대만 보인다 |
| 부품 | 200종에서 나온 부품 형식이 라이브러리의 선택지가 된다(그릴 약 50형, 전조등 약 20형 …) |
| 경쟁사 | 업체마다 집안 모양(그 업체 모델들의 부품 형식에서 뽑음)과 라인업 |
| 판매 | 손님이 기대하는 값과 성능을 경쟁 모델이 정한다 |
| 신문·잡지 | 신형 출시, 시승기, 광고에 그 모델의 그림 |
| 길 | 대수 기반 교통(검토 16) |
| 시대 | 출시 해에 맞춰 등장하고, 단종 뒤에도 몇 해 길에 남는다 |

### 3-4. 작업량과 방법

- 차 한 대(측면·정면·후면·평면)를 지금 방식으로 만드는 데 드는 품이 가장 크다. 견본 3종이 끝나면 한 대의 실제 품을 재고, 200종의 일정을 다시 낸다.
- 품을 줄이는 길: 같은 차체를 나눠 쓴 짝(같은 시트의 형제 차)은 뼈대 하나 + 부품 차이로 만든다. 부품 라이브러리가 쌓일수록 한 대가 빨라진다. 분석 도구가 반사·창·크롬을 미리 뽑아 준다.
- 차례: 슬라이스(미국 1930~1935)에 필요한 것부터. 그다음 1930년대 나머지, 1940년대.
- 실제 차 이름은 작업용 목록(docs/reference)에만 있다. 게임 데이터에는 지은 이름만 들어간다.
- 제원 확인: 목록표의 치수는 기억에서 나온 값이다. 게임에 넣기 전에 확신 "낮음"(38대)부터 자료로 확인한다.

### 3-5. 데이터 꼴(제안)

```
data/bodies/<id>.json      그림 데이터(네 방향, 부품, 특징)

data/makers/us.json        업체: 집안 모양(부품 형식 목록), 규모, 값대, 라인업
```

## 4. 결정이 필요한 것

1. 크롬과 반사의 구분 규칙(1-3)을 그대로 둘지.
2. 평면도를 정면·후면과 함께, 한 설계에서 만들지. (추천: 그렇게)
3. 200종의 역할을 뼈대 / 경쟁 모델 / 길 위의 차로 나누고, 한 종이 겸할 수 있게 할지. (추천: 그렇게)
4. 200종의 차례: 슬라이스용(미국 1930~1935) → 1930년대 나머지 → 1940년대. (추천: 그렇게)
5. 200종 작업은 견본 3종의 네 방향이 끝나고 한 대의 실제 품을 잰 뒤 일정을 정할지. (추천: 그렇게)
