## 2. 기술 스택 & 저장소 구조

기존 저장소의 `cage/` 프로젝트와 같은 방식(빌드 단계 없는 바닐라 JS, `index.html` + `src/` 모듈, Playwright 검증 스크립트, `Tuning` 데이터화)을 따른다. 다만 이 게임은 파티클·후처리 비중이 크므로 **렌더러는 처음부터 WebGL2**로 간다.

- **언어/런타임**: 바닐라 JavaScript(ES2020), 외부 의존성 없음, `file://`로도 실행 가능
- **렌더링**: 자체 경량 WebGL2 스프라이트 배처 + 파티클 인스턴싱 + 후처리 패스. Canvas2D는 디버그 오버레이에만 사용
- **물리**: 자체 구현(2D 강체 + 서스펜션 + 높이장 지형). 범용 엔진(Matter.js 등)은 궤도/토양 모델에 맞지 않아 쓰지 않는다
- **시뮬레이션 루프**: 고정 스텝 120 Hz(차량), 탄도는 스텝 내 서브스텝 + 선분 레이캐스트. 렌더는 보간
- **결정론**: 시드 기반 난수 + 고정 스텝 → 리플레이·킬캠 재생 가능

## 3. 스케일 & 카메라 — "실제 비례"와 "보이는 화면"의 충돌 해결

실제 교전거리(걸프전 전차전은 1.5~3 km, 최대 4 km급)를 그대로 쓰면 1920 px 화면에 3 km를 담을 때 전차가 몇 px밖에 안 된다. 그래서 **월드는 실측, 화면은 다단계**로 처리한다.

- **월드 단위**: 1 unit = 1 m. 모든 데이터(치수, 속도, 탄속)는 SI 단위
- **카메라 줌 3단계(연속 보간)**
  - 근접 시점: 1 m ≈ 40 px. 궤도·보기륜·주퇴복좌 디테일 감상용
  - 전투 시점(기본): 1 m ≈ 12~20 px. 자차 주변 300~500 m
  - 전술 시점: 전체 교전 구역(3~5 km), 차량은 아이콘 + LOD 실루엣
- **조준경 PiP(Picture-in-Picture)**: 포수 조준경(M1A1 GPS 10배 / 열상) 시야를 화면 한쪽 원형 창에 표시. 원거리 표적 확인과 사격은 여기서 한다. 정밀 사격과 넓은 맵을 함께 쓸 수 있게 해 주는 핵심 장치
- **LOD**: 거리/줌에 따라 리그 전체 → 단순 스프라이트 → 아이콘. 원거리 파티클 수 축소
- **맵**: 길이 6~12 km, 폭 개념 없음(단일 주행선). 50 m 청크로 스트리밍
- **시차 배경**: 원경(지평선, 유정 화재 연기 기둥) / 중경(사구) / 근경(주행선) / 전경(가까운 모래 둔덕, 바퀴 하단을 살짝 가림)

### 2D 횡스크롤의 3차원 보정
- **포탑 선회·차체 방향 전환**: 측면 시점에서 180° 선회는 `scaleX = cos(yaw)` + 중간 구간 정면/후면 스프라이트로 연출. 회전 시간은 실제 선회속도 기반(M1 포탑 360°에 약 9초 수준 → 게임에서는 조정)
- **가상 수평각**: 2D에서는 모든 피탄이 정면/후면이다. 사실감을 위해 탄착마다 차체 방향 편차각(±0~30°, 상황에 따라)을 추가해 **복합 경사각**으로 관통을 계산한다. 측면 피탄은 측방 노출 이벤트(선회 중, 지형 굴곡, 측면 우회 미션)에서만 발생

## 5. 시스템 상세 설계

### 5.1 지형 & 토양 (`world/Terrain.js`, `Soil.js`)
- **표현**: 0.1 m 간격 1D 높이장. 10 km면 10만 칸. 50 m(500칸) 청크로 나눈다. 칸마다 `height(Float32)`, `compaction(다짐도)`, `soil(타입: 연사·다져진 사막·사브카 염습지·암반·포장로)`, `moisture` 값을 가진다
- **차량 침하**: 단순화한 Bekker 모델 `z = (p / (k_c/b + k_φ))^(1/n)`으로 접지압 p에서 침하량을 계산한다. 같은 칸을 다시 밟으면 다짐도가 올라가 침하가 줄어든다(먼저 지나간 바퀴자국은 단단해짐)
- **견인력**: Mohr–Coulomb `F_max = A·c + W·tanφ`. 슬립률이 높을수록 모래가 많이 튀고 바퀴가 더 파묻힌다
- **입상체 붕괴**: 이웃 칸 경사가 모래 안식각(약 32~34°)을 넘으면 흙을 옮기는 완화 패스를 돌린다. 변경된 청크만 처리하는 dirty 리스트 방식
- **변형 원인**: 궤도 침하, 바퀴 앞 흙 밀어내기(bulldozing 저항), HE 포탄 크레이터, 운동에너지탄 지면 착탄, 폭발 잔해 낙하
- **측면 시점 표현**: 주행선 높이장(변형됨)과 그 앞의 전경 둔덕 레이어를 따로 둔다. 바퀴자국 가장자리는 전경 레이어의 "자국 테두리" 데칼로 보여서 2D에서도 땅이 밟힌 게 보인다
- **렌더**: 청크마다 오프스크린 텍스처에 굽고, 변형된 청크만 다시 굽는다. 표면에는 모래 디테일 노이즈 + 다짐도에 따른 어두운 톤(젖은/다져진 모래)

### 5.2 차량 물리 (`vehicle/`)
- **차체(Hull)**: 2D 강체(x, y, θ, 질량, 관성모멘트). 무게중심은 차량 데이터에서 지정
- **서스펜션**: 보기륜마다 토션바 암(피벗 + 암 길이 + 스프링 강성 + 댐퍼 + 행정 한계). 바퀴 원과 높이장 사이의 접촉을 해석해 수직력 → 차체에 힘·토크로 전달. M1은 행정이 길어 험지에서 차체가 덜 흔들리고, T-55는 행정이 짧아 더 튄다
- **궤도(Track)**: 하이브리드 방식
  1. 매 프레임 구동륜 → 상부(상부지지륜 또는 T-55/62처럼 보기륜 위로 처짐) → 유도륜 → 하부(보기륜 아래, 바퀴 사이는 지면 따라 휨) 순서로 **궤도 경로(polyline)**를 계산한다
  2. 궤도 링크를 경로 위에 호 길이 간격으로 배치하고, 오프셋 `s`는 구동륜 회전량만큼 누적한다. 링크 방향은 경로 접선
  3. 하부 궤도는 지면에 대해 정지(슬립이 없을 때), 상부는 차속의 2배로 이동 → 실제와 같은 움직임
  4. **궤도 파손**: 피격으로 궤도가 끊기면 그 순간 Verlet 체인 물리로 전환해 궤도가 풀려 땅에 깔린다. 차량은 기동 불능
- **바퀴 회전**: 각속도 = 접선속도 / 반지름. 구동륜 톱니 위상은 링크 피치에 맞춰 동기화(톱니가 링크와 맞물려 보이도록)
- **구동계**: 엔진 토크 곡선 → 변속(M1 X1100 자동 4단, T-55 수동 5단) → 구동륜 토크 → 견인력(토양 한계). 터빈은 반응이 느리고 디젤은 즉답성이 좋다. 엔진 부하는 사운드·배기 연기에 연결
- **안테나·짐 흔들림**: 안테나는 2~3 마디 스프링 체인. 가속, 정지, 사격 반동에 반응한다

### 5.3 포 & 탄도학 (`vehicle/Gun.js`, `ballistics/`)
- **조준**: 마우스/스틱으로 목표 앙각을 지정한다. 포는 실제 구동 속도로 따라가고 부앙각 한계를 적용한다. 안정장치가 있으면 차체가 흔들려도 조준을 유지하고, 없으면 차체 피치가 그대로 포에 더해진다
- **사격통제**
  - M1A1: 레이저 거리측정(버튼) → 탄도컴퓨터가 탄종·거리·자차 경사·풍속을 보정해 자동 고각(super-elevation) 적용
  - 이라크 전차: 조준경 스타디아 눈금으로 거리를 직접 추정하고 고각을 수동으로 잡는다. 실력 요소
- **탄도 적분**: 질점 모델
  `a = g + (−½ ρ C_d(M) A |v| v) / m + 바람`
  - `C_d(M)`: 탄종별 마하수-항력계수 표(장봉탄은 낮고 HEAT·HE는 높음)
  - 서브스텝 적분(스텝당 이동거리 ≤ 2 m). 120 Hz 기준 1,600 m/s 탄은 스텝당 13 m이므로 스텝 안에서 다시 나눈다
  - 충돌: 이동 선분 vs (지형 높이장, 차량 장갑 폴리곤) 교차 판정
- **검증 도구**: `tools/balbench.js`가 탄종별 사거리-고각-비행시간-낙차 표를 출력한다. 실제 사격표 대략값과 비교한다(예: APFSDS 2 km 비행시간 약 1.3~1.4 s)
- **이탈피(sabot)**: APFSDS는 포구 앞 수십 m에서 꽃잎 3장이 분리돼 날아간다(별도 파티클 강체)
- **예광**: 탄 꼬리 발광 + 잔상

### 5.4 주퇴복좌 (`vehicle/Gun.js`)
- 포신을 포탑 위 1D 슬라이더로 모델링한다. 사격 순간 반동 충격량(탄 운동량 + 추진가스 분)을 주고 주퇴 브레이크(감쇠)와 복좌기(스프링)를 적용
  - 주퇴 행정: M256 약 30 cm, 구형 포는 더 길게(데이터 지정). 주퇴는 약 0.05 s로 빠르게, 복좌는 0.4~0.8 s로 부드럽게
- 반동 반작용은 포이(trunnion) 높이에서 차체에 전달된다. 그래서 차체가 서스펜션 위에서 뒤로 기울고 흔들리며, 경량 T-55가 M1보다 더 크게 흔들린다
- 시각 연동: 포신 스프라이트가 슬라이드하고, 배연기(bore evacuator)에서 잔연이 배출되고, 탄피가 배출된다(T-62는 포탑 후면 배출구로 탄피를 밖으로 던진다. M1은 연소식 탄피라 탄저부만 남아 외부에서는 보이지 않는다)

### 5.5 관통 · 도탄 · 피해 (`ballistics/Armor.js`, `Penetration.js`, `Damage.js`)
- **장갑 모델**: 차량 측면 실루엣을 장갑 판 폴리곤 세그먼트로 나눈다. 세그먼트마다 실두께 t, 재질(RHA·주조강·복합·공간장갑·고무 사이드스커트), KE/CE용 RHA 환산 계수를 가진다
  - 시작값 예: M1A1HA 포탑 정면 KE 약 600 mm급 / T-72M1 포탑 정면 KE 약 380~410 mm / T-55 포탑 정면 약 200 mm 주조 / T-55·62 상부 차체 100 mm @ 60°
- **유효 두께**: `t_LOS = t / (cos θ_v · cos θ_h)` (θ_v: 2D 피탄각, θ_h: 가상 수평각)
- **관통력 모델**
  - APFSDS: Lanz–Odermatt 경험식(봉 길이 L, 직경 d, 밀도, 속도, 표적 경도). 거리에 따른 감속은 탄도 적분 결과 속도를 그대로 쓴다. 장봉탄은 거의 정규화되지 않음
  - 구경탄 AP/APHE: de Marre 공식 + 정규화 몇 도
  - HEAT: 거리와 무관한 고정 관통력(구경 × 계수) + 스탠드오프 보정. 공간장갑·사이드스커트에서 조기 기폭되면 효율이 떨어진다. 극단적 경사(>80°)에서는 신관 불발 확률
  - HE: 장갑 관통보다 충격·파편. 경장갑, 궤도, 외부 장비(광학·안테나) 손상
- **도탄**: 탄종별 임계각 θ_c(장봉탄 약 70~80°, 구경탄 약 60~70°, t/d 비와 속도에 따라 변동) 근처에서 확률적으로 판정한다. 도탄하면 반사 벡터에 에너지 손실과 무작위 편향을 더해 탄을 계속 비행시킨다(도탄된 탄이 다른 표적이나 지면에 맞을 수 있음)
- **결과 등급**: 도탄 / 비관통(흠집·충격) / 부분 관통(스폴링) / 관통(잔여 관통력 → 내부 피해)
- **내부 모듈 피해(HP 바 대신)**: 측면 단면도에 승무원(전차장·포수·장전수·조종수), 탄약고, 연료, 엔진, 변속기, 포, 광학장비, 궤도·보기륜 모듈을 배치한다. 관통 후 잔여 관통력으로 내부 레이를 계속 진행시키고 파편 원뿔로 모듈을 판정한다
  - M1A1: 포탑 후방 탄약고 + 방폭문 + 블로우오프 패널 → 유폭해도 위로 화염이 배출되고 승무원은 생존할 확률이 높다
  - T-72: 차체 바닥 회전식 자동장전기 → 탄약 피격 시 포탑 이탈(역사적 특징)
- **킬 판정**: 기동 불능(M-kill), 화력 불능(F-kill), 완파(K-kill)

### 5.6 이펙트 (`fx/`)
공통: 타입드 배열 파티클 풀(위치·속도·수명·크기·색·회전), GPU 인스턴싱 렌더, 바람·중력·항력 적용. 목표 동시 파티클 1만~2만 개.

- **포 섬광**: 3단계(포구 내부 1차 섬광 → 중간 섬광 → 2차 연소 화구). 2~4 프레임 지속. 주변 지형과 차체에 순간 광원(동적 라이트 반경)
- **포구 충격파**: 왜곡 링(후처리) + 포구 아래·앞 지면에서 원형으로 퍼지는 모래 구름. 사막에서는 실제로 이 먼지가 조준을 가려 다음 사격이 늦어진다 → 게임 규칙으로도 반영
- **포연**: 포구와 배연기에서 나오는 회백색 연기. 바람 따라 표류하고 천천히 확산·소멸
- **모래**: 궤도 뒤 루스터테일(슬립·속도에 비례), 보기륜 사이로 흘러내리는 모래, 사구 능선에서 바람에 날리는 모래 줄기, 착탄 기둥(KE: 높고 가는 기둥, HE: 크레이터 + 방사형 흙 투척 + 낙하 흙덩이 → 지형에 다시 퇴적)
- **엔진 연기**: M1 터빈은 연기가 거의 없는 대신 후방 그릴에서 열 아지랑이가 나오고 뒤쪽 모래를 불어낸다. T 계열 디젤은 가속·시동 때 검은 연기가 뭉쳐 나온다. T 계열 TDA(배기에 연료를 분사하는 연막 장치)는 게임 기능으로 구현
- **피격**: 도탄 불꽃 + 튕겨 나가는 예광, 비관통 착탄 그을음 데칼, 관통 시 내부 섬광이 해치·틈새로 새어 나옴, 차내 화재 연기
- **전차 폭발**: 단계형 시퀀스
  1. 관통 → 내부 화재(해치에서 연기)
  2. 탄약 유폭 → 대형 화구, 포탑 이탈(강체: 회전하며 날아가 지형에 떨어지고 땅을 파냄), 해치·잔해 파편
  3. 2차 유폭 30~60 초 간헐 발생, 높이 솟는 검은 연기 기둥(원경에서도 보임)
  4. 불타는 잔해는 그대로 남아 엄폐물·시야 차단물로 기능
- **환경**: 열 아지랑이(원거리 신기루 왜곡), 모래폭풍(73 이스팅 전투 당시 실제 기상), 쿠웨이트 유정 화재 연기로 어두워진 하늘, 야간 열상 모드(백열/흑열)

### 5.7 AI (`ai/`)
- 행동: 진지 대기(hull-down) → 표적 탐지(광학/열상 탐지 거리, 먼지·연기 차단) → 거리 추정(오차 포함) → 사격 → 재장전 중 은폐 → 이동
- 이라크 AI: 정적 방어선, 진지 사격, 근거리 매복, 탄착 보고 후 수정 사격
- 아군 AI: 미군 전차 소대 4대 편성. 플레이어 소대장 차량 + 아군 3대(간단한 명령: 전진/정지/사격 자유/집중 사격)

### 5.8 게임 구조
- **캠페인**: 1991년 2월 지상전 흐름을 바탕으로 한 가상 미션 6~8개(국경 돌파, 사막 야간 기동, 모래폭풍 속 조우전, 능선 너머 방어선 돌파, 유정 화재 지대 등). 실제 전투는 "영감"으로만 쓰고 부대·인물은 가상
- **스커미시**: 차량·지형·기상·시간대를 자유롭게 설정
- **사격장**: 탄도·관통 확인용 연습 모드(장갑판 각도 조절, 결과 표시)
- **이라크군 도전 모드(선택)**: T-72로 열세를 극복하는 고난도 모드

- **리그 JSON**: 모든 피벗·바퀴 중심·반지름·포이 위치·장갑 세그먼트를 미터 단위로 기록한다. 스프라이트 해상도와 분리해 데이터 하나로 물리·렌더·피해 판정을 같이 쓴다

- 시작 단계에서는 참고 이미지를 잘라 임시 리그를 만들고, 이후 직접 그린 레이어 원화로 교체한다
- ⚠ 첨부 이미지의 출처·사용권 확인 필요. 직접 제작했거나 사용 허가를 받은 그림이면 그대로 원화로 쓸 수 있다

## 9. 성능 예산 (목표: 중급 노트북 60 fps)
| 항목 | 예산 |
|---|---|
| 물리(차량 16대, 120 Hz) | ≤ 3 ms/프레임 |
| 탄도·충돌 | ≤ 0.5 ms |
| 지형 변형 + 재굽기 | ≤ 1 ms(변형 청크만) |
| 파티클 업데이트 | ≤ 2 ms(1만~2만 개) |
| 렌더 + 후처리 | ≤ 6 ms |
- 화면 밖 차량은 저주파 물리(30 Hz)와 궤도 링크 생략, 원거리 파티클 수 축소, 동적 해상도

- TOW 2: X 키 → 정지 상태에서 발사관 상승(1.2초) → 발사 → 조준선을 따라 유선 유도(3,750 m), 관통 900 mm. 장전 2 + 예비 5, 재장전 25초
- TOW 발사관: 좌측면 그림에서 잘라 포탑 뒤에 그림 → 올리면 포탑 위로 나온 부분이 실제 그림으로 보임. 발사관은 접힌 상태에서도 실제 위치(포탑 반대편)에 있으며, 포탑에 가려진 부분의 외곽선이 항상 투과되어 보임(Z로 끄기). 발사관 피격 시 TOW 사용 불가. 승무원·탄약 등 다른 엑스레이 표시는 제거
- 작전 선택 화면에서 차량 선택. 고르지 않은 차량이 아군 AI로 동행: 전차가 항상 선두 (브래들리 선택 시 M1A1이 45 m 앞, M1A1 선택 시 브래들리가 45 m 뒤) (M1A1은 주포, 브래들리는 TOW 사용). 같은 편 차량은 서로의 사선을 막지 않음
- 미사일 시점(Tab): 날아가는 TOW를 따라가는 카메라(거리·속도·유도 상태 표시), 착탄 후 2초간 착탄 지점을 보여준 뒤 전차로 복귀. 켜 두면 매 발사마다 자동
- 남은 것: 브래들리용 작전(B5), 분당 100발 선택, 적외선 탐조등

## 색적·표적 지정 시스템 계획 (검토 중)

### 목표
각 차량이 자기 조준경 성능만큼만 적을 찾고, 플레이어는 **찾아낸 적만** 표적으로 골라 조준한다.

### 1. 색적 모듈 (`src/ai/Sensor.js`, 아군·적군·플레이어 공용)
- 지금 적 AI 안에 있는 탐지 계산을 꺼내 모든 차량이 같은 규칙을 쓰게 한다
- 단계: **미탐지 → 접촉(무언가 있음, 위치 대략) → 식별(차종 확인)**. 식별은 접촉보다 시간이 더 걸린다
- 영향 요소: 시야 차단(지형·차체), 거리, 표적 크기(브래들리 0.5), 이동 여부, 발포 섬광, 야간, 모래폭풍, 먼지·연기
- 시야를 잃으면 마지막 위치를 몇 초 기억한 뒤 사라짐

| 차량 | 조준경 | 주간 탐지 / 식별 | 야간 | 모래폭풍 |
|---|---|---|---|---|
| M1A1 | GPS + 열상 | 4,000 / 2,500 m | 열상: 주간과 거의 같음 | 열상: 약 1,500–2,000 m |
| M2A2 | ISU + 열상 | 3,500 / 2,000 m | 열상 | 약 1,200–1,600 m |
| T-72M1 | 광학 + 레이저 | 2,500 / 1,500 m | 적외선 약 400 m | 수백 m |
| T-62 / T-55 | 광학 | 2,000–2,200 / 1,200 m | 적외선 약 400 m | 수백 m |
(이라크군 값은 지금 적용 중인 값 그대로 유지)

### 2. 화면 표시
- 탐지된 적 위에 표식: 접촉은 `?`, 식별되면 차종과 거리. 선택된 표적은 사각 괄호
- 미니맵에도 탐지된 적만 표시
- 조준경 안에 선택 표적 상자 표시
- 화면 옆에 표적 목록 (차종, 거리, 상태)

### 3. 표적 지정
- **다음 / 이전 표적 키**로 탐지된 적 사이를 가까운 순으로 순환
- 표적을 고르면 포수가 실제 포탑 구동 속도로 조준선을 그 표적에 옮김 (자동 조준은 시간이 걸림, 각도 차이가 클수록 오래)
- 옮긴 뒤에는 기존처럼 W/S로 미세 조정, E로 레이저, Space로 사격
- 표적이 시야에서 사라지거나 격파되면 지정 해제
- 브래들리 TOW 유도 중에는 선택 표적에 조준선을 유지 (자동 추적 여부는 결정 필요)
- 터치 화면: 표적 전환 버튼 추가

### 4. 적 AI·아군 AI
- 같은 색적 모듈로 바꾸고, 표적은 탐지된 적 중에서만 고름 (지금처럼 가장 가까운 적을 바로 아는 방식 제거)

### 단계
- T1 색적 모듈 분리, AI를 새 모듈로 전환 (동작은 지금과 같게)
- T2 플레이어 색적 + 표식·목록·미니맵
- T3 표적 순환 키, 자동 조준 이동, 조준경 표적 상자
- T4 TOW 연동, 터치 버튼, 테스트 (탐지 거리표 출력 도구)

### ✅ 사용자 결정 반영 (2026-11-10) — 구현 완료
- 미탐지 적: 보이지 않음. 접촉(?)은 흐린 실루엣, 식별되면 정상 표시
- 색적이 안 된 구역: 화면에서 흐리게(어둡고 탁하게) 표현. 내 차량의 탐지 거리 밖과 시야가 가려진 곳(사구 뒤)
- 표적 전환: Backspace = 다음 표적, Shift+Backspace = 이전 표적
- 표적 선택 시 포만 표적으로 이동 (거리측정·사격은 직접)
- TOW 유도는 수동 유지
- 키 가이드: 인게임 버튼 + H로 끄기/켜기, 상태 기억
- 메인 화면 정돈: 작전 카드는 이름·날짜·조건만, "브리핑" 펼침/접기, "출격" 버튼. 전쟁 게임풍 글꼴
- 이라크군 명중률 추가 하향

#### 구현 내용
- `src/ai/Sensor.js`: 모든 차량의 색적(접촉 d≥1 → 식별 d≥2, 시야 상실 후 8초 기억). 이라크군은 기존 하향 값, 미군은 열상(야간 무관, 모래폭풍에 단축)

- 상단 목록·미니맵·HUD는 탐지한 적만 표시
