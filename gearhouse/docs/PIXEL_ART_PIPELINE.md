# GEARHOUSE — 클로드 코드 픽셀아트 스프라이트 생성 계획 (v0.1)

> 목표: 게임에 필요한 픽셀아트 스프라이트(실루엣, 강판, 엔진 모듈, 섀시, 외장 부품, 휠, 패턴, UI)를
> **Claude Code가 코드와 데이터로 생성**하고, 렌더 결과를 직접 이미지로 확인하며 반복 개선하는 파이프라인.

이 문서는 **픽셀아트를 기본 아트 스타일**로 채택하는 것을 전제로 한다
(SPRITE_SYSTEM §10의 "플랫 일러스트 기본 + 픽셀 모드 옵션"을 대체. 스무스 모드는 후순위 옵션).

---

## 1. 기본 원칙

| 원칙 | 내용 |
|---|---|
| **그리지 않고 생성한다** | Claude Code는 붓으로 칠하지 않는다. ① 텍스트 픽셀맵(DSL), ② 절차적 생성기 코드, ③ 벡터→픽셀 래스터라이저로 PNG를 **빌드**한다. |
| **소스가 정본, PNG는 산출물** | 저장소에는 생성 코드 + JSON/DSL 소스를 커밋. PNG·아틀라스는 `build`로 언제든 재생성 → 팔레트·스케일 변경 시 전체 일괄 재생성 가능. |
| **눈으로 확인하는 루프** | 생성 → 4배 확대 콘택트 시트 PNG → Claude가 이미지를 직접 열어 체크리스트로 검수 → 파라미터 수정 → 재생성. |
| **규칙은 코드로 강제** | 팔레트 외 색, 고아 픽셀, 끊긴 외곽선, 이음새 불일치, 크기 오차를 **린터**가 자동 검사. 사람 눈·Claude 눈은 미적 판단에만 쓴다. |
| **의존성 0** | Node 내장 `zlib`으로 PNG 인코더 직접 구현 (기존 프로젝트 방침과 동일). 같은 래스터 코드를 브라우저 런타임에서도 공유. |
| **아트 디렉션은 사용자가 확정** | 초기 "스타일 락" 단계에서 사용자가 팔레트·외곽선·셰이딩 방식을 고르고, 이후 배치마다 승인. |

## 2. 픽셀 스케일 체계

픽셀아트는 **정수 배율만** 허용하므로(비정수 확대·회전 금지), 스케일을 먼저 고정하고 각 스케일에서 **네이티브로 생성**한다. 큰 그림을 축소하면 뭉개지기 때문.

| 스케일 | mm/px | 용도 | 예: 4.5m 세단 측면 | 예: 직렬4 엔진(600mm) |
|---|---|---|---|---|
| **S1 차량** | 25 | 디자인 스튜디오, 테스트 트랙, 쇼룸, X-ray | 180 × 56 px | 24 px |
| **S2 클로즈업** | 5 | 엔진 설계실, 플랫폼 설계실 상세, 부품 라이브러리 | — | 120 px |
| **S3 썸네일** | 50 | 시장 목록, 라인업 타임라인, 세이브 슬롯 | 90 × 28 px | (생략) |

- 화면 표시는 정수 배율(×2~×6)로 확대, `imageSmoothingEnabled = false`.
- 같은 부품은 스케일마다 별도 생성(**LOD 스프라이트**). S3에서는 디테일 생략 규칙(도어핸들·와이퍼 제거, 그릴 패턴 단순화)을 생성기가 적용.
- SPRITE_SYSTEM §1.2의 "1x = 10mm" 기준은 스무스 모드용으로 남기고, 픽셀 모드는 위 표를 따른다.

## 3. 생성 방식 4가지 (에셋 종류별 선택)

### 3.1 방식 A — 텍스트 픽셀맵 DSL (소형 디테일, ≤ 32px)

Claude가 텍스트로 직접 찍는 방식. 사람이 읽고 diff로 리뷰할 수 있다.

```text
# part_headlamp_round_E3_a  view=front  scale=S2  palette=E3
# . 투명  O 외곽  c 크롬 램프(1~4)  g 유리 램프(1~3)  w 하이라이트
legend: { ".":null, "O":"outline", "1":"chrome.0", "2":"chrome.1", "3":"chrome.2", "4":"chrome.3",
          "a":"glass.0", "b":"glass.1", "d":"glass.2", "w":"white" }
....OOOOOO....
..OO443322OO..
.O4432222211O.
.O43aaabbb21O.
O43abbbddwb21O
O42abbdddwb21O
O32abbddddb11O
O32aabbdddb11O
O321aabbbba11O
.O21aaabba11O.
.O2211aa1111O.
..OO111111OO..
....OOOOOO....
```

- 용도: 엠블럼 프레임, 도어핸들, 점화플러그, 볼트, 계기판 아이콘, 렌즈 패턴 타일, UI 아이콘, 시대별 로고 심볼.
- **변형 자동화**: 하나의 맵에서 팔레트 교체(크롬↔블랙↔바디색), 좌우 미러, 램프 색(적/황/백)으로 파생.

### 3.2 방식 B — 절차적 도형 생성기 (기계 부품·파라메트릭 부품)

픽셀 정확 원시 도형을 코드로 조합한다. **안티에일리어싱 없음**, 정수 좌표.

| 원시 도형 | 알고리즘 |
|---|---|
| 직선 | Bresenham + "픽셀 퍼펙트" 정리(L자 꺾임 제거) |
| 원/타원 | Midpoint circle/ellipse (휠·램프·풀리·브레이크 로터) |
| 다각형 채우기 | 스캔라인 (짝홀 규칙) |
| 두께 있는 선 | 브러시 스탬프(1·2·3px 원형/사각) |
| 둥근 사각형 | 코너 반경 midpoint (탱크·캠커버·범퍼 끝) |
| 그라디언트 → 단계 | 연속값을 램프 4~5단계로 양자화 + 선택적 Bayer 4×4 디더 |

생성기 예시 (스포크 휠 — 회전 스프라이트 대신 **스포크 수만큼 기하로 직접 그린다**):

```js
// tools/pixel/gen/wheel.js
export function wheel({ diaMM, tireMM, spokes, rim, whitewall, scale }, pal) {
  const r  = Math.round(diaMM / 2 / scale.mm);           // 타이어 바깥 반경(px)
  const ri = r - Math.max(2, Math.round(tireMM / scale.mm));
  const img = new Img(2 * r + 1, 2 * r + 1);
  fillCircle(img, r, r, r,  pal.rubber[1]);
  if (whitewall) ring(img, r, r, ri + 2, 1, pal.white[2]);
  fillCircle(img, r, r, ri, pal[rim][1]);
  for (let k = 0; k < spokes; k++) {                     // 스포크는 각도별로 선을 새로 래스터
    const a = (k / spokes) * Math.PI * 2;
    line(img, r, r, r + Math.cos(a) * ri, r + Math.sin(a) * ri, pal[rim][3]);
  }
  shadeSphere(img, { light: [-1, -1] }, pal);            // 좌상단 광원 셀 셰이딩
  outline(img, pal.outline, { mode: 'selout' });
  return img;
}
```

- 용도: 휠/타이어(+회전 애니 4~8프레임), 엔진 모듈, 프레임 레일, 스프링, 탱크, 머플러, 라디에이터, 범퍼, 그릴 프레임, 헤드램프(원형/사각/쿼드), 테일램프.
- **크기가 파라미터로 바뀌는 부품은 게임 런타임에서도 같은 생성기로 그린다** (보어 95mm → S1에서 4px, S2에서 19px). 사전 생성이 불가능한 조합 폭발을 피하는 핵심.

### 3.3 방식 C — 벡터 → 픽셀 래스터 (실루엣·패널·유리)

실루엣 JSON의 스플라인을 각 스케일에서 래스터화한 뒤 픽셀아트 정리 패스를 거친다.

```
스플라인(JSON) ─► 폴리라인 평탄화 ─► 스캔라인 채우기(S1/S2/S3 각각)
   ─► 계단 정리 (1:1, 1:2, 2:1, 1:3 기울기만 남기고 불규칙 계단 보정)
   ─► 돌출 1px·구멍 1px 제거 (모폴로지 open/close)
   ─► 패널 영역·유리 영역·스타일 라인을 같은 그리드에 래스터 (경계 정합 검사)
   ─► 높이맵 셰이딩 (§4.2) ─► 외곽선 (§4.3)
```

- 5뷰 일관성: 측면 길이(px) = 탑뷰 길이, 프론트 폭 = 탑뷰 폭, 측면 높이 = 프론트 높이 — 린터가 ±1px로 검사.
- 실루엣 생성기(`silgen`)의 후보 수백 개를 이 방식으로 일괄 래스터 → 콘택트 시트로 선별.

### 3.4 방식 D — 절차적 텍스처 (강판 소재·패턴 타일)

| 텍스처 | 생성 |
|---|---|
| 강판 소재 (등급 1~5) | 저주파 value noise(굴곡) + 등급별 진폭 → 램프 양자화, **이음매 없는 타일**(토러스 노이즈). 등급 1은 리벳/용접 점 패턴 추가 |
| 도색 플레이크(메탈릭) | 희소 점 노이즈 1~2색 |
| 그릴 인필 | 세로바·가로바·에그크레이트·메시·다이아몬드: 주기 패턴 공식 |
| 렌즈 패턴 | 플루티드(세로 줄), 프리즘(체크), 동심원 |
| 시트 직물 / 비닐 루프 | 2×2·3×3 반복 패턴 |
| 녹·오염(노화) | 마스크 가장자리 거리 기반 확률 + 클러스터 노이즈, 휠아치·실 하단 가중 |

## 4. 픽셀아트 품질 규칙 (생성기 공통 후처리)

### 4.1 팔레트

- **마스터 팔레트**: Era별 32색 이하, 모든 색은 **램프**(같은 계열 3~5단계)에 속한다. 램프는 어두울수록 청/보라 쪽, 밝을수록 노랑 쪽으로 **색상 이동**(hue shift) — 단순 명도 조절로 생기는 탁한 색 방지.
- 고정 재질 램프: `outline`, `chrome`, `rubber`, `glass`, `lens.red/amber/clear`, `iron`(주철), `alu`, `steel`, `brass`(E1~E2), `shadow`.
- 도색 램프: Era 팔레트 JSON의 기본색 → 생성기가 4단계 램프 자동 생성(OKLab 공간에서 계산 후 스냅).
- 출력은 **인덱스 컬러**. 린터가 팔레트 외 픽셀 = 오류.

```json
{ "era": "E3",
  "ramps": {
    "chrome":  ["#2b2d42", "#6c7a96", "#b8c4d6", "#f2f6fb"],
    "rubber":  ["#141419", "#2a2a33", "#45454f"],
    "glass":   ["#1f3a4d", "#3f6f86", "#8fc2cf"],
    "paint.seafoam": "auto:#7fc8b4"
  }}
```

### 4.2 셰이딩

- 광원 고정: 측면·탑뷰 = 좌상단, 프론트·리어 = 정상단. 우측면은 미러하지 않고 **광원을 유지한 채 다시 셰이딩** (미러하면 빛 방향이 뒤집히므로).
- 실루엣·탱크·캠커버 등 덩어리: 마스크 → 거리 변환 → 의사 높이맵 → 법선 → 램버트 → **3~4단계 양자화** (셀 셰이딩).
- 스타일 라인(벨트라인·캐릭터 라인): 높이맵에 주름(crease) 추가 → 한 줄 하이라이트 + 한 줄 그림자.
- 금속 하이라이트: 소재 등급이 높을수록 1px 연속 하이라이트, 낮을수록 끊긴 점선(물결).
- 디더링: 기본 OFF, E1~E2 "빈티지 인쇄" 느낌 옵션과 그라디언트 큰 면(루프·후드)에만 2단계 체커 디더 허용.

### 4.3 외곽선

- 모드 `selout`(셀렉티브 아웃라인): 외곽선 색 = 인접 내부색의 가장 어두운 램프 단계. 순수 검정은 지면과 닿는 하단·타이어에만.
- 외곽선 두께 1px 고정(S1·S2), S3은 외곽선 생략 가능.
- 부품이 차체 위에 얹힐 때 **내부 외곽선**(부품과 차체 경계)은 한 단계 밝게 → 납작하게 붙은 느낌 방지.

### 4.4 금지 사항 (린터 검사)

| 규칙 | 검사 방법 |
|---|---|
| 고아 픽셀 (주변 8칸과 다른 색의 외톨이 1px) | 이웃 비교, 허용 목록(하이라이트 점) 예외 |
| 끊긴 외곽선 | 외곽 마스크 경계 추적, 4-연결 끊김 검출 |
| 더블 픽셀 계단 / 불규칙 계단 | 외곽 체인 코드 분석 |
| 팔레트 외 색 / 스프라이트당 색 수 초과(기본 16) | 히스토그램 |
| 비정수 스케일 흔적(중복 행·열 패턴) | 행·열 중복 검출 |
| 모듈 이음새 불일치 | §5 타일 테스트 |
| 치수 오차 | 메타데이터 mm ÷ 스케일 vs 실제 px (±1) |
| 슬롯 밖 픽셀 | 실루엣 마스크와 AND |

## 5. 모듈 스프라이트 규칙 (반복·늘리기·회전의 픽셀아트 버전)

SPRITE_SYSTEM §5의 재활용 기법은 픽셀아트에서 다음과 같이 바뀐다.

| 기법 | 스무스 모드 | **픽셀 모드 구현** |
|---|---|---|
| Repeat | 모듈 N번 복사 | 동일. 단 모듈 좌·우 가장자리 열을 **이음새 열**로 정의해 서로 맞물리게 생성 |
| 3/9-slice 늘리기 | 가운데 확대 | **확대 금지 → 가운데 타일 반복**. 길이가 타일 배수가 아니면 나머지 열을 생성기가 채움 |
| Radial | 스포크 스프라이트 회전 | **각도마다 기하로 다시 래스터** (방식 B) |
| Bone (암·링크) | 스프라이트 회전·스케일 | 두 하드포인트 사이를 **두께 있는 Bresenham 선 + 끝 부싱 원**으로 런타임 래스터 |
| V 뱅크 기울기 | 단면 회전 | 허용 V각(45/60/72/90/120/180°)별 **뱅크 단면을 각도별로 생성기가 직접 그림** |
| Path strip (크롬 몰딩·배기관) | 텍스처 변형 | 경로를 픽셀 폴리라인으로 래스터한 뒤 **법선 방향 오프셋 1~2줄**에 램프 색 배치 |
| Tint | 곱하기 합성 | **팔레트 인덱스 교체** (램프 → 램프 매핑), 색 수 증가 없음 |
| Pattern fill | 패턴 클리핑 | 동일 (패턴 원점을 부품 좌상단에 정렬해 경계 깨짐 방지) |

**이음새 테스트**: 반복형 모듈은 N = 1~16개를 자동으로 이어 붙인 스트립을 생성 → 이음새 위치의 외곽선·하이라이트 연속성 린트 + 콘택트 시트 확인.

**엔진 모듈 예 (S1, 직렬 vs V8)**

```
직렬4 측면 (S1, 1px=25mm)        V8 엔드뷰 (S2 일부)
 ▕▓▏████▕▓▏  ← 캠커버 3-slice        ╲▓▓╱    ╲▓▓╱
 ▕▓▏▒▒▒▒▕▓▏  ← cyl ×4 (각 4px)       ╲▒▒╲  ╱▒▒╱
 ▕▓▏░░░░▕▓▏  ← 오일팬                  ╲▒▒╲╱▒▒╱   ← 90° 뱅크 단면 2개(미러)
```

## 6. Claude Code 작업 루프

> **선행 단계 — 레퍼런스 분석**: 시대·차종별 블루프린트를 격자 측정 → 휠베이스 비율 규칙으로 정리 → 생성 결과를 같은 축척의 블루프린트에 외곽선 오버레이로 대조. 결과는 [REFERENCE_ANALYSIS.md](REFERENCE_ANALYSIS.md).

```
 ┌─► ① 사양 작성/수정      (DSL 파일 · 생성기 파라미터 JSON · 팔레트)
 │   ② 빌드               node tools/pixel/build.js --group wheel --scale S1,S2
 │   ③ 린트               node tools/pixel/lint.js  → 규칙 위반 목록
 │   ④ 콘택트 시트         변형 전부를 격자로 ×4 확대 PNG (+ 체커 배경, 라벨)
 │   ⑤ 시각 검수 (Claude)  시트 PNG를 직접 열어 §7 체크리스트 대조, 문제 기록
 │   ⑥ 조립 검수           실제 게임 렌더러로 차량 5뷰 합성 → Playwright 스크린샷 → 확인
 └── ⑦ 문제 있으면 ①로     없으면 커밋 (소스 + 시트, PNG 아틀라스는 빌드 산출물)
        ▼
     ⑧ 사용자 리뷰 게이트  배치 단위 갤러리 페이지 → 승인/코멘트 → 반영
```

- 한 배치 = 한 부품 그룹 × 한 Era (예: "E3 헤드램프 12종").
- 사용자 리뷰는 갤러리 HTML(콘택트 시트 + 확대 비교 + 차량 장착 예시)로 제공. 코멘트를 받으면 해당 생성기/DSL만 수정해 재빌드.
- 모든 생성은 시드 고정 → 같은 입력이면 같은 PNG (diff 리뷰 가능).

## 7. 시각 검수 체크리스트 (Claude가 시트를 볼 때)

1. 실루엣이 해당 시대·차종으로 즉시 읽히는가 (S3 썸네일 크기에서도)
2. 광원 방향이 모든 부품에서 일치하는가
3. 부품이 차체에 "붙어" 보이는가, 떠 보이는가 (내부 외곽선·접지 그림자)
4. 소재 등급 1과 5의 차이가 S1에서 구분되는가
5. 크롬·유리·고무·도장면이 서로 다른 재질로 읽히는가
6. 반복 모듈의 이음새가 보이지 않는가 (N=3, 8, 12에서)
7. 5뷰 간 같은 부품의 위치·색·크기가 맞는가
8. 노이즈 과다(디테일이 지글거림) 또는 과소(밋밋함)가 없는가
9. 같은 그룹 내 변형들이 서로 충분히 달라 보이는가 (중복 제거)

> 한계: Claude의 이미지 판독은 형태·정렬·색 일관성 확인에는 충분하지만 미세한 미감 판단은 사람보다 약하다.
> 그래서 **규칙은 린터가, 미감 최종 결정은 사용자가** 맡고, Claude는 그 사이의 대량 생성·수정 반복을 담당한다.
> 사람·동물 같은 유기적 형태보다 자동차·기계처럼 기하적인 대상이 이 방식에 잘 맞는다.

## 10. 단계별 계획

| 단계 | 산출물 | 사용자 확인 포인트 |
|---|---|---|
| **P0 툴 기반** | png/img/palette/raster/lint/sheet, DSL 파서, 테스트 | 없음 (내부) |
| **P1 스타일 락** | E3 4도어 세단 1대를 S1 5뷰 + S3로 완성. 팔레트 3안 × 외곽선 2안(selout/검정) × 셰이딩 2안(3단/4단) 비교 시트 | **아트 방향 선택** (이후 전 에셋 기준) |
| **P2 휠·램프·그릴·범퍼** | E3 기준 부품 세트, 크기·색 변형 | 부품 갤러리 승인 |
| **P3 엔진 모듈** | 직렬/V/수평대향 × 헤드 4종 × S1·S2, 이음새 테스트, 장착 재매핑 | 엔진 설계실 프리뷰 승인 |
| **P4 섀시·구동·탱크** | 프레임·서스·변속기·배기, X-ray 합성 | X-ray 뷰 승인 |
| **P5 소재·도색·노화** | 강판 5등급 × Era, 도색 팔레트, 녹 오버레이 | 등급 구분감 확인 |
| **P6 실루엣 양산** | silgen 후보 Era당 150개 → 선별 40~60개 × 7 Era | Era별 선별 시트 승인 |
| **P7 Era 확장 패스** | E1·E2·E4~E7 부품 스타일 세트 | Era별 갤러리 승인 |
| **P8 UI·배경** | 아이콘, 쇼룸/공장/트랙 배경 | 화면 목업 승인 |

P1의 스타일 락이 가장 중요하다. 여기서 정한 팔레트·외곽선·셰이딩 규칙이 생성기 기본값이 되어, 이후 수천 개 스프라이트가 같은 손으로 그린 것처럼 보이게 만든다.

## 11. 선택 사항: 사용자 원화와 혼합

- 사용자가 키 스프라이트(예: 대표 헤드램프 2~3개, 차 1대)를 직접 그려 제공하면, Claude가 **팔레트·외곽선·셰이딩 규칙을 역추출**(색 히스토그램, 외곽 색 관계, 광원 방향 분석)해 생성기 기본값으로 삼는다.
- 사용자 원화 PNG는 `assets/handmade/`에 두고 DSL로 변환(방식 A)해 팔레트 교체·미러 파생을 똑같이 적용.
