# 검토 24 — 출렁이고 통통 튀는 하체: Desert Steel, Hill Climb Racing, BeamNG, 그리고 기술 시험

기획자 요청(2026-11-20):
- 실제처럼 출렁이고 통통 튀는 서스펜션·타이어 물리를 만들기 위해 다음을 참고할 수 있는지 검토한다.
  - 사용자가 Claude Code로 만든 사이드뷰 물리 전차 게임 Desert Steel
  - Hill Climb Racing (참고 정도)
- 픽셀을 돌리지 말고, 탄성 물리로 원래 그림을 약간 찌그러뜨리는 방식을 검토한다.
- 실차 조사는 세부 참고용으로만 쓴다.
- 프레임에 엔진, 드라이브샤프트, 트랜스퍼 케이스, 동력 전달부, 서스펜션(판스프링, 쇼크업소버, 토션 빔 등 당시 것)을 구조로 넣는다.
- 사이드뷰에서도 바퀴 4개가 보이게 한다.
- BeamNG.drive를 분석한다.

결론: 모두 가능하다. 한 대(1948 다목적차)로 기술 시험을 만들어 확인했다(5장).

## 1. Desert Steel — 그대로 가져올 수 있다

같은 저장소의 `claude/gulf-war-tank-game-plan-p65tok` 브랜치, `tank/`에 있다. 앞선 계획(1차판 24장)에도 이미 참고로 적혀 있다.

| Desert Steel의 것 | 위치 | 이번에 쓴 것 |
|---|---|---|
| 2D 강체 차체에 바퀴마다 스프링·댐퍼·범프 스톱·리바운드 | `src/vehicle/Vehicle.js` 앞부분 | 차체 + 판스프링 4개, 범프 고무, 리바운드 끈 |
| 바퀴를 점이 아니라 원으로 지면에 놓기(`circleRest`) | `src/world/Terrain.js` | 타이어를 점 18개의 고리로 만들어 더 나아갔다(BeamNG 방식) |
| 토양 견인(모어-쿨롱), 침하(베커), 다짐 기억 | `Terrain.press` | 아직. 비포장 시험장에서 그대로 가져온다 |
| 궤도가 끊기면 링크 사슬(베를레 점)이 땅에 늘어짐 | `src/vehicle/TrackChain.js` | 같은 방식으로 나중에 체인, 고삐, 덮개 끈에 쓸 수 있다 |
| 안테나 스프링(그림이 탄성으로 흔들림) | `Vehicle.js` | 차체 그림의 찌그러짐(2장)이 같은 생각이다 |
| 작은 고정 시간 간격 | `Game.js` | 1/4000초 |

**다른 점:** Desert Steel은 고해상도 그림을 매끄럽게(보간해서) 돌린다. 픽셀 그림에는 그 방식이 맞지 않아서, 이 게임은 2장의 방식을 쓴다.

## 2. 픽셀을 돌리지 않고 움직이기

| 방식 | 내용 | 결과 |
|---|---|---|
| 기둥 밀기 | 그림 한 장을 픽셀 기둥마다 위아래로 옮겨 기울기를 흉내낸다 | 2~3°까지는 자연스럽다. 그 이상은 세로선(앞유리, 문)이 세로로 남아 찌그러져 보인다 |
| **윤곽에서 다시 그리기 (채택)** | Z 방식은 그림이 아니라 윤곽선 데이터다. 1° 간격(-8°~+8°)으로 윤곽을 돌린 뒤 렌더러가 새로 그리고, 사이 각도(0.5° 미만)만 기둥 밀기로 메운다 | 선이 픽셀 격자에 맞고, 빛은 계속 왼쪽 위에서 오고, 외곽선 두께가 같다(첨부 2 아래 줄). 차 한 대 17자세 × 차체·하우스·섀시 3장으로 약 8초 걸려 한 번 만들어 둔다 |
| 탄성 찌그러짐 | 차체 그림의 행을 약간 늘이고 줄인다. 차체의 상하 가속도로 움직이는 "보이기용 스프링"이 정한다(Hill Climb Racing류의 squash) | 착지 때 최대 2% 정도. 행을 복제·생략하므로 픽셀은 그대로다 |
| 고리 타이어 | 타이어는 그림이 아니라 물리 점 고리의 모양대로 매 프레임 채운다 | 땅에 닿으면 실제로 납작해지고, 턱을 넘으면 찌그러졌다 돌아온다 |
| 움직이는 부품 | 판스프링(휨과 섀클 흔들림), 댐퍼(늘고 줄기), 프로펠러 샤프트(각도), 바퀴 너트(회전)를 매 프레임 선과 원으로 그린다 | 돌리는 그림이 없다 |

## 3. Hill Climb Racing — 느낌만 참고한다

- 공개 자료에서 개발사가 쓴 물리 엔진은 확인되지 않는다. Box2D라는 말은 팬이 만든 모작 이야기다.
- 참고할 것:
  - 서스펜션과 타이어를 업그레이드하면 움직임이 눈에 띄게 바뀌는 게임 구조
  - 과장된 통통 튐
  - 착지 때 차체가 눌리는 연출
- 이 게임은 실차 수치에 맞춘 물리를 기본으로 하고, 과장은 보이기용 스프링(squash)의 세기로만 조절한다. 실제 차의 움직임이 설계의 결과로 보여야 하기 때문이다(잘못 만든 현가는 실제로 나쁘게 움직여야 한다).

## 4. BeamNG.drive 분석

[JBeam 문서](https://documentation.beamng.com/modding/vehicle/sections/)를 기준으로 정리했다.

| BeamNG | 뜻 | 이 게임에서 |
|---|---|---|
| 노드 | 질량을 가진 점. 충돌은 노드만 한다 | 타이어 고리의 점, 차축, 차체 |
| 빔 | 노드 사이 스프링·댐퍼. 변형이 여기서 나온다 | 타이어의 방사·둘레·교차 스프링, 판스프링 |
| [압력 바퀴](https://documentation.beamng.com/modding/vehicle/sections/wheels/) | 노드·빔·삼각형으로 된 실시간 타이어. 공기압이 있고, 미끄럼 속도와 하중에 따라 마찰이 바뀐다 | 그대로 2D로 옮겼다: 점 18개 고리 + 내부 압력 + 지면 마찰 |
| [플렉스바디](https://documentation.beamng.com/modding/vehicle/sections/flexbodies/) | 보이는 모델을 노드 묶음에 붙여 노드가 움직이면 따라 변형 | 우리 그림(Z 부품)을 노드에 붙이는 방식이 같다. 차체는 강체 + 자세별 다시 그리기, 타이어는 고리 모양 그대로 |
| [파트·슬롯](https://documentation.beamng.com/modding/vehicle/intro_jbeam/partslotsystem/) | 부품이 슬롯에 끼워지고, 이름 붙은 노드를 공유해 연결된다 | 이미 정한 공통 장착 기준(검토 22·23)과 같은 생각이다. 부품이 장착점 이름을 갖는다 |
| 파워트레인 | 엔진 → 클러치 → 변속기 → 트랜스퍼 → 축 → 디퍼렌셜 → 바퀴의 장치 연결 | 1차판 `legacy/sim/dyn.mjs`에 같은 사슬이 있다. 트랜스퍼 케이스(4륜)만 더하면 된다 |

**가져오지 않는 것:**
- 차체 전체를 노드·빔으로 만드는 완전 연체 차체. 계산이 수천 배 많고, 충돌 변형은 이 게임의 주제가 아니다.
- 3D.

## 5. 기술 시험 (첨부 1·2)

`physics/rig.ts`, `render/car/running.ts`, `render/car/pose.ts`, `tools/ref/rigdemo.ts`.

### 물리 (실차 근사값)
| 구성 | 값 |
|---|---|
| 차체 | 1050kg, 피치·롤 관성 |
| 일체차축 2개 | 각 85kg, 상하·기울기 |
| 판스프링 4개 | 앞 42kN/m, 뒤 48kN/m. 잎 사이 마찰 260N, 범프 고무, 리바운드 끈, 망원식 댐퍼 |
| 타이어 4개 | 6.00-16, 점 18개 고리. 공기압 1.8bar, 지면 마찰 0.95. 정지 상태에서 약 40mm 눌림 |
| 구동 | 네 바퀴에 토크(4륜). 차축 감김 반작용으로 출발할 때 앞이 든다 |
| 지면 | 가까운 쪽과 먼 쪽 높이 따로 |

### 시험 코스
1. 가까운 바퀴만 넘는 통나무 → 롤 약 1°, 스프링 45mm 눌림 후 반동
2. 먼 바퀴만 넘는 턱
3. 움푹 팬 곳
4. 22cm 낙차 → 앞으로 숙였다가 착지해 튐, 스프링 78mm, 차체 찌그러짐 1.8%
5. 빨래판 길

시속 약 15km/h(4.2m/s).

### 그림 (위: 보이는 그대로, 아래: 차체는 선만, 섀시는 전부)
- 4바퀴: 먼 쪽 바퀴, 판스프링, 댐퍼가 위·뒤로 조금 비켜 어둡게 보이고, 먼 쪽 길을 따로 탄다.
- 프레임, 엔진(블록·헤드·로커 커버·발전기·기화기), 벨하우징, 변속기, 트랜스퍼 케이스, 배기관·소음기, 라디에이터, 스프링 행어, 범프 고무: 차체와 함께 움직이는 섀시 그림이다.
- 앞뒤 디퍼렌셜, 프로펠러 샤프트 2개(트랜스퍼 → 각 차축), 판스프링 4개와 섀클, 댐퍼 4개, 타이어, 휠: 매 프레임 물리대로 그린다.
- 첨부 2의 위 줄은 기둥 밀기만 쓴 것, 아래 줄은 자세마다 다시 그린 것. 아래가 맞다.

### 남은 것
- 비포장 토양(침하, 헛돎, 흙 튐) — Desert Steel에서 가져온다.
- 1차판 파워트레인 사슬(엔진 회전수, 변속, 클러치)과 연결.
- 롤은 지금 바퀴 위치로만 보인다. 앞·뒤 보기에서는 롤 자세를 다시 그리기로 처리한다.
- 당시 다른 현가 형식: 가로 판스프링, 4분타원, 1934년 이후 독립 현가(위시본+코일, 토션 바). 토션 빔은 대부분 뒤 시기다.
- 섀시 그림의 세부(볼트, 리벳, 배선)와 실차 조사로 보강할 부분(엔진 모양, 트랜스퍼 위치).
- 휴대폰 성능: 한 프레임 물리 200단계 × 타이어 4개가 지금 약 25ms다. 한 대만 달리는 시험 주행 장면에는 충분하다. 길거리의 여러 대는 단순 모델로 돌린다.

## 6. 실차 조사
세부 참고용으로만 쓴다(지시대로):
- 엔진 모양
- 트랜스퍼 위치
- 스프링 길이와 잎 수
- 댐퍼 형식
- 타이어 규격

값과 확신도를 제원표에 적고, 그림 판단은 원본 시트와 함께 눈으로 한다.

## 7. 정할 것
1. 자세는 윤곽에서 다시 그리기(채택), 탄성 찌그러짐은 착지 때 약하게(지금 최대 2%). 세기를 올릴지.
2. 다음 순서:
   1. 토양과 파워트레인 사슬 연결
   2. 다른 현가 형식
   3. 1920년대 첫 차에 같은 하체 적용
3. 길거리 차는 단순 모델(고리 타이어 없이)로 돌린다.
