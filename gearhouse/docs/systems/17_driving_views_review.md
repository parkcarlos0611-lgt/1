# 검토 17 — 주행 장면의 시점: 사이드뷰와 탑뷰, 벨트스크롤과 사이드스크롤

기획자 지시(2026-11-19)에 대한 검토다. 적용한 것은 없다. 맨 끝의 결정 사항에 답을 받으면 계획에 넣는다.

지시:
- 길거리, 직선 주행, 드래그 레이스는 사이드뷰로, 방향 전환이 필요한 트랙 경주와 주행은 탑뷰로 나누어 쓰는 방안을 검토한다.
- 사이드뷰를 깊이가 있는 벨트스크롤로 할지, 한 평면만 보이는 사이드스크롤로 할지 검토한다.

지금까지의 결정: 탑뷰가 기본 주행(스프라이트 스태킹, 약 300px), 사이드샷은 일부 장면에만(2026-11-19 이전 결정). 이번 지시는 이를 "장면의 성격에 따라 나눈다"로 바꾸는 것이다.

## 1. 장면별 시점

| 장면 | 시점 | 까닭 |
|---|---|---|
| 읍내 거리, 손님에게 배달, 공방 앞 | 사이드뷰 | 우리가 가진 그림(측면 400px)을 그대로 쓴다. 가게, 사람, 날씨가 배경에 보인다 |
| 직선 시험(가속, 최고 속도, 제동) | 사이드뷰 | 앞뒤 움직임만 있다. 차의 기울어짐(가속 때 꼬리가 내려앉고 제동 때 코가 숙는 것)이 잘 보인다 |
| 드래그 레이스 | 사이드뷰 | 두 대가 나란히 달리는 것이 한눈에 보인다 |
| 언덕 오르기, 험한 길 시험 | 사이드뷰 | 경사와 바퀴가 튀는 모습이 옆에서 보여야 한다. 1차 판과 Desert Steel의 높이 지형을 쓸 수 있다 |
| 트랙 경주, 도로 경주, 랠리 | 탑뷰 | 굽은 길에서 조향이 핵심이다 |
| 조종성 시험(슬라럼, 원 선회) | 탑뷰 | 옆으로 미끄러짐과 회전이 보여야 한다 |
| 퍼레이드, 품평회 입장 | 사이드뷰 | 차를 보여 주는 장면이다 |

- 물리는 하나로 둔다. 엔진·변속기·타이어·무게의 계산(계획 14의 B)이 같고, 사이드뷰는 앞뒤 + 위아래(현가, 경사), 탑뷰는 평면 운동을 쓴다. 같은 차가 두 시점에서 같은 성능을 낸다.
- 사이드뷰 주행은 1차 판에서 "멀미가 난다"는 지적이 있던 도로 화면과 다르다. 그때는 도로를 따라 화면이 기울고 휘었다. 이번에는 땅이 수평이고 배경만 겹으로 흐른다.

## 2. 사이드뷰의 두 방식

| | 사이드스크롤 (한 평면) | 벨트스크롤 (깊이 있는 2D) |
|---|---|---|
| 모습 | 모든 차가 한 줄 위에 있다. 앞뒤로만 움직인다 | 화면 위아래가 앞뒤 깊이가 된다. 차가 여러 차선을 오가고, 먼 차선의 차는 위쪽에 그려진다 |
| 필요한 그림 | 지금의 측면 그림 그대로 | 차선을 바꿀 때 차가 비스듬히 틀어지는 모습이 필요하다. 순수 측면 그림만으로는 차선 변경이 미끄러지듯 보인다. 제대로 하려면 3/4 각도 그림이 더 필요하다 |
| 다른 차 | 앞뒤에만 있다. 추월이나 마주 오는 차를 보여 주기 어렵다 | 추월, 마주 오는 차, 주차된 차, 길 건너는 사람이 자연스럽다 |
| 조작 | 가속·제동·변속만. 휴대폰에서 쉽다 | 차선 이동이 더해진다. 터치로는 조금 번거롭다 |
| 드래그 레이스 | 두 대를 위아래 두 줄로 겹쳐 그려야 한다 | 두 차선에 나란히 선다 |
| 충돌 판정 | 단순하다 | 깊이가 겹치는지 따로 따져야 한다. 같은 높이에 그려진 차끼리만 부딪친다 |
| 만드는 품 | 작다 | 크다. 그림(3/4 각도), 깊이 정렬, 차선 이동 연출이 더 든다 |

### 2-1. 제안: 차선이 정해진 사이드스크롤 (2.5평면)

두 방식의 가운데를 제안한다.

- 화면에 차선을 2~3개 둔다: 가까운 차선, 먼 차선, 그리고 인도(사람과 주차된 차).
- 차선은 위아래로 일정한 간격(약 30~40px)을 두고 그린다. 차는 크기를 바꾸지 않는다(픽셀아트가 늘었다 줄었다 하지 않도록). 먼 차선은 조금 어둡게 한다.
- 차선 변경은 자유 이동이 아니라 0.5초쯤 걸리는 "옮겨 가기"다. 차가 위아래로 미끄러지며 차체가 1~2px 기운다. 순수 측면 그림으로도 어색하지 않다.
- 이것으로 추월, 마주 오는 차(먼 차선에서 반대 방향, 그림을 좌우로 뒤집음), 드래그 레이스(두 차선), 길가 주차가 된다.
- 충돌은 같은 차선 안에서만 따진다.
- 배경은 겹(4~6장)으로 흐른다. 가까운 것일수록 빨리 흐른다(Desert Steel의 방식).

벨트스크롤의 자유로운 깊이 이동은 권하지 않는다. 3/4 각도 그림이 차마다 더 필요해 200종의 그림 일이 거의 두 배가 되고, 얻는 것은 거리 장면의 자유도 정도다.

### 2-2. 사이드뷰에서 차를 움직이게 하려면 필요한 것

| 항목 | 내용 |
|---|---|
| 바퀴 따로 | 지금은 바퀴가 차 그림 안에 그려진다. 바퀴를 따로 그려 돌려야 한다(바퀴살·휠캡 무늬를 각도별로 몇 장). |
| 차체 흔들림 | 현가에 따라 차체만 위아래·앞뒤로 1~3px 움직인다 |
| 연기·먼지 | 배기 연기, 흙길 먼지, 비 오는 날 물보라 |
| 반대 방향 | 그림을 좌우로 뒤집으면 빛이 오른쪽 위에서 오게 된다. A 방식은 빛이 왼쪽 위로 정해져 있어, 반대 방향 차는 따로 그리는 것이 맞다(1차 판의 오른쪽 그림과 같은 방식). 먼 차선의 마주 오는 차 정도는 뒤집어도 눈에 덜 띈다 |

## 3. 탑뷰

- 이미 정한 대로 스프라이트 스태킹(높이별 단면을 쌓기) 약 300px이다.
- 단면은 참고 시트의 평면·측면·정면에서 딴 뼈대로 만든다. 측면만 있으면 안 된다.
- 트랙은 도로망과 높이 지도로 만든다. 날씨(비, 눈)는 노면 마찰을 바꾼다.

## 4. 넣는 순서 제안

1. 사이드뷰 직선 시험(한 차선): 바퀴 따로, 차체 흔들림, 겹 배경. 구동계 계산이 화면으로 보이는 첫 장면이다
2. 드래그 레이스와 거리(두세 차선, 다른 차, 마주 오는 차)
3. 배달 컷신을 이 장면 위에서 만든다
4. 탑뷰 트랙 주행(뼈대의 평면 윤곽이 쌓인 뒤)

## 5. 결정이 필요한 것

1. 장면별 시점을 1장의 표처럼 나눌지.
2. 사이드뷰를 "차선이 정해진 사이드스크롤(2.5평면)"로 할지, 한 차선 사이드스크롤로 할지, 자유로운 벨트스크롤로 할지. (추천: 2.5평면)
3. 반대 방향으로 달리는 차를 따로 그릴지(빛이 맞음), 뒤집어 쓸지(품이 적음). (추천: 가까운 차선은 따로, 먼 차선은 뒤집기)
4. 사이드뷰 직선 시험을 다음 차례(견본 3종과 구동계 계산 다음)로 둘지.
