| 항목 | 지금 | 고칠 방법 | 확인 |

## 2. 토큰 비교
### 무엇을 비교하나
- 아래 숫자는 각 에이전트가 끝났을 때의 **대화 길이(토큰)**다. 실제로 쓴 총량은 이보다 크다. 에이전트는 도구를 한 번 쓸 때마다 그때까지의 대화를 다시 읽기 때문이다(대부분 캐시로 처리된다).
- 그래도 같은 방식으로 잰 값이라 서로 비교할 수는 있다.
- 모델마다 토큰 단가가 다르다. 이 표는 양만 비교하고 비용은 비교하지 않는다.

### 차 한 대에 든 양
| 차 | 방식 | 단계별 (토큰, 도구 사용 횟수) | 합계 |
|---|---|---|---|
| **F355** | **Opus 혼자** (시트+차체 한 에이전트) | 시트+차체 351,568 (94회, 30분) | **약 35만** |
| **NSX** | **Opus 시트 + Fable 차체** | 시트(Opus) 198,534 (80회) + 차체(Fable) 345,745 (71회, 29분) + 뒷면 다시 만들기(Fable) 194,541 (53회) | **약 74만** (처음 제작만 약 54만) |
| **디아블로** | **Fable 혼자** (시트+차체) | 첫 시도 중지(기록 없음) + 다시 시작 259,930 (78회) + 보강 약 2만 추가 | **약 28만 + 중지된 첫 시도** |
| EB110 패널판 | Fable 차체 (시트는 내가 따로 작성) | 395,473 (53회) | 약 40만 |
| 참고: 물리 | Opus | NSX 232,945 / F355 190,886 | — |
| 참고: 공용 엔진 모듈 | Opus | 177,027 (한 번 만들고 모든 차에 재사용) | — |

### 해석
- **나눠 맡기는 방식(Opus 시트 + Fable 차체)이 가장 많이 들었다.** 차체 에이전트가 시트와 자료를 처음부터 다시 읽어야 하기 때문이다. NSX는 뒷면을 다시 만든 몫까지 더해져 더 커졌다.
- **한 에이전트가 시트와 차체를 이어서 하면** 자료를 한 번만 읽는다. Opus 혼자 만든 F355가 약 35만, Fable 혼자 만든 디아블로가 약 28만으로 비슷한 수준이다.
- **품질:** Fable 결과물(NSX, 디아블로)은 파낸 디테일이 더 많았다. Opus 결과물(F355)은 비례는 맞지만 디테일이 덧붙인 판이었다. 다만 차와 자료가 달라서 엄밀한 비교는 아니다.
- **비용:** 단가가 모델마다 달라서, 토큰이 같아도 비용은 다르다.

### 권장
- **새 차:** 한 에이전트가 시트와 차체를 이어서 맡는다. 품질이 중요하면 Fable, 비용을 아끼려면 Opus.
- **Opus로 만든 뒤 Fable로 보완하기**(이번 F355 계획): 보완 에이전트가 기존 파일과 자료를 다시 읽어야 하므로 약 20만 토큰이 더 들 것으로 본다. NSX 뒷면 다시 만들기가 약 19만이었다.

## 3. 대안: Fable이 처음부터 혼자 다시 만들기 (검토 160)

### 두 방안 비교
| | (가) Fable 보완 (1절) | (나) Fable이 처음부터 다시 만들기 |
|---|---|---|
| 하는 일 | Opus 차체를 두고 그릴, 램프, 덕테일, 보닛 면, 휠만 고친다 | 시트(이미 있음)를 기준으로 차체를 새로 만든다. 지금 파일은 참고만 한다 |
| 예상 토큰 | 약 20만 | **약 30~40만** (디아블로 28만, EB110 패널판 40만, NSX 차체 35만 기준) |
| 품질 상한 | Opus 차체의 구조(한 장의 껍질 + 덧붙인 판)를 넘기 어렵다. 구멍을 파려면 껍질을 다시 나눠야 해서 사실상 절반은 새로 만들게 된다 | NSX·디아블로처럼 패널을 처음부터 나눠서, 파낸 디테일과 날카로운 경계를 구조에서부터 만든다 |
| 위험 | 기존 구조 위에 덧대다 보면 이음매와 틈이 생기기 쉽다 | 결과가 지금보다 못할 수 있다. 다만 지금 파일이 남아 있어 비교한 뒤 좋은 쪽을 고르면 된다 |
| 남는 것 | 고친 F355 한 대 | F355 한 대와, 같은 지시로 만든 Opus판·Fable판의 직접 비교(같은 차, 같은 자료) |

### 판단: (나)를 권장
- 보완해야 할 것 대부분이 구조 문제다. 그릴, 램프, 번호판을 파내려면 앞뒤 면을 패널로 다시 나눠야 한다. 덕테일과 테일 패널의 관계도 마찬가지다. 그래서 보완 비용이 다시 만드는 비용에 가까워진다.
- 시트(`data/cars/spec/f355.json`)는 이미 검증된 것이 있다. Fable은 차체에만 집중하면 된다. 앞서 NSX에서 비용이 컸던 원인(시트와 자료를 처음부터 다시 읽는 것)도 시트가 짧고 정리돼 있어 덜하다.
- 같은 차를 두 모델이 만든 결과가 생긴다. 앞으로 차를 만들 방식을 정할 근거가 된다.

### 진행 방식
1. **지시:** NSX 차체 때 지시와 같은 형식이다.
   - 반드시 살릴 요소: 옆 홈, 루버와 V8, 버팀벽, 팝업 램프, 파낸 앞 그릴과 안개등, 파낸 원형 테일램프 4개, 덕테일과 들어간 테일 패널, 쌍배기구, 깊이 있는 5스포크 휠.
   - 실시간 렌더러 확인을 조건으로 건다.
2. **파일:** `render/car/mesh_f355_fable.ts`로 따로 만든다. 지금 파일은 그대로 둔다.
3. **비교:** 같은 각도(3/4 앞뒤, 정면, 정후면, 실시간 렌더러)로 두 판을 나란히 놓고, 렌더와 겹쳐 본 오차와 토큰 사용량을 함께 정리한다.
4. **선택:** 정해 주시는 판을 `mesh_f355.ts`로 등록한다. 다른 판은 참고용으로 남기거나 지운다.
- 예상 시간: 30~40분.
