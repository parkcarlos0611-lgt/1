# 시스템 설계 01 — 시간과 사건 정지

수직 슬라이스(소규모 공방, 미국, 1930~1935) 기준이다. 수치는 모두 시작값이고 `data/`의 JSON에 둔다.

## 1. 목적

- 하루하루가 눈에 보이게 지나가고, 일이 생길 때마다 멈춰서 플레이어가 읽고 결정한다.
- 화면 없이도 같은 시드로 같은 5년이 재현된다(자동 시험, 밸런스 조정).

## 2. 달력과 하루의 구조

| 항목 | 값 |
|---|---|
| 시작일 | 1930-01-01 (수요일) |
| 틱 단위 | 하루 |
| 속도 | 1배속 8초, 2배속 4초, 3배속 약 2.7초 |
| 근무일 | 월~토 (1930년대 미국 소규모 업체 기준). 일요일은 휴무 |
| 실제 달력 | 윤년, 요일, 공휴일(설날, 독립기념일, 추수감사절, 성탄절)을 따른다 |

하루는 세 구간으로 나뉜다. 화면에서는 시계와 창밖 빛으로 보인다.

| 구간 | 시각 | 일어나는 일 |
|---|---|---|
| 아침 | 07~09시 | 우편과 신문이 도착한다. 납품 트럭이 온다 |
| 낮 | 09~18시 | 작업 시간이다. 전화와 방문 손님이 온다 |
| 저녁 | 18시 이후 | 하루 결산(작업 진척, 지출, 숙련 성장) |

## 3. 창업자의 시간 — 소규모의 핵심 자원

소규모 공방에서는 창업자 본인의 하루가 가장 귀한 자원이다. "직접 하기 → 맡기기 → 결정만 하기"가 여기서 시작된다.

- 창업자는 근무일마다 **10시간**을 쓴다. 야근으로 14시간까지 늘릴 수 있지만 피로가 쌓인다.
- 시간을 쓰는 일은 **작업 배정표**(책상 위 주간 계획표)에 올린다.

| 일 | 시간 | 비고 |
|---|---|---|
| 설계 도면 작업 | 프로젝트 단계별 필요 공수에서 차감 | 설계 능력치가 속도를 정한다 |
| 차량 제작(용접·판금·조립) | 차 한 대의 제작 공수에서 차감 | 직원과 나눠서 한다 |
| 고객 상담 | 건당 1~3시간 | 방문 손님은 그 자리에서, 편지는 답장 작성 |
| 공급사 방문 | 반나절~하루 | 거리에 따라 다르다 |
| 직원 면접 | 건당 1~2시간 | |
| 신문·잡지 읽기 | 0시간 | 시간을 쓰지 않는다. 읽는 재미를 막지 않기 위해서다 |

- 배정하지 않은 시간은 자동으로 "진행 중인 제작"에 들어간다. 그래서 아무것도 안 눌러도 공방은 돈다.
- 피로: 야근 시간이 주 10시간을 넘으면 다음 주 작업 효율이 10% 떨어진다. 4주 연속이면 병가 사건이 날 수 있다.
- 직원이 늘면 일을 맡길 수 있다. 맡긴 일은 그 직원의 능력치로 진행된다.

## 4. 사건과 자동 정지

사건은 세 등급이다. 등급마다 기본 정지 여부가 다르고, 설정에서 종류별로 켜고 끌 수 있다.

| 등급 | 예 | 기본 동작 |
|---|---|---|
| 결정 필요 | 고객 문의·주문, 공급사 견적 회신, 계약 만료, 직원 사직 통보, 납기 지연, 현금 부족, 사고 | 반드시 멈추고 창을 띄운다. 끌 수 없다 |
| 알림 | 신문·잡지 도착, 납품 도착, 차량 완성, 면접 지원자 도착, 리뷰 게재 | 멈춘다. 종류별로 끌 수 있다 |
| 기록 | 급여 지급, 정기 지출, 숙련 성장, 날씨 | 멈추지 않는다. 일지에만 남는다 |

- 같은 날 여러 사건이 생기면 아침 → 낮 → 저녁 순으로 하나씩 보여 준다.
- 결정 필요 사건에는 **응답 기한**이 있다(예: 고객 문의 14일). 미루기를 누르면 책상 위 서류함에 남고, 기한이 지나면 자동으로 놓친 것으로 처리된다.
- 슬라이스 초반 목표 빈도: 정지가 평균 2~4일에 한 번. 너무 잦으면 알림 등급부터 묶어서 보여 준다(아침 우편 묶음).

## 5. 건너뛰기

- **한 주 / 한 달 건너뛰기**: 하루를 약 0.3초씩 넘기며 달력이 넘어가는 것을 보여 준다. 한 달이면 약 9초다.
- 정지 등급 사건이 생기면 그 날에서 멈춘다.
- **다음 사건까지**: 다음 정지 사건이 생길 때까지 넘긴다. 최대 30일.
- 건너뛰는 동안 창업자의 시간은 배정표대로 자동으로 쓰인다.

## 6. 실시간 장면과 달력

- 시험 주행, 직접 용접 같은 실시간 장면에 들어가면 달력이 멈춘다.
- 장면이 끝나면 그 장면이 쓴 시간(예: 시험 주행 반나절 = 5시간)만큼 창업자의 시간에서 뺀다.

## 7. 연락 수단과 걸리는 시간

1930년 미국 기준이다. 모든 거래(공급사, 고객, 구인)가 이 지연을 따른다.

| 수단 | 걸리는 시간 | 조건 |
|---|---|---|
| 방문 | 그 자리에서 | 같은 도시. 다른 도시는 이동에 반나절~이틀 |
| 전화 | 그 자리에서 | 양쪽 다 전화가 있어야 한다. 시외 전화는 요금이 든다 |
| 우편 | 편도 2~5일 | 거리에 따라 다르다 |
| 전보 | 당일 | 비싸다. 짧은 내용만 |

- 공방에 전화를 놓는 것은 초반 투자 선택지다(설치비와 월 요금). 전화가 없으면 문의가 우편과 방문으로만 온다.

## 8. 상태 데이터

```
Clock      { date, phase, speed, paused, seed }
Founder    { hoursToday, overtimeWeek, fatigue }
WorkPlan   { week, slots: [{ task, hours }] }

Journal    [{ date, text }]

```

## 9. 하루 틱 순서

1. 날짜를 하루 올린다. 요일·공휴일을 판정한다.
2. 아침: 우편 도착, 신문 발행일이면 신문 도착, 납품 도착을 큐에 넣는다.
3. 낮: 각 시스템이 그날의 사건을 만든다(문의 발생, 방문 손님, 전화). 작업 배정표대로 공수를 진행한다.
4. 저녁: 지출과 수입을 정산한다. 숙련을 올린다. 기한이 지난 사건을 처리한다.
5. 정지 등급 사건이 큐에 있으면 `game_paused`를 내고 멈춘다.

## 10. 이벤트

| 이벤트 | 내용 | 듣는 시스템 |
|---|---|---|
| `day_started` | 날짜, 요일, 근무일 여부 | 전부 |
| `phase_changed` | 아침·낮·저녁 | 미디어, 공급, 판매 |
| `day_ended` | 날짜 | 재무, 인사 |
| `event_raised` | 사건 종류, 등급, 기한 | UI |
| `event_resolved` | 사건 id, 선택 | 해당 시스템 |
| `event_expired` | 사건 id | 해당 시스템(평판 하락 등) |
| `game_paused` / `game_resumed` | 이유 | UI |
| `hours_spent` | 일, 시간, 누가 | 프로젝트, 생산, 피로 |

## 11. 결정이 필요한 것

1. 창업자의 하루 시간을 자원으로 쓰는 방식(3장)으로 갈지. 대안은 시간 개념 없이 프로젝트 진행률만 두는 것이다.
2. 일요일 휴무와 공휴일을 넣을지. 넣으면 시대감이 살지만 "멈춘 날"이 생긴다.
3. 신문 읽기에 시간을 쓰지 않게 할지(지금 제안은 0시간).
