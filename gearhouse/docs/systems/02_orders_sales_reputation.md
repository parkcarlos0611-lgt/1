# 시스템 설계 02 — 주문 고객, 판매, 평판

수직 슬라이스(소규모 공방, 미국, 1930~1935) 기준이다. 수치는 시작값이고 5년 자동 진행 시험으로 조정한다. 금액은 당시 달러다.

## 1. 목적

- 소규모 공방의 돈과 이름이 어디서 오는지를 한 순환으로 만든다: 광고 → 문의 → 상담 → 주문 → 제작 → 인도 → 만족 → 입소문·평판 → 다음 문의.
- 고객 한 명 한 명이 이름과 사정을 가진 사람이다. 숫자가 아니라 편지와 방문으로 만난다.

## 2. 시장의 크기 감각 (1930년 미국, 확인 필요한 근사값)

| 항목 | 값 |
|---|---|
| 보급형 신차 | 약 $450~$600 |
| 중급 세단 | 약 $1,000~$1,500 |
| 고급차 | 약 $3,000~$6,000 |
| 주문 제작 차체(코치빌드) | 섀시 값 위에 약 $2,000~$8,000 |
| 노동자 연 소득 | 약 $1,300~$1,500 |
| 숙련공 주급 | 약 $30~$40 |

- 공방의 차는 대당 $1,800~$7,000 범위가 목표다. 한 해 3~8대를 만든다.
- 대공황으로 1930~1933년 사이 고급차 수요가 크게 줄어든다(경제 시스템이 수요 배수로 준다).

## 3. 인지도와 평판

두 값을 따로 둔다. 인지도는 "아는 사람 수", 평판은 "아는 사람들의 평가"다.

| 값 | 범위 | 오르는 원인 | 내리는 원인 |
|---|---|---|---|
| 인지도 | 권역별 0~100 (동네, 도시, 주, 전국) | 광고, 신문 기사, 잡지 리뷰, 거리에 다니는 내 차, 레이스 | 시간(매달 조금씩 잊힌다) |
| 평판 | 분야별 −100~+100 (품질, 성능, 멋, 신뢰, 값어치) | 만족한 고객, 좋은 리뷰, 약속 지키기 | 불만 고객, 고장, 납기 지연, 나쁜 리뷰 |

- 인지도는 가까운 권역부터 찬다. 동네 인지도가 60을 넘어야 도시 인지도가 제대로 오른다.
- 평판은 분야별이라 "빠르지만 잘 고장 나는 차"라는 이름이 붙을 수 있다. 잡지 성격과 고객 성향이 분야를 다르게 본다.

## 4. 문의가 생기는 길

| 길 | 조건 | 특징 |
|---|---|---|
| 신문 광고 | 광고비를 내고 지역지에 실음 | 게재 주부터 2~3주 동안 문의가 온다 |
| 잡지 광고 | 광고비가 더 비싸다 | 넓은 권역, 진지한 손님 비율이 높다 |
| 입소문 | 만족한 고객이 있음 | 돈이 안 든다. 고객의 사회적 지위가 높을수록 세다 |
| 지나가다 들름 | 동네 인지도 | 구경꾼이 많다 |
| 단골 | 이전 고객 | 2~6년 뒤 다시 온다 |
| 기사·리뷰 | 신문·잡지에 실림 | 한꺼번에 몰린다 |

- 주간 문의 수는 `권역 인구 중 살 만한 사람 × 인지도 × 경기 배수 × 광고 효과`를 평균으로 하는 무작위 수다.
- 슬라이스 초반 목표: 광고를 하면 한 달에 문의 2~5건, 그중 주문은 0~1건.

## 5. 고객

문의가 생기면 고객 한 명을 만든다.

```
Customer {
  name, age, job, town            // 국가별 이름 데이터, 직업은 시대 직업표
  wealth                          // 예산의 바탕
  standing                        // 사회적 지위 0~100: 입소문 세기
  budget: [low, high]
  wants: { body, seats, use, priorities: [분야 순서] }   // 예: 2인승 로드스터, 주말용, 멋 > 성능 > 값어치
  mustHave: [...]                 // 예: "시속 80마일", "접이식 지붕", "짙은 녹색"
  deadline                        // 원하는 인도 시점
  patience                        // 답장을 기다려 주는 날 수, 지연 허용
  temper                          // 까다로움: 만족도 계산의 엄격함
  channel                         // 편지, 전화, 방문
  source                          // 어느 광고·누구 소개로 왔는지
}
```

- 고객 유형 예: 지역 의사, 은행가, 농장주, 젊은 상속자, 아마추어 레이서, 영화관 주인, 배달업자(상용 갈래).
- 대공황이 깊어지면 유형 비율이 바뀐다. 사치 구매가 줄고, 싸고 튼튼한 상용차 문의가 늘어난다. 회사 진화 갈래 선택과 이어진다.

## 6. 상담과 견적

문의는 결정 필요 사건이다. 응답 기한은 고객의 `patience`다.

1. **문의서 읽기**: 편지나 방문 대화로 `wants`의 일부만 드러난다. 예산은 직접 말하지 않는 고객이 많다.
2. **질문하기**: 상담 시간을 더 쓰면 숨은 요구(`mustHave`, 예산 범위)가 드러난다. 판매 능력치가 높으면 더 잘 드러난다.
3. **제안하기**: 기존 설계를 그대로 권하거나, 고쳐서 권하거나, 새로 설계하겠다고 한다.
4. **견적서 쓰기**: 가격, 인도 날짜, 계약금 비율(보통 25~50%), 사양 요약.
5. **고객 회신**: 수락, 흥정(가격이나 날짜), 거절.

수락 확률은 다음을 본다.

| 요소 | 영향 |
|---|---|
| 가격 대 예산 | 예산 상한을 넘으면 급락한다 |
| 사양 일치 | `mustHave`를 하나라도 놓치면 크게 떨어진다 |
| 인도 날짜 대 희망 | 늦을수록 떨어진다 |
| 평판(고객이 중시하는 분야) | 높으면 비싸도 받아들인다 |
| 판매 능력치 | 소폭 보정 |

- 흥정은 최대 2번 오간다. 그 뒤에는 결렬된다.
- 견적을 낼 때 **원가 예상표**(부품, 공수, 여유분)가 옆에 보인다. 예상이므로 실제 원가는 달라질 수 있다.

## 7. 주문에서 인도까지

1. 계약금을 받는다. 주문서가 작업 게시판에 붙는다.
2. 부품이 없으면 공급사에 발주한다(공급 시스템).
3. 제작한다(생산 시스템). 완성차는 품질 점수와 결함 목록을 갖는다.
4. 선택: 인도 전에 시험 주행을 해 결함을 찾아 고친다(시간과 돈이 든다).
5. 인도한다. 잔금을 받는다.

진행 중 생길 수 있는 사건:

| 사건 | 선택지 |
|---|---|
| 납기 지연 예상 | 고객에게 미리 알림(불만 감소) / 야근 / 품질을 낮춰 맞춤 |
| 고객의 사양 변경 요청 | 추가 요금으로 받음 / 무료로 받음 / 거절 |
| 고객의 지불 능력 상실(대공황) | 계약금 몰수 후 재고로 판매 / 값을 깎아 인도 / 기다림 |
| 고객의 공방 방문 | 진척을 보여 줌(만족 상승, 시간 소모) |

## 8. 만족도와 그 뒤

인도 시 만족도(−100~+100)를 계산한다.

| 요소 | 비중 |
|---|---|
| 사양 일치(`wants`, `mustHave`) | 30% |
| 품질 점수와 눈에 띄는 결함 | 25% |
| 실제 성능(계산 물리 수치) 대 기대 | 15% |
| 납기 준수 | 15% |
| 값어치(가격 대 받은 것) | 15% |

- `temper`가 높으면 감점이 커진다.
- 인도 뒤 1년 동안 **고장 사건**이 생길 수 있다(부품 신뢰성과 제작 품질에 따라). 무상 수리 여부를 정한다. 만족도가 그때 다시 바뀐다.

만족도의 결과:

| 만족도 | 결과 |
|---|---|
| +60 이상 | 감사 편지. 입소문 문의 1~3건(지위에 비례). 지역지 기사가 날 수 있다. 단골 후보 |
| +20~+60 | 평판 소폭 상승 |
| −20~+20 | 변화 없음 |
| −20~−60 | 평판 하락. 나쁜 입소문 |
| −60 이하 | 환불 요구 또는 소송 사건. 지역지에 나쁜 기사가 날 수 있다 |

- 팔린 차는 **차량 대장**에 남는다(주인, 인도일, 상태). 회사 연대기의 자료가 된다.

## 9. 재고 판매 (주문 없이 만든 차)

- 주문 없이 만든 차는 공방 앞에 전시한다. 광고에 "즉시 인도"를 넣을 수 있다.
- 문의 고객 중 사양이 대체로 맞는 사람에게 권한다. 주문 제작보다 수락률은 낮지만 인도가 빠르다.
- 오래 안 팔리면 값을 내리거나, 시승차로 잡지에 보낸다(미디어 시스템).

## 10. 상태 데이터

```
Market      { awareness: { 동네, 도시, 주, 전국 }, reputation: { 품질, 성능, 멋, 신뢰, 값어치 } }
Ad          { medium, cost, startDate, weeks, text }
Inquiry     { id, customer, receivedDate, deadline, revealed: [...], state }
Quote       { inquiryId, designId, price, deliveryDate, depositRate, round }
Order       { id, customer, quote, depositPaid, state, events: [...] }
SoldCar     { id, orderId, designId, owner, deliveredDate, quality, defects, satisfaction }
```

## 11. 하루 틱에서 하는 일

1. 진행 중인 광고마다 그날의 문의 발생을 굴린다.
2. 입소문·단골·지나가다 들름을 굴린다.
3. 기다리는 견적의 고객 회신 날짜가 되면 회신 사건을 낸다.
4. 주문마다 납기 예상을 다시 계산하고, 지연이 예상되면 사건을 낸다.
5. 팔린 차마다 고장을 굴린다(인도 후 1년).
6. 월말: 인지도를 조금 깎는다.

## 12. 이벤트

| 이벤트 | 보내는 내용 | 듣는 시스템 |
|---|---|---|
| `ad_placed` | 매체, 비용, 기간 | 재무, 미디어(지면에 실림) |
| `inquiry_received` | 문의, 고객 | UI, 시간(정지) |
| `quote_sent` / `quote_answered` | 견적, 회신 | UI |
| `order_placed` | 주문 | 생산, 공급, 재무(계약금) |
| `order_changed` / `order_cancelled` | 주문 | 생산, 재무 |
| `car_delivered` | 팔린 차, 만족도 | 재무(잔금), 평판, 미디어 |
| `car_broke_down` | 팔린 차, 결함 | 평판, 수리 |
| `reputation_changed` | 분야, 변화량, 이유 | 미디어(리뷰 대상 여부), 인사(지원자 질) |
| `awareness_changed` | 권역, 변화량 | 판매, 미디어 |

듣는 이벤트: `review_published`(인지도·평판·문의 몰림), `economy_changed`(수요 배수, 고객 유형 비율), `car_built`(인도 가능), `design_finalized`(권할 수 있는 설계 목록).

## 13. 결정이 필요한 것

1. 고객의 숨은 요구를 상담으로 알아내는 방식(6장)으로 갈지. 대안은 요구를 처음부터 다 보여 주는 것이다. 숨기면 판매 능력치와 상담 시간에 의미가 생기지만 더 복잡하다.
2. 대공황으로 고객이 돈을 못 내는 사건(7장)을 넣을지. 시대감은 크지만 초반 난이도가 오른다.
3. 평판을 5분야로 나눌지, 하나로 둘지.
4. 가격·소득 근사값(2장)은 당시 자료로 확인한 뒤 확정한다. 자료를 찾아 대조하는 작업을 제가 할지.
