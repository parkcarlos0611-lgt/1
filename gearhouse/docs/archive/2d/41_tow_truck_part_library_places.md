# 검토 41 — 견인차, 부품 라이브러리, 공방 그림, 판본 1단계 3단계(장소)

기획자 메시지(2026-11-21):
- 바로잡음: 두 번 온 포드 B · 닷지 트럭 시트는 **첫 번째 시트**를 쓴다.
- 질문: 견인차를 NPC 차로만 둘지, 나중에 직접 만들 수 있게 할지.
- 질문: Automation처럼 부품 이름과 큰 미리보기를 보여 주는 것(부품 라이브러리 버튼).

## 1. 견인차: NPC로 둘까, 만들 수 있게 할까

### 추천: 판본 1에서는 NPC만, 나중에 "장비 부품"으로 만들 수 있게

**판본 1 (지금)**
- 견인차는 운송 회사의 차다. 전화번호부 "운송" 칸에서 부르면, 고장 난 손님 차를 끌고 와 집 앞이나 차고 앞에 내려 준다.
- 제작 단계(제도판)의 부품 목록에는 견인 장비가 나오지 않는다.
- 이유: 판본 1은 수리 한 건의 하루가 목표다. 견인 장비까지 부품으로 만들면 하중 · 붐 · 윈치 계산이 필요하다. 지금 들이면 차체 · 프레임 작업이 늦어진다.

**나중 판본 (재미 요소)**
- 견인차는 "차종"이 아니다. 트럭이나 낡은 승용차의 차대 위에 얹는 **장비 묶음**으로 만든다.
- 장비 부품의 예:
  - 크레인 붐 A(목재 A형 틀) / 크레인 붐 B(강철 붐)
  - 손 윈치 / 엔진 동력 윈치(PTO)
  - 고리와 체인, 견인 바퀴 받침(달리)
  - 뒤 받침 다리
- 당시에도 실제로 그랬다.
  - 알려진 바로는, 1910년대 후반 미국에서 정비소가 낡은 승용차 차대에 크레인을 얹어 견인차를 만들기 시작했다.
  - 그 뒤 장비 회사가 "차대는 손님이 가져오고 장비만 판다"는 방식으로 팔았다.
  - 이 고증은 나중에 장비 부품을 만들 때 자료로 다시 확인한다.
- 그래서 게임에서도 "견인 장비 A/B를 사서 낡은 트럭에 단다" 또는 "제도판에서 붐을 설계한다"가 자연스럽다.
- 만들면 얻는 것:
  - 자기 견인 일(고장 차 데려오기 → 수리 손님이 늘어남, 운송비 절약)
  - 마을의 견인 의뢰
- 정해 둘 것: 차종 분류에 "장비 차"라는 갈래를 하나 둔다. 견인 · 소방 · 배달 상자 같은 **윗몸 장비**가 같은 틀을 쓴다. 그러면 소방차 시트도 나중에 같은 방식으로 들어온다.

**지금 할 일**
- 차종 분류와 부품 · 에셋 정리에서 견인차 시트는 "NPC 차량 (나중에 장비 부품의 참고 그림)"으로 표시만 한다.
- 견인차의 부품은 지금 나누지 않는다.

## 2. 부품 라이브러리 (Automation식 큰 미리보기)

### 추천: 두 길로 연다

1. **"부품 라이브러리" 버튼**: 제도판 · 차고 화면 구석에 둔다. 누르면 화면 전체를 쓰는 창이 열린다.
2. **공방 책장의 카탈로그**: 게임 안의 물건으로 연다. 같은 창이 "부품 카탈로그(책)" 모양으로 열린다.

### 창의 모양
- 왼쪽: 갈래 목록(차체 · 펜더 · 발판 · 바퀴 · 램프 · 엔진 · 장비 …)과 그 안의 부품 목록.
- 오른쪽: **큰 미리보기**(화면 절반쯤).
  - 부품마다 있는 3D 부품 모델을 그 부품만 크게 그린다.
  - 앞 · 옆 · 위를 돌려 보고, 빛 방향도 바꿀 수 있다.
- 아래: 이름, 만든 곳(회사 · 공방), 연식, 크기(mm), 무게, 값, 소재 · 칠(검토 37 형식), 맞는 차(차대 길이 · 고정점).
- 아직 손에 넣지 못한 부품은 그림자 실루엣과 "?"로만 보인다. 카탈로그를 사거나 잡지를 읽으면 열린다(배움 · 수집의 재미).

### 기술 메모
- 미리보기는 지금 차 그림에 쓰는 같은 모델(`render/car/model.ts`)과 그리기(`rasterizeFlat`)를 쓴다. 부품 하나만 골라 그리면 된다.
- 따라서 부품 에셋은 "부품 모델 + 이름 · 자료 한 줄"이면 라이브러리에 저절로 들어간다.
- 화면이 좁은 문제는 창을 따로 띄워서 푼다. 제도판 화면은 지금처럼 작은 목록만 유지한다.
- 넣을 때: 판본 1의 8단계(공방 방: 책장) 다음. 판본 목록에 올림.

## 3. 시트와 그림

- 포드 B · 닷지 KC가 두 번 온 시트는 **첫 번째 시트**를 쓴다.
  - 검토 40의 "닷지 시트" 결정을 이 말로 바로잡는다.
  - 두 번째 시트는 참고로만 둔다.
- 공방 그림 2장:
  - 방 전체: 제도판, 침대, 난로, 창, 책장.
  - 제도판 앞: 판 위의 설계도.
  - 둘 다 B 구도 + A 빛 방향과 잘 맞는다. 방 전체는 "공방 방" 장소의 바탕으로 쓴다. 제도판 앞 그림은 제도판에 다가갈 때 넘어가는 장면(나중)으로 쓴다.

## 4. 판본 1, 3단계: 장소 (이번에 한 것)

- 새 화면: `ui/world/world.ts`, 새 페이지 `ui/v1.ts`.
- 장소 다섯 곳: 집 앞, 주방, 공방 방, 차고, 전화 책상.
  - 바탕은 참고 그림을 480×270, 64색으로 줄인 임시 그림이다(`assets/placeholder`).
- 장소 사이를 오가는 길:
  - 문 · 물건 위에 포인터를 올리면 점선 테두리와 이름이 뜨고, 누르면 간다.
  - 아래쪽 버튼이나 1~5 키로도 간다.
  - 방을 옮길 때 화면이 어두워졌다 밝아진다.
- 시계: 위쪽 판에 날짜, 시각, 날씨, 돈, 지금의 속도가 보인다.
  - 집 앞 · 주방 · 공방: 하루 60초.
  - 차고: 작업 20배.
  - 전화 · 다른 화면이 열려 있을 때: 멈춤.
  - 손님 차가 서는 순간: 잠시 느리게.
- 빛: 시각에 따라 밤은 어둡고, 저녁 무렵 바깥은 붉게 물든다. 바깥의 비 · 눈은 날씨대로 떨어진다.
- 그날의 소식: 오른쪽 아래 쪽지에 쌓인다(조간 신문, 수리 손님, 편지 …).
- 일정이 되면 카드가 뜬다. 예: "차 한 대가 집 앞에 섰다" → 나가 본다 / 두고 본다.
- 물건:
  - 침대: 다음 날 06:00으로 잔다.
  - 제도판: 설계 화면으로 간다.
  - 전화: 전화 화면으로 간다.
  - 매시 정각마다 저장한다.
- 아직 안내만 하는 것(다음 단계): 주방 탁자(4단계 손님 상담), 차고 작업대 · 작업 칸(6단계), 책장(8단계 · 부품 라이브러리).

### 확인한 것
- 브라우저로 직접 몰아 봤다: 새로 시작 → 집 앞 → 주방 → 공방 → 차고 → 침대(1월 1일 09:38 → 1월 2일 06:34), 오류 없음.
- 60일 동안 수리 손님 17명이 왔다(처음엔 마을이 가게를 몰라 적다). 바로 시험해 볼 수 있도록 4단계에서 첫 손님을 둘째 날 오전에 오게 할 것.

### 판본 목록에 올릴 것 (다듬기)
- 바탕을 층으로 나누기(하늘 · 집 · 땅 · 앞 소품): 비 오는 날 젖은 길, 밤의 창 불빛, 굴뚝 연기.
- 지금 집 앞 그림은 비 오는 날 그림이라, 맑은 날에도 젖어 보인다. 날씨별 층이 생기면 풀린다.
- 방을 옮길 때 문 소리 · 발소리, 장소마다 바탕 소리(바깥 바람, 난로 탁탁, 차고 울림).
