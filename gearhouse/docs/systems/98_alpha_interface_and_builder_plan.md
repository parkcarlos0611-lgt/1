# 98 · 인터페이스의 실제 게임화(알파)와 부품 빌더 — 검토 (검토 176)

계획 검토만 한다. 순서대로 보고하고, 검토를 받은 뒤 진행한다.

## 1. 지금 상태: 화면이 흩어져 있다
| 화면 | 성격 | 상태 |
|---|---|---|
| `drive.html` (주행 페이지) | 3D 시험장: 차 고르기, 레이스, 트랙 3개, 설정 서랍 | 가장 많이 다듬어졌다. 하지만 게임이 아니라 **시험 도구**다 |
| `game.html` / `desk.html` | 2D 픽셀 책상(주문, 신문, 장부), 도면 화면 | 2D 시대의 것이다. 계획은 보관했고(`docs/archive/2d`), 코드는 남아 있다 |
| `ui/world/*`, `ui/scenes/*` | 2D 장소(주방, 집 앞, 전화번호부, 손님, 차고) | 2D 시대 견본 |
| `meshview.html`, `testtrack.html` 등 | 개발용 보기 | 도구 |
- **게임 체계(`core/`):** 시간·달력, 주문·판매·평판, 공급·계약, 제작 9공정·품질, 사람, 신문, 장부·은행·세금, 날씨, 저장. 코드와 테스트가 있지만 2D 책상 화면에만 붙어 있다.
- **3D 쪽:** 차(키트 2대 + 손 제작 4대 + 시트 차), 물리, 렌더러, 트랙 3개, 레이스, 엔진 모듈. 경영 체계와는 아직 연결되지 않았다.
- **결론:** 재료는 많다. 그런데 "회사를 운영하며 차를 만들어 팔고 경주한다"는 하나의 흐름으로 묶인 화면이 없다.

## 2. 알파의 목표: 한 바퀴 도는 게임
```
회사(차고·사무실) → 설계(부품 빌더) → 시험(시험장·측정) → 생산·원가 → 판매·레이스 → 돈·평판 → 연구(새 부품·장비) → 다음 차
```
- **한 화면 앱:** 시작 화면 → 회사 허브 → 각 화면(빌더, 시험장, 레이스, 시장, 장부)으로 들어가고 나온다. 저장·불러오기를 붙인다.
- **3D 허브:** 회사 차고를 3D로 보여 준다. 설계한 차가 차고에 서 있고, 클릭하면 빌더나 시험장으로 간다.
- **경영 화면:** 주문, 판매, 장부, 신문을 3D 위의 판(패널) UI로 띄운다. 2D 책상의 기능(`core/`)을 그대로 쓰고 겉모습만 바꾼다.
- **알파 범위(제안):** 1년 안팎의 플레이. 설계 → 시험 → 판매·레이스 → 연구 한 바퀴가 2~3번 돌면 충분하다.

## 3. 먼저 정할 것: 알파의 시대
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| (가) 1990년대 시험 라인 | 키트 차(NSX, F355)와 장비(ABS, TCS, VTEC, F1 변속기)로 빌더를 시작한다 | 지금 3D 재료가 가장 많다. 빌더를 바로 만들 수 있다 | 게임 본편 설정(1930년대 작은 공방)과 다르다 |
| (나) 1930년대 본편 | 경영 체계(`core/`)가 1930년 기준이다 | 게임의 원래 설정이다 | 키트에 1930년대 계열(분리 펜더, 발판, 라디에이터)이 없다. 그걸 먼저 만들어야 한다 |
- **권장:** 빌더는 (가)로 먼저 만들어 구조를 검증한다. 그사이 키트에 1930년대 계열을 더해 (나)로 옮긴다. 빌더 코드는 시대와 상관없이 같다.

## 4. 부품 빌더 계획 (먼저 할 것)
### 4-1. 무엇을 고르나
| 층 | 고르는 것 | 지금 있는 것 |
|---|---|---|
| 플랫폼 | 엔진 위치(미드십, 앞), 구동(후륜, 4륜), 차체 소재, 휠베이스·윤거·오버행·높이 | 키트의 선 체계가 늘이기를 받는다(교체 시험 통과) |
| 차체 | 코(`round`, `pointed`), 헤드램프(`popup`), 캐빈(`canopy`, 버팀벽), 옆 흡기(`intake`, `scoop`), 데크(`lid`, `louvre`), 꼬리(`frame`, `roundLamps`, `ducktail`), 색 | NSX와 F355에서 뽑은 형태. 섞어 끼우기 시험을 일부 통과했다 |
| 부품 | 휠(`fiveSpoke`, `disc`, `star`), 램프 묶음, 미러, 배기 수 | 있음 |
| 엔진 | 배열(V6, V8, V12), 실린더, 배기량, 밸브, 과급(터보 수), VTEC | 엔진 메시 모듈은 있다. **사양에서 출력 곡선을 만드는 계산이 없다** |
| 구동계 | 변속기(수동 5·6단, F1), 기어비, 종감속, LSD | 물리에 있다(차 사양에 직접 적는 방식) |
| 장비 | ABS, TCS, 스티어링(수동, 유압, 전동), 댐퍼(고정, 가변), 윙, 디퓨저 | 물리에 있다 |

### 4-2. 새로 만들어야 할 것
1. **설계 데이터(`Design`):** 위 선택을 담는 JSON 하나. 저장, 공유, 비교의 단위가 된다.
2. **설계 → 차(메시):** `Design`을 키트 조립 명세로 바꾸고, `assemble`로 메시를 만든다. 고를 수 있는 조합은 이음매 검사를 통과해야 한다. 통과하지 못하는 조합은 막거나 경고한다.
3. **설계 → 물리 사양(`RaceSpec`) 생성기:** 지금은 차마다 사람이 수치를 적는다. 이것을 계산으로 만든다(Opus가 맡을 일).
   - 무게: 플랫폼 + 소재 + 엔진 + 장비
   - 무게중심과 앞뒤 배분: 엔진 위치
   - 공기 저항(cdA): 차체 형태와 크기
   - 출력·토크 곡선: 엔진 사양(배기량, 밸브, 회전수, 과급, VTEC)
   - 기어비: 자동 제안 또는 직접 입력
   - 검증: 생성기로 NSX와 F355를 만들어 실제 사양(최고 속도, 0→100)과 ±5 % 안인지 본다.
4. **빌더 화면(3D):**
   - 가운데: 실시간 렌더러로 차를 띄워 돌려 보고, 엔진룸 투시 보기를 둔다.
   - 왼쪽: 탭(플랫폼, 차체, 부품, 엔진, 구동계, 장비, 칠).
   - 오른쪽: 수치(무게, 마력당 무게, 예상 최고 속도, 0→100, 횡가속, 원가).
   - 휴대폰에서도 쓸 수 있게 한다.
5. **시험 주행 연결:** "시험 주행" 버튼으로 지금 설계를 시험장(로드 코스, 스피드 트랙)에 바로 보낸다. 측정(0→100, 최고 속도, 랩타임)을 설계에 기록한다.
6. **경영 연결(알파 후반):** 부품마다 원가와 등장 연도, 연구 조건을 둔다. `core/supply.ts`(공급)와 `core/build.ts`(제작 공정)에 잇는다.

### 4-3. 순서와 비용 (예상)
| 단계 | 내용 | 맡을 쪽 | 예상 토큰 |
|---|---|---|---|
| B1 | `Design` 데이터와 설계 → 키트 명세 변환. 조합 이음매 시험(무작위 조합 수십 개) | Opus | 15~20만 |
| B2 | 설계 → 물리 사양 생성기. NSX·F355 재현 시험 | Opus | 20~25만 |
| B3 | 빌더 화면(3D 미리보기, 탭, 수치) | Opus(화면) + Fable(보기 다듬기) | 25~35만 |
| B4 | 시험 주행 연결, 측정 기록, 설계 저장 | Opus | 10~15만 |
| B5 | 원가·연도·연구 연결 | Opus | 15~20만 |
- 형태 수가 적으면(코 2종, 꼬리 3종) 빌더가 금방 지루해진다. 그래서 키트 전환(XJ220, EB110, 디아블로)과 병행해 형태를 늘린다. 차체 형태는 Fable이 맡는다.

## 5. 알파 전체 순서 (제안)
1. **부품 빌더 B1~B4.** 지금 가진 3D 재료로 바로 만든다.
2. **키트 형태 늘리기:** XJ220, EB110, 디아블로를 키트로 옮겨 빌더 선택지를 넓힌다(Fable).
3. **한 화면 앱과 회사 허브:** 시작 화면, 3D 차고, 저장. 주행 페이지는 그 안의 "시험장"이 된다.
4. **경영 화면을 3D 위의 판 UI로:** 주문, 판매, 장부, 신문(`core/`를 그대로 쓴다).
5. **빌더 B5(원가·연구)와 경영을 연결해** 한 바퀴를 완성한다.
6. **알파 시험 플레이:** 1년 플레이, 균형, 버그.
- **시대:** 1990년대(가)로 시작하고, 1930년대 계열은 4~5단계와 병행해 키트에 더하기를 권장한다.

## 6. 검토받을 것
- 알파의 시대: (가) 1990년대로 시작(권장) / (나) 1930년대부터.
- 부품 빌더 B1~B4부터 시작해도 될지.
- 회사 허브를 3D 차고로 할지, 2D 책상을 다듬어 쓸지.

## 7. 결정 (사용자 검토, 2026-11-24)
- **시대:** (가) 1990년대로 시작한다. 1930년대 차는 버리지 않는다. **클래식카**(중고·수집 시장, 경매)로 등장시키고, **녹·바랜 칠·찌그러짐 효과**를 입혀 **리스토어**(복원 작업)하는 콘텐츠로 쓴다.
- **부품 빌더 B1~B4:** 진행한다.
- **회사 허브:** 지금은 만들지 않는다. 나중에 3D로 다시 만든다(계획만 남겨 둔다).

## 8. 설계 데이터 (B1·B2 공통, `core/design.ts`)
- `Design` 한 개가 차 한 대의 설계다. 차체는 **바탕 차대**(지금은 `nsx`, `f355`)를 고르고 그 위에 패널 종류를 바꿔 끼운다. 바탕마다 패널의 치수가 다르기 때문이다. 키트에 차가 늘면 바탕도 는다.
- 차체 → `render/car/design.ts`의 `designKit()`(B1), 물리 → `race/design.ts`의 `designSpec()`(B2).

## 9. 결정: 출력 상한 없음 (2026-11-24)
- 1990년대에도 시판차 중 최고 속도 400 km/h 부근(맥라렌 F1 등)이 있었다. 설계 단계에서는 **출력 상한을 두지 않는다.** 한계값은 부품의 물리적 범위일 뿐이다(배기량 1.0~8.0 L, 레드라인 5,000~10,000 rpm, 터보 0~2개).
- 비용, 연구, 신뢰성(냉각·변속기 내구)으로 제약하는 것은 B5에서 다룬다.
