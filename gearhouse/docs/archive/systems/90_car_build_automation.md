# 90 · 차 제작 과정의 자동화 — 검토 (검토 161)

## 지금 사람이 하는 일
차 한 대(EB110, 디아블로, NSX, F355)마다 아래를 손으로 이어 왔다.
1. 자료 받기
2. 시트 작성(에이전트)
3. 차체 제작(에이전트)
4. 내가 렌더를 보고 판정
5. 사용자가 보고 지적 (NSX 뒷면, 루프 라인, A필러 등)
6. 고치기
7. 등록, 핸디캡 측정, 게시

품질 문제는 대부분 4~5단계에서 잡혔다. 사람이 볼 때까지 아무도 못 잡은 것이다.

## 자동화할 수 있는 것과 없는 것
| 단계 | 자동화 | 방법 |
|---|---|---|
| 자료 수집 | **어렵다** | 이 세션의 네트워크에서 Sketchfab, 위키백과 등이 막혀 있다. 사진과 도면은 계속 사용자가 주는 것이 가장 확실하다 |
| 시트 측정 | 가능 | 도면의 원근과 눌림을 바퀴로 확인하고, 축마다 배율을 정해 윤곽을 따는 지금 방식을 도구로 고정한다 |
| 차체 제작 | 가능 | 에이전트. 지시서를 고정 양식으로 만든다 |
| **형상 검증** | **가능, 효과가 가장 크다** | 아래 '자동 검사' |
| **닮음 판정** | **부분적으로 가능** | 별도의 검수 에이전트가 렌더와 참고 자료를 나란히 보고 차이를 목록으로 낸다. 만든 에이전트가 아니라 다른 에이전트가 해야 자기 결과를 좋게 보는 경향이 줄어든다 |
| 최종 판단 | **사람** | "닮았나", "이 차 같은가"의 마지막 판단은 계속 사용자가 한다 |
| 등록·측정·게시 | 가능 | 이미 스크립트가 있다. 한 명령으로 묶는다 |

## 자동 검사 (`tools/ref/carcheck.ts`, 만들 것)
차 하나에 명령 하나로 아래를 돌리고, 숫자와 비교 그림을 낸다.
1. **윤곽 일치도:** 시트의 옆, 평면, 정면, 후면 윤곽과 메시 윤곽이 겹치는 비율(IoU)과 최대 오차(mm). 예: 0.95 이상, 오차 40 mm 이하면 통과.
2. **참고 렌더 대조:** 사용자가 준 정사영 렌더에 메시 윤곽을 겹친 그림. 원근은 NSX·F355 때 쓴 카메라 맞춤을 도구로 만든다.
3. **표면 검사:** 면적 0 삼각형, 뒤집힌 면, 패널 사이 틈(가장자리 점이 짝이 없는 곳), 같은 자리 겹친 면(z-fighting).
4. **바퀴 검사:** 바퀴로 잡힌 부품이 바퀴 부품뿐인지(검토 146 버그 재발 방지).
5. **하이라이트 검사:** 실시간 렌더러로 3/4 두 장을 찍어, 한 패널 안에서 밝기가 계단처럼 끊기는 곳을 찾는다(규칙 127).
6. **예산과 등록:** 삼각형 수, 팝업 램프와 렌즈 이름 규칙, 물리 테스트, 핸디캡 완주.

## 파이프라인
```
자료(사용자) → 시트 에이전트 → [시트 자동 검사]
             → 차체 에이전트 ⇄ [자동 검사] (통과할 때까지, 최대 N회)
             → 검수 에이전트(다른 모델 또는 새 에이전트): 참고 자료 대비 차이 목록
             → 차체 에이전트가 목록 수정 → [자동 검사]
             → 사람 검토(비교 그림 한 장) → 등록·측정·게시(한 명령)
```
- 지시서와 규칙(문서 70의 규칙, NSX·디아블로 지시서)을 고정 양식 하나로 만든다. 저장소의 `.claude/skills/car-build/`에 두면 차마다 같은 품질 기준이 적용된다.
- 실행은 Workflow(여러 에이전트를 정해진 순서로 돌리는 기능)로 묶을 수 있다. 사용자가 "workflow로 해 줘"라고 하면 쓸 수 있다.

## 기대 효과와 한계
- **기대:** 지금까지 사용자가 잡아 준 문제 중 약 절반은 자동 검사나 검수 에이전트가 먼저 잡을 수 있었다. 윤곽, 틈, 바퀴 조각, 계단 무늬, 루프 라인 굴곡이 그렇다. 뒷면 구조 같은 "디자인이 다르다"는 문제는 검수 에이전트가 일부를 잡는다.
- **한계:**
  - 자료가 부족하면 어떤 자동화로도 닮게 만들 수 없다.
  - 검수 에이전트도 틀릴 수 있다.
  - 비용이 는다. 검수와 수정 한 바퀴에 약 10~20만 토큰이다. 대신 사용자가 지적하고 다시 만드는 횟수가 줄어든다(NSX 뒷면 다시 만들기 약 19만).

## 단계 제안
1. `carcheck.ts` 자동 검사 도구를 만들고, 기존 5대(EB110, XJ220, 디아블로, NSX, F355)에 돌려 기준선을 잡는다. 문제가 나오면 목록으로 정리한다.
2. 지시서 양식과 `car-build` 스킬을 만든다.
3. F355 Fable 재제작을 이 파이프라인의 첫 시험으로 돌려, 수동으로 할 때와 품질과 토큰을 비교한다.
