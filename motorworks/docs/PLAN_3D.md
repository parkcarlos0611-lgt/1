# MotorWorks 3D 전환 계획 — 차량 3D 모델링 · 3D 엔진 설계

목표: 현재 2D(측면·평면) 차량 디자인을 **실시간 3D 모델링**으로 바꾸고, 엔진도 **3D로 보면서 설계**한다.
기준선은 Automation의 차량 디자이너(차체 모핑 + 부착물 배치)와 엔진 디자이너이며, 그 위에
MotorWorks 고유의 것(실측 청사진 기반 틀, 패널·강판·성형 한계, 플랫폼, 생산 공정)을 3D에 그대로 연결한다.

## 0. 핵심 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 렌더링 | **Three.js (WebGL2)**, cdnjs에서 로드 | 빌드 없는 현재 구조 유지, 브라우저·휴대폰에서 실행 |
| 차체 생성 | **절차적 로프트**: 청사진의 측면·평면·정면 윤곽 → 단면(station) 곡선 → 표면 메시 | 손으로 만든 메시 없이도 모든 틀이 3D가 됨. v0.3의 기준점(랜드마크)·슬라이더·범위 제약을 그대로 3D에 적용 |
| 시뮬레이션 | `src/sim/`은 그대로 (DOM·3D 무관). 3D는 **형상 데이터의 또 다른 표현** | 물리·경영·밸런스 점검(`simcheck.js`)이 깨지지 않음 |
| 2D 뷰 | 삭제하지 않고 **도면 뷰**(측면·평면·정면 정사영)로 유지 | 청사진 겹쳐 보기·정밀 편집·저사양 기기 대체 화면 |
| 고품질 메시 | 선택 사항으로 **glTF 차체 가져오기** 지원(나중 단계) | 절차적 로프트의 한계를 넘는 디테일이 필요할 때 |

정직한 한계: Automation의 차체는 아티스트가 손으로 만든 메시다. 절차적 로프트는 **비례·실루엣·면 흐름**은 실차와 맞출 수 있지만,
펜더 볼륨의 미세한 조형 같은 디테일은 정면·후면·평면 청사진의 품질에 좌우된다. "Automation 이상"은
**설계 자유도와 공학 연결(패널·강판·플랫폼·공정·공력)** 에서 노리고, 조형 디테일은 glTF 가져오기로 보완한다.

## 1. 차체 3D 모델

### 1.1 형상 표현
- 좌표: x 전후(앞=0), y 상하(지면=0), z 좌우(중심=0), 단위 mm. 좌우 대칭(반쪽만 생성 후 미러).
- **단면 스테이션**: 차 길이 방향으로 40~60개 위치마다 반쪽 단면 곡선 1개.
  단면 곡선은 `바닥 중심 → 실(로커) → 차체 측면 최대 폭 → 벨트라인(어깨) → 유리 하단 → 루프 모서리 → 루프 중심`의
  이름 붙은 점으로 구성된 스플라인.
- 각 스테이션의 점은 세 도면에서 결정:
  - **측면도** → 그 x에서의 상단 높이(후드·루프·데크), 벨트라인 높이, 하단 높이
  - **평면도** → 그 x에서의 최대 반폭, 루프 반폭(텀블홈)
  - **정면/후면도** → 단면의 모양(어깨 둥글기, 측면 볼록함, 루프 크라운) — 없으면 차체 형식별 기본 단면
- 표면: 스테이션 사이를 Catmull-Rom/B-스플라인으로 보간한 사각 격자 메시(약 60×24 → 필요 시 세분화). 법선은 해석적으로 계산.
- 각진 선(캐릭터 라인, 후드 모서리)은 **크리스 가중치**로 표현(해당 격자선에서 법선을 끊음).

### 1.2 디자인 조작 (v0.3 계획의 3D 확장)
- **슬라이더(기본)**: 후드 높이·길이, 윈드실드 각도, 루프 높이·곡률, 노치↔패스트백, 트렁크 높이, 벨트라인,
  **+ 3D 전용**: 텀블홈(측면 유리 기울기), 어깨 폭, 측면 볼록함, 펜더 플레어(앞/뒤), 루프 크라운, 노즈 평면 곡률, 테일 좁아짐.
- **직접 조작(Automation 방식)**: 3D 뷰에서 차체 부위를 잡아 끌면 그 영역의 기준점이 감쇠(falloff)와 함께 이동.
  모든 이동은 기준 틀 대비 **허용 범위 안에서 멈춤**, 좌우 대칭 유지, 자기 교차·최소 곡률 검증.
- **도면 뷰**: 측면·평면·정면 정사영에서 청사진을 겹쳐 놓고 기준점을 정밀 조정(현재 2D 편집기의 후신).
- 되돌리기/다시하기, 기준 틀로 초기화, 경쟁차 3D 나란히 보기.

### 1.3 개구부·패널
- 휠 아치: 원통 불리언 대신 **격자에서 아치 영역을 잘라내고 테두리(립)를 압출**. 휠 하우스 안쪽 면 생성.
- 유리(DLO): 측면도의 유리 다각형 + 평면도로 윈드실드·측면 유리·뒷유리 메시를 분리 생성, 필러는 차체 색.
- **패널 분할**: 후드·펜더·도어·쿼터·루프·트렁크의 분할선을 표면 위 곡선으로 정의 → 패널별 메시 그룹.
  - 셧라인은 실제 틈(홈)으로 렌더.
  - 패널마다 **강판 재질**(이미 구현된 패널별 소재)을 다른 머티리얼로 표시. "원소재 보기"에서 강판 텍스처가 UV를 따라 입혀짐.
  - 패널의 실제 **곡률·드로잉 깊이를 메시에서 측정**해 성형 한계·스크랩 계산에 사용(현재의 근사식 대체).
  - 도어·후드·트렁크 **열기 애니메이션**(힌지 축).

### 1.4 부착물(픽스처) — Automation의 핵심 기능
- 카탈로그: 헤드램프, 테일램프, 그릴, 범퍼, 흡기구, 배기구, 미러, 도어 핸들, 엠블럼, 몰딩, 스포일러, 루프랙, 와이퍼, 번호판.
  시대별 사용 가능 연도(기존 `intro/mp` 체계 재사용).
- 배치: 차체 표면을 클릭 → 부착물이 **표면에 투영**되어 법선 방향으로 붙음. 이동·회전·크기·좌우 대칭, 격자 스냅.
- 형태: 부착물마다 파라메트릭 메시(예: 원형/각형/랩어라운드 램프) + 표면을 따라 휘는 변형.
- 게임 연결: 그릴·흡기구 면적 → 냉각 성능, 램프 종류 → 안전·원가, 스포일러 → 양력/항력, 크롬 → 원가·고급감.
- 제약: 법규 위치(헤드램프 높이, 번호판), 겹침 금지, 개수 상한(성능·UI 보호).

### 1.5 하부·실내·휠
- 플랫폼 3D: 프레임/플로어팬, 서스펜션 형식별 간략 모델, 구동계, 배기 라인, EV 배터리 팩. **차체 반투명(X-ray) 모드**로 표시.
- 엔진룸: 설계한 3D 엔진이 실제 크기로 들어가고 **간섭 검사**(현재의 길이·폭 비교를 3D 충돌 검사로).
- 실내: 대시보드·시트·스티어링의 간략 모델(유리 너머로 보임), 인테리어 등급에 따라 재질 변경.
- 휠·타이어: 림 지름·폭·편평비대로 생성, 시대별 휠 디자인(스포크 수·형태 파라미터), 브레이크 디스크·캘리퍼, 조향·회전.

### 1.6 재질·조명
- PBR 도장: 솔리드/메탈릭/펄, 클리어코트, 도장 공정 품질 → 오렌지필 노멀맵 강도(공장 도장 공정과 연결).
- 크롬, 유리(틴트·반사), 고무, 무도장 강판·알루미늄·카본(절차적 텍스처 재사용).
- 환경: 스튜디오 HDR(절차 생성 그라디언트 큐브맵), 바닥 반사, 접지 그림자. 시대별 쇼룸 배경(선택).

### 1.7 형상에서 직접 계산하는 값 (3D의 이점)
- 전면 투영 면적(실제 실루엣 렌더로 측정), 표면적(패널 중량), 실내·적재 체적(메시 내부 체적).
- 공력: 1단계는 현재 지표식 유지 + 실측 전면적. 2단계는 단면 분포 기반 압력 항력 추정과 양력(전후 축), 3단계는 간이 패널법.
- 시야각(A필러 사각), 범퍼 높이, 보행자 보호 여유 등 규제 검증을 실제 형상으로.

## 2. 엔진 3D

### 2.1 파라메트릭 부품 생성
설계 변수(보어·스트로크·기통 수·레이아웃·뱅크각·헤드 형식·밸브 수 등)에서 부품 메시를 코드로 생성:

| 부품 | 변수 반영 |
|---|---|
| 블록 | 보어 간격·기통 수·레이아웃(I/V/수평대향/W)·뱅크각·데크 높이, 재질(주철/알루미늄) |
| 크랭크샤프트 | 스트로크, 크랭크 핀 위상(크로스플레인/플랫플레인), 카운터웨이트, 재질 |
| 커넥팅로드·피스톤 | 로드 길이, 보어, 피스톤 형상(압축비), 재질 |
| 헤드·밸브트레인 | 사이드밸브/OHV(푸시로드·로커)/SOHC/DOHC, 기통당 밸브 수, 캠 프로파일(로브 형상), 가변밸브 장치 |
| 타이밍 | 체인/벨트/기어, 캠 스프로킷 |
| 흡기 | 카뷰레터(1·2·4배럴, 멀티), 인젝터 레일, 스로틀 바디, 매니폴드 러너 길이 |
| 과급 | 터보(컴프레서·터빈 하우징, 배관), 슈퍼차저, 인터쿨러 |
| 배기 | 로그 매니폴드/튜블러 헤더(등장), 촉매 |
| 보기류 | 배전기/코일, 발전기, 워터펌프, 오일팬, 플라이휠 |
| EV | 모터(고정자·회전자), 인버터, 감속기, 배터리 모듈 |

### 2.2 보기 모드
- **외관**(주조 질감, 도색 밸브 커버), **컷어웨이**(단면 평면을 끌어 이동), **분해도**(부품이 축 방향으로 펼쳐짐), **X-ray**.
- **작동 애니메이션**: 크랭크 회전에 맞춘 피스톤·로드·밸브·캠 운동(실제 점화 순서·캠 타이밍), rpm 슬라이더, 슬로모션.
  연소 플래시, 흡배기 흐름 표시(선택).
- 부품을 클릭하면 인스펙터에서 그 부품의 설계 항목으로 이동(3D ↔ 속성 연결).
- 응력·한계 시각화: 피스톤 속도·밸브 서징·노킹 위험이 큰 부품을 색으로 표시.

### 2.3 게임 연결
- 엔진의 3D 외형 치수 = 엔진룸 간섭 검사에 쓰는 실제 크기.
- 토크 곡선·다이노 그래프는 3D 뷰 옆에 유지, rpm 스윕 때 엔진 애니메이션과 동기화.
- (선택) Web Audio로 기통 수·점화 순서·배기 형식 기반 엔진음 합성.

## 3. 화면 구성
- 디자인 작업공간의 중앙이 3D 뷰포트(궤도 회전·줌·팬, 터치 지원). 뷰 전환: 3D / 측면 / 평면 / 정면 / 4분할.
- 표시 모드: 도장 / 원소재(강판) / 패널 색 구분 / 곡률 맵(성형 난이도) / X-ray(플랫폼·엔진) / 공력.
- 오른쪽 인스펙터는 현재 구조 유지(차체 · 패널 · 부착물 · 파워트레인 · 섀시 · 실내 · 트림).
- 공장 화면: 탑뷰 2D 유지, 이후 라인 위 차체를 3D 썸네일로 대체.
- 경쟁사 차량도 같은 생성기로 3D 표시, 언론 평가·쇼룸에 3D 스틸 컷.

## 4. 기술 구조

```
src/geo/          순수 기하 (DOM·Three 무관, Node에서 테스트 가능)
  loft.js           도면 → 스테이션 단면 → 표면 격자
  constraints.js    기준점 범위·대칭·교차 검증
  panels.js         패널 분할·곡률/드로잉 깊이 측정
  measure.js        전면적·표면적·체적
  enginegeo.js      엔진 부품 파라메트릭 형상
src/r3d/          Three.js 표현
  scene.js          렌더러·조명·환경·카메라
  bodymesh.js       격자 → BufferGeometry, 머티리얼
  fixtures.js       부착물 카탈로그·표면 투영
  enginemesh.js     엔진 조립·애니메이션·컷어웨이
  interact.js       선택·드래그·기즈모
src/render/       기존 2D (도면 뷰·공장·저사양 대체)
```

- 성능 목표: 데스크톱 60fps, 휴대폰 30fps. 차체 약 3만 삼각형, 부착물·휠 포함 장면 15만 이하, 엔진 10만 이하. 형상 재생성은 변경된 스테이션만.
- WebGL 불가 기기: 2D 도면 뷰로 자동 대체.
- 저장: 형상은 계속 **수치 데이터(기준점·슬라이더·부착물 목록)** 로 저장 → 저장 파일 크기 작게 유지, 구버전 2D 설계는 기본 단면을 붙여 자동 변환.

## 5. 단계별 일정

| 단계 | 내용 | 결과물 |
|---|---|---|
| A. 기반 | Three.js 도입, 스튜디오 장면, 궤도 카메라, 기존 16개 틀을 기본 단면으로 로프트 | 모든 기존 차가 3D로 보임 (색·유리·휠 포함) |
| B. 차체 완성 | 휠 아치·유리·패널 분할·셧라인, PBR 도장, 슬라이더·범위 제약, 도면 뷰 | 3D에서 틀 + 범위 안 디자인 |
| C. 부착물 | 램프·그릴·범퍼·미러 등 카탈로그, 표면 배치, 시대별 목록, 게임 수치 연결 | Automation식 외관 꾸미기 |
| D. 엔진 3D | 블록·크랭크·피스톤·헤드·밸브트레인 생성, 작동 애니메이션, 컷어웨이·분해도 | 3D 엔진 설계 화면 |
| E. 통합 | 엔진룸 간섭, 플랫폼·하부 X-ray, 형상 실측(전면적·체적·패널 곡률), 경쟁사 3D | 3D가 시뮬레이션에 연결됨 |
| F. 다듬기 | 직접 끌기 조작, 실내, 도어 열기, 쇼룸, 엔진음, glTF 가져오기, 성능 최적화 | |

A~B가 끝나면 2D 디자인 화면을 3D로 교체하고, C·D는 서로 독립이라 순서를 바꿀 수 있다.

## 6. 청사진 요청에 미치는 영향
3D에서는 **측면도 + 평면도 + 정면도(가능하면 후면도)** 가 모두 있어야 실차와 맞는 단면을 만들 수 있다.
- 측면만 있는 차: 차체 형식별 기본 단면을 사용 → 실루엣은 맞지만 정면·3/4 뷰는 근사.
- 4면도가 있는 차: 단면까지 추적해 실차 비례를 재현.
`docs/BLUEPRINTS.md`의 파일 규격을 "측면 필수, 평면·정면 강력 권장"으로 올린다.

## 7. 위험과 대응
| 위험 | 대응 |
|---|---|
| 절차적 로프트의 조형 품질 한계(펜더 볼륨, 복합 곡면) | 단면 점 수를 늘리고 정면·후면 도면 추적, 부족한 차종은 glTF 가져오기 |
| 휴대폰 성능 | LOD, 부착물 인스턴싱, 그림자 품질 단계, 2D 대체 화면 |
| 표면 위 부착물 변형의 깨짐 | 부착물 크기 상한, 곡률 큰 곳 배치 제한, 평면 근사 대체 |
| 작업량 | A→B→(C,D)→E 순으로 각 단계가 독립적으로 플레이 가능한 상태가 되게 진행 |
| 저장 호환 | 형상은 수치로만 저장, 버전 마이그레이션 함수 |
