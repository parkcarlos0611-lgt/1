# 검토 14 — 차량 제작의 현황과 단계

기획자 질문(2026-11-19)에 대한 검토다. 적용한 것은 없다. 맨 끝의 결정 사항에 답을 받으면 시작한다.

질문은 두 가지다.
- 계획 단계에서 세운 로드맵에 비추어 차량 제작이 어디까지 와 있는가.
- 도면에서 프레임·섀시·바퀴·엔진·변속기·구동계·연료 탱크를 구상하고, 카탈로그로 부품을 주문하고, 도면대로 차체를 만들고, 조립하고, 운행 시험을 하는 흐름이 계획에 잡혀 있는가.

## 1. 로드맵과 지금

재설계 계획(REBOOT_PLAN 9장)은 "단계 1의 시제품 5가지가 모두 승인되면 단계 2(수직 슬라이스)로 간다"였다.

| 단계 1 시제품 | 통과 기준 | 지금 |
|---|---|---|
| ① 차체 → 400px 픽셀아트 | 세단·로드스터·리무진 3대를 기획자가 승인 | 2차 시제품까지 만들었다. 승인받지 못했다. 측면만 있다 |
| ② 계산 물리 | 0-60, 최고속, 제동, 연비, 무게가 당시 실제 차 범위 안 | 시작하지 않았다. 1차 판의 계산 코드(엔진·섀시·구동·치수, 약 430줄)는 `legacy/sim/`에 그대로 있다 |
| ③ 400px 부품·배경 | 엔진 1개와 공방 장면 1장 승인 | 시작하지 않았다 |
| ④ 탑뷰 주행 | 새 실시간 물리, 스프라이트 스태킹, 조향 안정, 휴대폰 60fps | 시작하지 않았다 |
| ⑤ UI 틀 | 공통 부품, 창 관리, 자동 검사 | 책상 화면 1차가 있다. 공통 틀과 자동 검사는 없다 |

단계 1을 끝내지 않고 단계 2의 시스템(시간, 사람, 돈, 공급, 판매, 신문, 날씨, 은행)으로 넘어갔다.
참고 이미지를 만드는 동안 게임 시스템 구상을 먼저 하기로 한 결정에서 시작했지만, 그 뒤로 차 쪽 시제품으로 돌아오지 않았다. 이것이 "차 제작이 묻힌다"는 느낌의 직접 원인이다.

## 2. 질문하신 흐름이 계획에 있는가

04 문서(차량 프로젝트)의 7단계에 줄기는 잡혀 있다: 기획 → 설계 → 조달 → 목업 → 시제작·시험 → 수정 → 출시.
그러나 줄기만 있고, 아래 표의 대부분은 계획이 한 줄이거나 없다.

| 흐름 | 계획 문서 | 구현 |
|---|---|---|
| 도면에서 프레임·섀시를 구상 | "섀시(구매/자작)" 한 줄. 프레임 형식, 축간거리, 윤거를 정하는 화면은 계획에 없다 | 없음. 주문 종류 3가지(차체만, 사 온 섀시, 자체 섀시)로만 구분 |
| 바퀴·엔진·변속기·구동계·연료 탱크를 도면에 배치 | 1차 판에 "요소 배치 레이어"가 있었고 활용하기로 했다. 새 설계 문서에는 옮겨 적지 않았다 | 없음 |
| 배치에 맞는 엔진과 부품을 카탈로그로 주문 | 03 문서에 공급사 카탈로그가 있다. 다만 "엔진 1종, 변속기 1종"의 묶음이다. 배기량·마력·무게·치수가 다른 엔진 여럿 중에서 고르는 카탈로그는 계획에 없다 | 공급사 12곳, 부품 12가지(등급만 다름). 엔진의 제원은 없다 |
| 도면대로 차체를 만듦 | 04 문서의 9공정, 목업, 손 판금 공정 하나 | 9공정이 시간 게이지로 돈다. 도면과 공정이 이어지지 않는다 |
| 부품 조립 | 9공정 안의 섀시·동력계·부속 공정 | 시간 게이지뿐이다 |
| 운행 시험 | 04 문서 5단계, 시제품 ④(탑뷰) | 없음 |
| 손님 요구에 맞는지 판정 | 02 문서에 "꼭 원하는 것" | 약속만 하면 지킨 것이 된다 |

결론: 큰 줄기는 계획에 있으나, 질문하신 수준의 구체적인 흐름(도면 위 배치 → 제원 있는 부품 카탈로그 → 도면과 이어진 제작 → 시험)은 계획에 빠져 있거나 한 줄뿐이다. 계획부터 다시 세워야 한다.

## 3. 다시 세우는 차량 제작 흐름 (제안)

1차 판에서 가져오는 것: 실측 기준 차와 패널 데이터, 3층 편집(비례·부품·패널), 요소 배치 레이어의 생각, 계산 공식(엔진·섀시·구동·치수).

```
요구서 → 도면(배치) → 부품표 → 카탈로그 주문 → 섀시 조립 → 차체 제작 → 결합·마감 → 시험 → 수정 → 인도
```

| 단계 | 플레이어가 하는 일 | 보이는 것 | 계산되는 것 |
|---|---|---|---|
| 1 요구서 | 손님의 요구를 항목으로 받는다(자리 수, 지붕, 짐, 지상고, 속도, 조용함, 값, 날짜) | 요구서 한 장 | — |
| 2 도면: 하체 | 프레임 형식(사다리꼴, X자 보강), 축간거리, 윤거, 지상고를 정한다. 사 온 섀시면 고르기만 한다 | 측면도와 평면도(400px), 하부도 | 무게, 강성, 실내 길이 |
| 3 도면: 배치 | 엔진, 변속기, 구동축, 뒤차축, 연료 탱크, 라디에이터, 예비 바퀴를 도면에 놓는다. 서로 겹치거나 차체 밖으로 나가면 안 된다 | 부품이 도면 위에 실제 치수로 놓인다 | 무게 배분, 무게중심, 발 공간, 짐칸 |
| 4 도면: 차체 | 기준 차에서 시작해 비례·부품·패널을 바꾼다. 하체와 배치가 차체 안에 들어가야 한다 | 400px 측면, 그리고 평면·정면 | 공기 저항, 차체 무게, 판금 공수 |
| 5 부품표와 수치 | 도면이 부품표와 예상 성능·원가·공수를 만든다. 요구서의 항목마다 맞는지 표시된다 | 요구서 대조표 | 최고속, 가속, 제동, 연비, 소음, 원가 |
| 6 카탈로그 주문 | 제원이 적힌 카탈로그에서 엔진·변속기·차축·바퀴를 고른다. 도면의 자리에 맞아야 한다 | 카탈로그 쪽(그림, 마력, 무게, 치수, 값, 납기) | — |
| 7 섀시 조립 | 프레임에 부품을 단다. 공정마다 그림이 채워진다 | 하부도와 측면도가 단계별로 완성된다 | 조립 품질 |
| 8 차체 제작 | 목형 → 목골조 → 판금(직접 하는 공정) → 접합 → 도장 | 뼈대 → 판 → 칠로 차가 달라진다 | 공정 품질, 결함 |
| 9 결합·마감 | 차체를 섀시에 얹고 내장·부속을 단다 | 완성된 차 | 완성차 품질 |
| 10 시험 | 공방 앞길과 언덕에서 달려 본다 | 처음에는 수치와 사이드뷰 장면, 뒤에 탑뷰 주행 | 실제 성능(도면 값과 다를 수 있다), 결함 발견 |
| 11 수정 | 찾은 결함을 고친다. 도면을 고치면 다음 차부터 반영된다 | — | — |

- 소규모 공방의 첫 주문은 "차체만"이다. 2·3·6·7단계는 손님 섀시가 정해져 있어 건너뛴다. 사 온 섀시, 자체 섀시로 갈수록 단계가 열린다. 그래서 처음부터 전부 배우지 않아도 된다.
- 지금의 시스템과 이어지는 곳: 부품표 → 공급 시스템, 공수 → 작업표, 품질·결함 → 인도 장면과 평판, 요구서 대조 → 만족도.

## 4. 참고 이미지 200종의 쓰임

기획자가 만든 것: 1930년대·1940년대 실제 차 기반 200종. 한 장에 2종, 앞·뒤·좌·우·위·아래와 기반 차 이름.

| 쓰임 | 내용 |
|---|---|
| 실측 기준 차 늘리기 | 지금 기준 차는 9종이다. 여섯 방향이 있으므로 측면뿐 아니라 평면·정면·하부의 윤곽을 딸 수 있다. 탑뷰 주행(스프라이트 스태킹), 배달 컷신의 정면, 하부 배치도에 필요한 것이 모두 여기서 나온다 |
| 하부도 | 프레임과 구동계 배치의 본보기가 된다(3장의 2·3단계) |
| 경쟁사와 길 위의 차 | 플레이어가 짓지 않는 차는 윤곽을 따지 않고 그림을 그대로 줄여 쓸 수 있다 |

지켜야 할 것과 한계:
- 상표: 이미지에 실제 엠블럼과 차 이름이 들어 있다. 게임에 쓸 때는 엠블럼을 지우고 이름을 지어 붙인다. 원본 이미지는 저장소에 올리지 않는다(이미 정한 규칙).
- 치수: 만든 그림이라 방향마다 비율이 조금씩 다를 수 있다. 기준 차로 쓸 때는 알려진 제원(축간거리, 전장, 전폭)에 맞춰 보정해야 한다. 제원은 자료로 확인해야 한다.
- 분량: 한 대의 패널 윤곽을 따는 데 품이 든다. 200종을 모두 편집 가능한 기준 차로 만드는 것은 한 번에 할 수 없다. 슬라이스(미국, 1930~1935)에 필요한 12종쯤을 먼저 하고 나머지는 그림으로 쓰다가 차례로 옮긴다.
- 아직 이미지를 받지 않았다. 세션에 올려 주시면 처리 도구(시트 나누기 → 방향별 자르기 → 엠블럼 지우기 → 치수 보정 → 윤곽 따기 보조)부터 만든다.

## 5. 단계 제안

| 순서 | 작업 | 통과 기준 |
|---|---|---|
| A | 참고 이미지 처리 도구와 기준 차 3종(세단, 로드스터, 실용차)의 여섯 방향 윤곽 | 기획자가 400px 측면·평면·정면을 보고 승인 (시제품 ①의 마무리) |
| B | 계산 물리 옮기기(시제품 ②): 엔진·섀시·구동·치수 공식을 TS로, 표는 JSON으로 | 1930년대 차 3종의 수치가 당시 자료 범위 안 |
| C | 요구서와 도면 화면: 하체 → 배치 → 차체, 요구서 대조표 | 손님 요구 하나를 도면으로 맞추는 한 바퀴 |
| D | 제원 있는 부품 카탈로그와 주문(공급 시스템에 연결) | 도면의 자리에 맞는 엔진을 골라 주문 |
| E | 도면과 이어진 제작: 공정마다 그림이 달라짐, 판금 직접 하기 | 한 대가 뼈대에서 완성까지 눈에 보임 |
| F | 시험(수치 + 사이드뷰 장면)과 결함 수리, 인도 전 점검 | 시험에서 결함을 찾아 고쳐서 인도 |
| G | 탑뷰 주행(시제품 ④), 배달 컷신 | 휴대폰에서 직접 몰아 보고 승인 |

구인·인사, 경쟁사, 잡지는 F 뒤로 미룬다.

## 6. 결정이 필요한 것

1. 5장의 순서(A~G)로 갈지.
2. 참고 이미지를 먼저 몇 종 올려 주실지. (추천: 슬라이스용 미국 1930~1935년 차 12종쯤. 세단, 쿠페, 로드스터, 실용차가 섞이게)
3. 플레이어가 짓지 않는 차(경쟁사, 길 위의 차)는 엠블럼을 지운 그림을 그대로 줄여 쓰는 것. (추천: 그렇게)
4. 도면의 배치(3장 3단계)를 어디까지 자유롭게 할지: 부품을 자유로이 옮기는 방식 / 정해진 자리 몇 군데에서 고르는 방식. (추천: 정해진 자리에서 고르고 앞뒤로만 조금 옮기기. 자유 배치는 검증할 경우가 너무 많다)
5. 차체 2차 시제품의 그림 방향 승인 여부. 참고 이미지를 받은 뒤 A에서 다시 보여 드리고 그때 정해도 된다.

## 7. 추가 검토 — 제공 이미지의 활용과 1차 판 코드의 이전 (2026-11-19)

### 7-1. 견본 시트 한 장으로 실제로 재 본 것

| 항목 | 결과 |
|---|---|
| 방향 나누기 | 투명 배경이라 여섯 방향이 자동으로 나뉜다 |
| 해상도 | 받은 견본은 1312×1199이고 측면이 폭 448px이다. 5 m = 400px 규격(12.5 mm/px)으로는 약 0.78배 줄이면 된다. 원본이 더 크면 더 좋다 |
| 축간거리 | 측면에서 바퀴 중심을 재어 전장 기준으로 환산하면 2,823 mm가 나왔다. 기억하는 실제 값은 2,845 mm다(자료 확인 필요). 차이 1% 안 |
| 방향 사이의 비율 | 측면·평면·하부의 길이는 서로 1~4% 안에서 맞는다. 정면·후면은 다른 배율로 그려져 있고, 높이와 폭은 방향에 따라 10~20% 어긋난다 |
| 픽셀아트 변환 | 측면을 350×147로 줄이고 28색으로 줄였다. 그대로 게임 그림으로 쓸 만하다 |

- 치수는 측면을 기준으로 잡고, 정면·후면·평면은 알려진 제원(전장, 전폭, 전고, 축간거리)에 맞춰 방향별로 배율을 보정해야 한다.
- 로고: 휠캡, 라디에이터 장식, 예비 바퀴 덮개, 그릴에 있다. 자리를 표시하면 민무늬로 덮어 그릴 수 있다. 자리를 찾는 일은 차마다 눈으로 확인해야 한다.
- 시트 아래의 "Based on ..." 글자는 잘라 내고, 차 이름은 처리 목록(저장소 밖)에만 둔다.

### 7-2. 그대로 쓸 수 있는 곳과 없는 곳

| 쓰임 | 그대로 쓸 수 있는가 |
|---|---|
| 경쟁사 차, 길 위의 차, 신문·잡지 그림, 카탈로그 | 된다. 로고를 지우고 줄여서 쓴다 |
| 탑뷰 주행의 차(평면 그림) | 된다. 다만 스프라이트 스태킹(층층이 쌓기)은 높이별 단면이 필요해 평면 한 장으로는 안 된다. 평면 그림 + 그림자로 시작한다 |
| 배달 컷신의 측면·정면 | 된다 |
| 하부도 | 프레임·구동계 배치 화면의 본보기와 배경으로 쓴다 |
| 플레이어가 고쳐 짓는 차 | 그림 그대로는 안 된다. 패널을 옮기거나 바꾸려면 윤곽 데이터가 있어야 한다 |

플레이어가 고치는 차에 대한 두 가지 길:

| 길 | 내용 | 장단점 |
|---|---|---|
| 윤곽 데이터 | 그림을 대고 패널 윤곽을 따서 지금의 400px 그리기에 넣는다 | 3층 편집이 다 된다. 차 한 대마다 품이 든다. 그린 결과가 원본 그림보다 단순하다 |
| 그림 변형 | 원본 그림을 조각(앞머리, 객실, 꼬리, 펜더, 바퀴)으로 나눠 늘이고 바꿔 끼운다 | 원본의 품질이 그대로 남는다. 비례와 부품 교체까지는 된다. 패널을 손으로 고치는 3층째는 어렵다 |

두 길의 그림이 한 화면에 섞이면 화풍이 달라 보일 수 있다. 견본 3종으로 두 길을 모두 만들어 나란히 보고 정하는 것을 권한다.

### 7-3. 1차 판의 차량·엔진·변속기 코드가 얼마나 넘어왔는가

| 코드 | 내용 | 새 프로젝트로 |
|---|---|---|
| 실측 기준 차 9종의 패널 데이터 | 측면 윤곽 | 넘어왔다(`data/cars/`, `tools/importLegacy.ts`) |
| 차체 그리기와 3층 편집 | 25 mm/px → 400px로 새로 만듦 | 넘어왔다(`render/car/`). 승인 전 |
| `legacy/sim/engine.mjs` | 엔진 설계 모형: 형식(직렬 4·6·8, V8, V12), 밸브 형식, 재료, 보어·행정·압축비·캠·기화기 → 출력 곡선, 마력, 토크, 내구, 개발비 | 안 넘어왔다. 그대로 돌아간다 |
| `legacy/sim/calibrate.mjs` | 실제 엔진 10종과 대조 | 안 넘어왔다. 지금 돌려 보면 가장 큰 오차가 16%다(목표 10%) |
| `legacy/sim/chassis.mjs` | 현가, 댐퍼, 조향, 타이어 → 승차감·조종성 수치 | 안 넘어왔다 |
| `legacy/sim/drive.mjs` | 변속기, 기어비 제안, 가속·최고속 계산 | 안 넘어왔다 |
| `legacy/sim/dims.mjs` | 차급별 치수 한계 | 안 넘어왔다 |
| `legacy/game/assembly.mjs` | 조립 단계별 그림(차체를 벗긴 모습 등) | 안 넘어왔다. 옛 해상도 |
| `legacy/game/engdraw·gbdraw·chassdraw·cutaway·engview` | 엔진·변속기·섀시 그림, 단면도 | 안 넘어왔다. 옛 해상도라 400px로 다시 그려야 한다. 치수와 구조의 논리는 쓸 수 있다 |

### 7-4. 차 이름으로 크기와 성격을 알 수 있는가

- 알 수 있다. 이름과 연식이 있으면 전장·전폭·전고·축간거리·무게·엔진과, 성격(대중 세단, 고급 세단, 쿠페, 로드스터·스포츠, 경주차, 왜건, 상용)을 표로 만들 수 있다.
- 다만 값은 내 기억에서 나온다. 널리 알려진 차는 믿을 만하지만 드문 차와 차체 변형은 틀릴 수 있다. 표에 차마다 확신 정도를 적고, 낮은 것은 자료로 확인하거나 그림에서 잰 비율로 견준다(7-1처럼 축간거리와 전장의 비가 맞는지).
- 이 표가 게임의 차급, 손님 유형과의 짝, 경쟁사 차의 값과 성격, 연도별 등장 순서의 바탕이 된다.
