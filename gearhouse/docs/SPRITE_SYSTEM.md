# GEARHOUSE — 스프라이트 & 렌더링 시스템 명세 (v0.1)

목표: **모든 차량 요소를 스프라이트 단위로 분해**하고, 반복·늘리기·회전·미러·팔레트 교체로
**적은 원화에서 수천 가지 조합**을 만든다. 차량 하나는 5개 뷰(좌측면·우측면·탑·프론트·리어)로 그려지며,
5개 뷰는 하나의 데이터 모델에서 투영된다.

---

## 1. 좌표계 & 5뷰 투영

### 1.1 차량 좌표 (단위 mm, 원점 = 앞 차축 중심의 지면)

```
        +Z (위)
         │
         │      +X (차 앞쪽)
         │    ↗
         │  ↗
         └──────────► +Y (차의 왼쪽)
```

모든 부품은 차량 좌표에 **한 번만** `(x, y, z)` + 크기 `(sx, sy, sz)` + 뷰별 스프라이트 키로 배치된다.

### 1.2 뷰별 투영

| 뷰 | 화면 가로 ← 차량 축 | 화면 세로 ← | 깊이(그리기 순서) | 비고 |
|---|---|---|---|---|
| 좌측면 (L) | -X (차 앞이 화면 왼쪽) | Z | +Y 가 가까움 | 기본 편집 뷰 |
| 우측면 (R) | +X (차 앞이 화면 오른쪽) | Z | -Y 가 가까움 | L을 미러 + **비대칭 오버레이** |
| 탑 (T) | -X (앞이 위) → 화면 세로 | Y → 화면 가로 | +Z 가 가까움 | 루프·후드·트렁크 패널, 패키징 확인 |
| 프론트 (F) | -Y (차의 왼쪽이 화면 오른쪽) | Z | +X 가 가까움 | 전면 투영 면적 계산 |
| 리어 (B) | +Y | Z | -X 가 가까움 | |

- 스케일: **기준 1px = 10mm (1x 아틀라스)**, 2x 아틀라스는 1px = 5mm. 차 길이 4.5m → 1x에서 450px.
- 정사영이므로 원근 없음. 입체감은 셰이딩 스프라이트와 하이라이트 레이어로 표현.

### 1.3 좌/우측면 비대칭 처리

우측면은 기본적으로 좌측면 레이어를 **수평 미러**해서 그리되, 다음 요소는 `side: "L" | "R" | "both"` 속성으로 따로 그린다:

- 연료 주입구 도어 (탱크 필러 넥 위치에 따라 좌/우 결정)
- 스티어링 휠·운전석 위치 (LHD/RHD — 수출 시장 대응, 창문 너머로 보임)
- 배기 머플러/테일파이프 (한쪽 출구일 때)
- 안테나, 사이드 미러(초기 시대는 운전석 쪽 1개만), 스페어 타이어(사이드마운트)
- 엠블럼/데칼 문자 (미러하면 글자가 뒤집히므로 항상 개별 렌더)

## 2. 실루엣 (Silhouette) 에셋

실루엣은 "차의 겉껍데기 모양 + 그 안에 무엇을 어디에 넣을 수 있는지"를 정의하는 **마스터 에셋**이다.

### 2.1 실루엣 구성 요소

| 요소 | 형식 | 용도 |
|---|---|---|
| 외곽 마스크 (뷰별 5개) | 벡터 스플라인 → 런타임 래스터 알파 마스크 | 강판 클리핑, 전면 면적 계산, 부품 클리핑 |
| 패널 영역 (Panel Region) | 마스크 내부 폐곡선 | 후드/루프/도어/앞·뒤 펜더/트렁크/사이드실/필러 — 영역별 소재·도색 지정 |
| 패널 라인 | 스플라인 | 도어 틈새·후드 라인 등 (선 굵기 = 소재 `panelFit`) |
| 유리 영역 (Greenhouse) | 폐곡선 | 앞/뒤 유리, 측면 창 분할(필러 위치) |
| 휠 아치 | 중심 + 반지름 + 형태 | 타이어 최대 크기 제한, 펜더 스커트 슬롯 |
| **부품 슬롯 (Slot)** | 앵커 + 허용 박스 + 허용 태그 | 헤드램프, 그릴, 범퍼, 테일램프, 미러, 도어핸들, 주입구, 엠블럼, 라이선스 플레이트 등 |
| **패키징 박스** | 3D 박스 (차량 좌표) | 엔진베이, 캐빈, 트렁크, 연료탱크 후보 위치, 스페어 위치, 배터리 |
| 스타일 라인 | 스플라인 | 벨트라인, 캐릭터 라인, 루프 엣지 — 크롬 몰딩·투톤 분할·스트라이프 경로 |
| 모프 핸들 | 파라미터 → 컨트롤 포인트 가중치 | 길이·폭·높이·루프 높이·후드 길이·오버행 조정 |
| 메타데이터 | JSON | Era, 차종, 도어 수, 좌석 수, 기본 Cd, `wheelbaseRange`, `trackRange`, 허용 엔진 배치, 스타일 태그 |

### 2.3 "수백 종" 실루엣 확보 전략

| 방법 | 설명 | 비중 |
|---|---|---|
| **파라메트릭 생성기** | 차종별 "기본 골격 템플릿"(펜더 형태·그린하우스·후드 길이·오버행 비율·루프 곡률 파라미터) × 시대 스타일 프리셋 → 실루엣 후보 자동 생성 | 후보의 70% |
| 수작업 다듬기 | 생성 결과를 실루엣 에디터에서 컨트롤 포인트 수정, 슬롯·패키징 박스 검수 | 전체 품질 보증 |
| 수작업 시그니처 | 시대를 대표하는 특이 형태(극단적 테일핀, 유선형 패스트백 등) | 10~15% |
| 런타임 모프 | 실루엣당 허용 범위 내 연속 변형 → 체감 종류는 수천 가지 | — |

**목표 수량**: 7 Era × 차종 평균 8종 × 변형 5~7개 ≈ **300~400 실루엣** (출시 시), 차종 목록:
로드스터, 2도어 쿠페, 2도어 세단, 4도어 세단, 리무진, 왜건/에스테이트, 컨버터블, 해치백(E4~), 패스트백, 쿠페 유틸리티, 픽업, 밴/미니버스, 오프로더/SUV, 마이크로카/경차, 스포츠/GT, 미니밴(E6~).

## 3. 레이어 스택 (그리기 순서)

한 뷰는 아래 레이어 순서로 합성된다. **(사용자 워크플로 순서 = ①실루엣 → ②강판 → ③기계 → ④외장 → ⑤도색)** 와 레이어 순서는 다르다:
기계 부품은 일반 모드에서 차체 아래에 숨고, X-ray 모드에서만 차체 위로 올라온다.

```
L13  UI 오버레이       : 슬롯 하이라이트, 치수선, 충돌(겹침) 경고, 무게중심 마커
L12  FX               : 반사 하이라이트, 크롬 스펙큘러, 헤드램프 점등 글로우, 배기 연기
L11  노화/오염 (옵션)   : 녹(소재 corrosion 기반 위치·확률), 먼지, 탈색
L10  데칼·엠블럼        : 로고, 스트라이프, 번호판
L9   외장 부품(가까운 쪽): 헤드램프, 그릴, 범퍼, 미러, 도어핸들, 크롬 몰딩, 테일핀, 스포일러
L8   유리 & 창틀        : 유리 틴트, 창틀(크롬/블랙/바디색), 실내 실루엣(시트·스티어링 휠·탑승자 그림자)
L7   도색(Paint)       : 패널 영역별 색 (곱하기 합성) + 투톤 분할 + 메탈릭 플레이크
L6   강판(Panel)       : 소재 텍스처를 실루엣 패널 영역에 클리핑, 패널 라인
L5   휠(가까운 쪽)      : 타이어, 림, 허브캡, 브레이크(디스크/드럼 보임)
L4   하부/노출 기계      : 배기 테일파이프, 머플러 일부, 서스펜션 하부, 러닝보드
L3   [X-ray시 L9 위로]  : 엔진, 변속기, 구동축, 디프, 서스, 연료탱크, 라디에이터, 배터리, 스페어
L2   섀시 프레임         : 프레임 레일, 크로스멤버 (X-ray / 플랫폼 설계실에서만)
L1   휠(먼 쪽)          : 측면뷰에서 반대편 바퀴 (어둡게, 대부분 가려짐)
L0   지면 그림자
```

X-ray 모드: L6~L10을 30% 불투명 + 외곽선만 남기고, L2·L3을 그 위에 그린다.

### 3.1 각 레이어는 "뷰별 서브 레이어 캔버스"로 베이크

- 부품 변경 시 해당 레이어 캔버스만 재합성(dirty flag) → 최종 합성 캐시.
- 테스트 트랙 애니메이션은 "차체 베이크 1장 + 휠 2장(회전) + 서스펜션 오프셋"만 움직이므로 가볍다.

## 4. 강판(소재) & 도색 합성

"실루엣 안에 강판을 씌워 넣는다"를 2D에서 다음과 같이 구현한다.

```
 소재 텍스처(그레이스케일 타일)   ──┐
                                 ├─ 실루엣 패널 영역 마스크로 클리핑 (source-in)
 패널 셰이딩 맵(볼륨감 그라디언트) ──┘
             │
             ▼
     강판 레이어 (명도 + 질감 + 패널 라인)
             │   × (multiply)
     도색 색상 (그라디언트 맵 / 팔레트 램프)
             │   + (screen)
     스펙큘러 하이라이트 (소재 등급별 선명도)
             ▼
          최종 차체
```

| 소재 등급 | 텍스처 | 패널 라인 | 하이라이트 | 노화 |
|---|---|---|---|---|
| 1 최하급 | 굴곡 노이즈 큼(오렌지필), 이음 리벳 | 넓고 불균일 (3px@1x) | 흐릿·물결 | 녹 빠름, 휠아치·실부터 |
| 3 중급 | 약간의 노이즈 | 보통 (2px) | 보통 | 보통 |
| 5 최고급 | 매끈 | 가늘고 균일 (1px) | 선명한 한 줄 반사 | 거의 없음 (알루미늄은 녹 없음, FRP는 균열 표현) |

- **패널 셰이딩 맵**은 실루엣마다 1장(뷰별): 위쪽 밝고 아래쪽 어두운 볼륨 그라디언트 + 캐릭터 라인 하이라이트. 소재와 독립이므로 재사용됨.
- **도색**: 시대별 팔레트(JSON 색 목록) + 무광/유광/메탈릭(플레이크 노이즈 타일 추가)/펄(시점 대신 위치 기반 색상 시프트).
- **투톤/스트라이프**: 실루엣의 스타일 라인(벨트라인·루프·사이드 스피어)을 분할선으로 사용해 패널 영역을 둘로 나누고 각각 색 지정. 스트라이프는 스타일 라인을 따라 흐르는 스트립 스프라이트.

## 5. 스프라이트 재활용 기법 (공통 도구)

모든 부품 스프라이트는 아래 7가지 "조립 기법" 중 하나 이상으로 그려진다. 엔진·섀시·외장 모두 같은 렌더 함수 세트를 공유한다.

| 기법 | 설명 | 예 |
|---|---|---|
| **Repeat (반복)** | 모듈 스프라이트를 축 방향으로 N번 타일 | 실린더, 헤드 캠커버 세그먼트, 흡기 러너, 리프 스프링 장수, 코일 감김 수, 그릴 바 |
| **Radial (회전 반복)** | 중심 기준 N개 회전 복제 | 휠 스포크, 와이어 휠, 볼트 패턴, 팬 블레이드, 계기판 눈금 |
| **3-slice / 9-slice (늘리기)** | 끝단 보존 + 중간만 늘림 | 프레임 레일, 범퍼 블레이드, 구동축, 머플러, 연료탱크, 오일팬, 캠커버, 라디에이터 코어 |
| **Path strip (경로 따라 그리기)** | 스플라인을 따라 스트립 텍스처 변형 | 크롬 몰딩, 창틀, 배기관, 고무 웨더스트립, 스트라이프, 연료 호스 |
| **Bone (두 점 사이 늘리기)** | 두 하드포인트 사이 회전·스케일 | 위시본 암, 트레일링 암, 타이로드, 쇼크업소버, 스태빌라이저 링크 |
| **Mirror (대칭)** | X 또는 Y축 반전 | 좌우 헤드램프, V엔진 뱅크, 수평대향 반대 뱅크, 좌/우측면 뷰 |
| **Tint / Palette swap** | 그레이스케일 원화 + 색 램프(LUT) | 도색, 렌즈 색(레드/앰버/클리어), 크롬 vs 블랙 트림, 소재 색조, 엔진 커버 색 |
| **Pattern fill (패턴 채우기)** | 타일 패턴을 임의 도형에 클리핑 | 그릴 인필(세로바/에그크레이트/메시/가로바), 램프 렌즈 패턴, 시트 직물, 라디에이터 핀 |

> 원칙: **원화 1장 = 기능 단위 1개.** "V8 엔진" 원화는 존재하지 않는다. "V형 뱅크용 OHV 실린더 모듈 1기통" 원화가 있고, 규칙이 V8을 만든다.

## 6. 모듈형 엔진 스프라이트

### 6.1 모듈 카탈로그 (각 모듈 × 3뷰: 측면/정면(엔드)/상면)

| 그룹 | 모듈 | 조립 규칙 |
|---|---|---|
| 블록 | `block.cyl` (1기통 블록 단면), `block.endF` (타이밍 커버), `block.endR` (벨하우징 플랜지) | `endF + cyl×N + endR` 반복. cyl 폭 = 보어 + 벽두께, 높이 = 스트로크×k + 데크 |
| 크랭크케이스/오일팬 | `sump` | 3-slice, 길이 = 블록 길이 |
| 헤드 | `head.sv` (사이드밸브 평판), `head.ohv.seg`, `head.sohc.seg`, `head.dohc.seg` | 실린더마다 seg 반복 + 양 끝 캡. DOHC는 엔드뷰에서 캠커버 2개 |
| 캠/로커 커버 | `cover.*` (시대 스타일: 리브형, 매끈, 크링클 도장, 로고판) | 3-slice로 헤드 길이에 맞춤, 틴트로 색 지정 |
| 점화 | `plug`, `coil`, `distributor`, `plugwire` | 실린더당 반복, 배선은 Path strip |
| 흡기 | `intake.runner`, `intake.plenum`, `carb.1bbl/2bbl/4bbl/side`, `fi.throttle`, `aircleaner.*` | 러너 실린더당 반복, 플레넘 3-slice, 캐브 개수는 설정(1·2·N/2·N)에 따라 균등 배치 |
| 배기 | `exh.runner`, `exh.log` (주철 통 매니폴드), `exh.header.4-1`, `exh.header.4-2-1` | 러너 반복 → 컬렉터. 이후 배기관은 Path strip으로 차체 후방까지 |
| 과급 | `turbo.small/large`, `sc.roots`, `sc.centrifugal`, `intercooler` | 앵커(배기 컬렉터 / 흡기 플레넘 위)에 부착 |
| 보기류 | `pulley`, `belt`(Path strip), `alternator/dynamo`, `waterpump`, `fan`(Radial 블레이드), `oilfilter` | 엔드뷰 앞면 앵커에 배치 |
| 로터리 | `rotor.housing`, `rotor.end` | 로터 수만큼 반복 |

### 6.2 레이아웃별 조립

```
[직렬 N]  측면뷰:  ▕F▏■■■■■■▕R▏          (cyl 모듈 N개 일렬)
          엔드뷰:      ▲  1개 단면 (기울기 slant 각 적용 가능)
          상면뷰:  ▕F▏□□□□□□▕R▏

[V N]     엔드뷰:     ╲   ╱     두 뱅크: 단면을 ±V각/2 회전, 크랭크 중심 공유
                       ╲_╱
          상면뷰:  ▕F▏□□□□▕R▏   좌뱅크
                   ▕F▏ □□□□▕R▏  우뱅크 (콘로드 나란히 → 반 보어만큼 오프셋)
          측면뷰:  가까운 뱅크만 보이고 먼 뱅크 헤드 윗부분이 살짝 겹쳐 보임

[수평대향] V각 = 180° 의 특수 경우: 엔드뷰 좌우 대칭(Mirror), 높이 낮음 → 무게중심↓

[로터리]  rotor.housing × 로터 수 (1~3)
```

- **V각 회전 + 뱅크 오프셋 + 미러**만으로 V6/V8/V10/V12/V16이 같은 모듈에서 나온다.
- 엔진 **물리 치수 = 조립 결과 바운딩 박스(mm)**. 이 값이 엔진베이 패키징 박스에 들어가는지 검사 → GDD §5.2.

### 6.3 장착 방향에 따른 뷰 재매핑

엔진은 자체 3뷰(엔진 측면·엔드·상면)를 갖고, 차량 뷰에 **장착 방향대로 재매핑**된다.

| 장착 | 차량 측면뷰에 보이는 것 | 차량 프론트뷰 | 차량 탑뷰 |
|---|---|---|---|
| 종치 (front_long / mid / rear) | 엔진 측면 | 엔진 엔드 | 엔진 상면 |
| 횡치 (front_trans) | 엔진 엔드 | 엔진 측면 | 엔진 상면 90° 회전 |

같은 원화가 장착 방향만 바꿔 전부 재사용된다.

### 6.4 엔진 조립 데이터 예시

```json
{

  "layout": "V", "cylinders": 8, "vAngle": 90,
  "head": "ohv", "valves": 2, "blockMat": "castiron",
```

## 8. 외장 부품 스프라이트

부품 = **하위 조각 조합**. 각 조각이 따로 교체 가능하므로 조합 수가 곱으로 늘어난다.

| 부품 | 하위 조각 | 기법 | 슬롯 피팅 |
|---|---|---|---|
| 헤드램프 | 하우징(포드형/매립형/팝업) + 베젤(크롬/바디색) + 렌즈 패턴 + 리플렉터 | Tint, Pattern fill, Repeat(쿼드=2개) | 슬롯 박스 안에서 크기·위치 자유, 박스 초과 불가. `mirrorY` 자동 대칭 |
| 그릴 | 외곽 프레임(9-slice 도형) + 인필 패턴 + 중앙 엠블럼 앵커 | 9-slice, Pattern fill | 그릴 슬롯 + 실루엣 외곽 마스크로 클리핑 |
| 범퍼 | 블레이드(3-slice) + 오버라이더(가드) + 엔드캡 + 고무 스트립 | 3-slice, Path strip | 폭은 슬롯 폭에 자동 맞춤 / E5 대형 범퍼는 크럼플 길이 ↑ |
| 테일램프 | 하우징 도형 + 렌즈 색 구역(적/황/백) + 패턴 | Tint, Pattern fill | 테일핀 앵커와 연동 가능 |
| 창문 | 실루엣 유리 영역에서 자동 + 창틀(Path strip) + 벤트 윈도(E1~E3) + 필러 커버 | Path strip | 실루엣 정의 그대로 |
| 크롬 몰딩 | 스타일 라인 선택 → Path strip | Path strip | 실루엣 스타일 라인만 허용 |
| 미러 | 스템 + 헤드 (원형/사각/공력형) | — | 도어/펜더 슬롯 |
| 도어 핸들 | 돌출형/매립형/플랩형 | — | 도어 패널 내 자동 위치 |
| 테일핀 / 스포일러 / 후드 스쿠프 | 형태 스프라이트 + 모프 | Bone 스케일 | 펜더·트렁크·후드 패널 위 앵커 |
| 펜더 스커트, 러닝보드, 사이드마운트 스페어 | — | 3-slice | 휠아치·실 슬롯 |
| 휠 | 타이어(사이드월 폭 스케일, 화이트월 링 Tint) + 림 배럴 + 스포크(Radial N개) + 허브캡/센터캡 | Radial, Tint | 휠아치 반경으로 최대 지름 제한 |
| 엠블럼 | 로고 에디터 결과 (프레임 + 심볼 + 글자) | 개별 베이크 | 그릴·트렁크·펜더 앵커 |

### 8.1 슬롯 피팅 규칙

1. 부품은 **허용 태그(accept)** 가 맞는 슬롯에만 들어간다.
2. 위치·크기는 슬롯 박스 내부에서만 조정 가능(스냅 + 드래그). 박스를 넘으면 빨간 경고 + 적용 불가.
3. 최종 그리기 시 **실루엣 외곽 마스크로 클리핑** — 부품이 차체 밖으로 삐져나오지 않음(단, 범퍼·미러·스포일러처럼 `allowOutside: true` 부품 예외).
4. `mirrorY` 슬롯은 한쪽 배치 시 반대쪽 자동 생성(해제 가능 — 비대칭 디자인).
5. **뷰 간 동기화**: 부품은 차량 좌표에 저장되므로 프론트뷰에서 헤드램프를 올리면 측면·탑뷰에서도 즉시 올라간다.
6. 패키징 충돌: 기계 부품끼리, 기계 부품과 캐빈/트렁크 박스의 3D 박스 겹침을 검사 → 겹침 부피만큼 실용성 감점 또는 배치 불가.

## 9. 스타일 태그 & 디자인 점수 연동

- 모든 부품·실루엣은 `styleTags`(예: `chrome`, `streamline`, `wedge`, `boxy`, `retro`, `sport`, `luxury`, `utility`)와 `era` 범위를 가진다.
- 디자인 점수 = 비례 점수 + 시대 적합도(부품 era vs 현재 연도) + 태그 조화도(실루엣 태그와 부품 태그 일치율) + 정렬 점수(좌우 대칭, 헤드램프-그릴-범퍼 수평 정렬) + 패널 품질.
- 소비자 집단마다 태그 선호가 다름 (럭셔리층: `chrome`,`luxury` / 매니아: `sport`,`wedge`).

## 10. 아트 스타일 가이드

- 기본: **플랫 일러스트** — 두꺼운 외곽선(1x 기준 2px, 선택 옵션), 3~4단계 셀 셰이딩, 스펙큘러 하이라이트 1줄. cage 프로젝트의 `FlatStyle`/`Outline` 접근과 일관.

- 모든 원화는 **기준 스케일(2x = 1px 5mm)** 로 제작, 앵커 포인트·9-slice 가이드를 메타데이터로 함께 내보냄.

## 12. 렌더러 구현 메모

- Canvas2D: `globalCompositeOperation` 으로 클리핑(`source-in`/`destination-in`), 도색(`multiply`), 하이라이트(`screen`).
- WebGL 경로(선택): 레이어를 텍스처로 올려 한 패스 셰이더 합성(그라디언트 맵, 스펙큘러, 노화 마스크) — cage의 `GPURenderer` 구조 재사용.
- 오프스크린 캐시 키: `hash(차량 데이터 서브트리, 뷰, 스케일)`. 썸네일(세이브 슬롯·시장 화면·라인업 타임라인)은 저해상도 베이크 재사용.
- 경쟁사 AI 차량 수십~수백 대도 같은 파이프라인으로 썸네일 생성(필요 시 Web Worker + OffscreenCanvas).
- 전면 투영 면적: 프론트 뷰 최종 알파 마스크 픽셀 카운트(타이어·미러 포함) × (mm/px)². 해상도 독립 위해 항상 1x 마스크에서 계산.
