# 101 · 알파 0.1 로드맵: 동력계, 차체 편집, 게임 인터페이스와 메뉴 (검토 179)

사용자 요청: (1) 동력계 전체를 Automation 같은 방식으로 만드는 것과 아이디어 보완, (2) M(동력계·서스펜션) → E(차체 편집) 전체 실행 로드맵, (3) 실제 게임 같은 인터페이스와 메뉴 계획. 이 묶음을 **알파 0.1**이라 부른다.

이 문서는 계획이다. 검토를 받은 뒤 순서대로 진행한다.

---

## 0. 알파 0.1은 무엇인가
**"설계하고 시험하는 게임"**이다. 회사 경영(제작 공정, 시장, 돈)은 0.2부터 넣는다(문서 100은 계획으로 보류 중).

| 판 | 핵심 | 내용 |
|---|---|---|
| **알파 0.1** | 설계·시험 샌드박스 | 타이틀과 메뉴, 차 설계(차체·동력계·서스펜션), 엔진 설계, 시험장 측정, 레이스, 차고(설계 보관) |
| 알파 0.2 | 회사 | 제작 공정(문서 100), 개발 단계, 돈과 시간, 3D 회사 허브 |
| 알파 0.3 | 시장 | 손님층, 차종 비율, 판매, 레이스 규정·상금 |
| 알파 0.4 | 클래식 | 1930년대 차 리스토어, 녹·바랜 칠 효과, 경매 |

**0.1 완료 기준**
- 처음 켠 사람이 메뉴에서 시작해 차 한 대를 설계하고, 엔진을 만들어 얹고, 시험장에서 측정하고, 레이스까지 할 수 있다. 설명서는 필요 없다.
- 휴대폰과 PC에서 모두 된다.
- 콘솔 오류가 없다.
- 실차 6대 검산과 전체 테스트를 통과한다.

## 1부. 동력계: Automation 방식과 보완
### 1-1. Automation에서 가져올 것 (방식만 가져오고, 화면과 모양은 우리 것으로 만든다)
- **엔진 설계를 별도 화면으로.** 3D 엔진이 받침대 위에 있고, 부품을 고르면 그 자리에서 모양이 바뀐다.
- **엔진 계열과 변형.**
  - 계열: 블록 배열, 블록 소재, 보어·행정 범위, 헤드와 밸브 형식
  - 변형: 배기량, 캠, 흡기, 연료 공급, 배기, 과급
  - 한 계열에서 변형을 여러 개 만들어 여러 차에 쓴다.
- **엔진 평가표.** 출력·토크 곡선 그래프, 연비, 신뢰성, 소음, 배출가스, 무게, 치수, 원가, 개발 시간.
- **부품별 품질.** 우리의 개발 등급(1~5)은 엔진 전체의 수준이다. 그 위에 부품별 품질을 −3~+3으로 조절한다. 품질이 높으면 신뢰성과 성능이 오르고 원가가 오른다.

### 1-2. 우리 쪽에서 더할 것 (보완)
| # | 아이디어 | 왜 |
|---|---|---|
| ① | **엔진 소리를 설계에서 바로 듣는다.** 배열·실린더 수·점화 순서·흡기·배기로 소리를 합성하고, 설계 화면에서 회전수를 올려 볼 수 있다(`ui/sound.ts`의 엔진 소리를 확장) | 숫자보다 소리가 엔진의 성격을 바로 알려 준다. V12와 플랫 6이 다르게 들린다 |
| ② | **가상 다이노.** 실제 주행 물리와 같은 토크 계산으로 다이노를 돌린다. 곡선이 그려지는 동안 회전수가 오르는 연출을 한다 | 설계값이 곧 주행 성능이라는 신뢰를 준다 |
| ③ | **배기 경로가 차에 맞춰 이어진다.** 매니폴드 → 촉매 → 머플러 → 차의 배기구까지 관이 실제로 연결된다. 배기구 수와 위치는 차체 설계에서 온다 | 엔진이 따로 떠 있지 않고 차의 일부로 보인다 |
| ④ | **엔진룸에 얹힌 상태로 본다.** 차 빌더에서 차체를 반투명이나 절단으로 보면 엔진, 변속기, 배기, 냉각, 서브프레임이 제자리에 있다. 장착 검사에 걸린 부품은 빨갛게 표시된다 | "덩그러니 있음" 문제를 해결한다 |
| ⑤ | **변속기 설계.** 기어 수, 기어비, 종감속을 정하고 "기어별 속도-회전수 톱니 그래프"를 본다. 형식은 트랜스액슬과 일반, 수동과 F1, 클러치 용량 | 기어비가 왜 중요한지 눈으로 보인다 |
| ⑥ | **분해도.** 엔진과 동력계를 부품별로 띄워 보고, 부품을 누르면 이름·사양·품질이 나온다 | 무엇이 무엇인지 배울 수 있다 |
| ⑦ | **시대 제한.** 연료 분사(1980년대 이후), F1 변속기(1997), 가변 밸브(1989 이후) 같은 기술의 등장 연도 | 0.2 연구 체계로 이어진다. 0.1 샌드박스에서는 "연도 제한 끄기"를 고를 수 있다 |
| ⑧ | **엔진 보관함.** 만든 엔진(계열·변형)을 저장하고 차 빌더의 ② 단계에서 고른다. 차 안에서 바로 고치는 것도 여전히 된다 | 엔진 재사용. 0.2에서 개발비와 생산 설비로 이어진다 |

### 1-3. 동력계 부품 목록 (3D로 만들 것)
- **엔진:** 블록(V, 직렬, 수평대향), 헤드와 캠 커버, 흡기(단일 스로틀 플레넘, 가변 흡기, 개별 스로틀 나팔관), 배기 매니폴드(주철 일체, 등장 헤더), 터보·인터쿨러·배관, 풀리와 벨트, 드라이·웨트 섬프, 점화 코일
- **구동계:** 클러치 하우징, 변속기(세로 트랜스액슬 / 가로), 디퍼렌셜, 드라이브샤프트와 등속 조인트, 4륜구동의 센터 디퍼렌셜·프로펠러 샤프트·앞 디퍼렌셜
- **보조:** 라디에이터(앞 또는 옆), 냉각 호스, 오일 쿨러, 연료 탱크, 배터리
- **배기:** 촉매, 중간관, 머플러, 배기구(차체 설계와 연결)
- **차대:** 앞뒤 서브프레임, 엔진 마운트

모든 부품은 설계값으로 만드는 **매개변수 메시**다. 이음매와 예산은 키트처럼 자동 검사한다.

## 3부. 실제 게임 같은 인터페이스
### 3-1. 지금 문제
- 페이지가 따로따로다(주행, 빌더, 메시 보기). 시험 주행이 **새 창**으로 열리고 저장도 페이지마다 다르다.
- 시작 화면과 메뉴가 없다. 켜면 바로 도구 화면이다.
- 페이지마다 버튼 모양과 패널 모양이 조금씩 다르다.
- 불러오는 동안 빈 화면이 보인다.

### 3-2. 해결: 한 페이지 게임 앱
- **하나의 앱, 하나의 렌더러.** 화면을 바꿔도 3D 렌더러와 불러온 텍스처를 그대로 쓴다. 빌더에서 시험장으로 가는 데 새로 불러오기가 없다.
- **화면 이동 체계(라우터).**
  - 각 화면은 `enter / leave` 함수를 가진다.
  - 뒤로 가기(휴대폰 뒤로 버튼, Esc)가 일관되게 동작한다.
  - 화면 사이에 짧은 페이드 전환을 둔다.
- **공통 디자인 체계.**
  - 지금 빌더의 색과 글꼴(Oswald + Noto Sans KR)을 기준으로 한다.
  - 버튼, 탭, 슬라이더, 칩, 카드, 대화상자, 알림(토스트) 컴포넌트를 하나로 만든다.
  - 밝은 화면·어두운 화면 모두 지원한다.
- **불러오기 화면.** 진행 막대와 팁(예: "드라이 섬프는 엔진을 낮게 앉힌다")을 보여 준다.
- **조작.** 마우스·터치·키보드·게임패드(시험장 주행)를 지원한다. 메뉴는 키보드와 패드로도 이동할 수 있다.
- **UI 소리.** 버튼, 전환, 저장에 짧은 소리를 넣는다. 설정에서 끌 수 있다.
- **저장 체계.** 저장 슬롯(설계, 엔진, 측정 기록, 설정), 자동 저장, 내보내기·가져오기를 한곳에서 관리한다.

## 4부. 메뉴 구조 (알파 0.1)
```
[불러오기] → [타이틀]
               ├─ 이어하기 ────────────── 마지막 화면과 설계로
               ├─ 자유 설계 ───────────── [차고]
               │                            ├─ 새 차 설계 → [차 빌더 ①~⑥] ⇄ [엔진 공방]
               │                            ├─ 엔진 공방 → [엔진 설계]
               │                            ├─ 설계 목록(카드: 사진, 수치, 측정)
               │                            └─ 엔진 보관함
               ├─ 시험장 ──────────────── 트랙·측정 프로그램 선택 → [주행]
               ├─ 레이스 ──────────────── 트랙·상대·바퀴 수 → [주행] → [결과]
               ├─ 설정 ────────────────── 그래픽 / 소리 / 조작 / 화면 / 언어 / 저장 관리
               └─ 정보 ────────────────── 버전(알파 0.1), 바뀐 점, 만든 사람·자료 출처
```
- **타이틀 화면:**
  - 3D 차고 배경에 최근 설계한 차가 턴테이블 위에서 천천히 돈다.
  - 게임 이름 GEARHOUSE와 "알파 0.1" 표시를 둔다.
  - 3D 회사 허브(0.2)의 첫 모습이 된다.
- **차고:** 설계 목록을 카드로 보여 준다. 차 사진(렌더 썸네일), 차종, 출력, 최고 속도, 측정 기록이 나온다. 복제, 삭제, 내보내기를 할 수 있다.
- **시험장(측정 프로그램):** 결과를 측정 카드로 저장하고 설계에 붙인다.
  - 0→100, 0→400 m, 최고 속도(Speed Bowl), 100→0 제동, 원선회 횡가속, 랩타임(Millbrook, Ashcombe Park)
- **주행 중 일시정지 메뉴(Esc, 휴대폰은 화면의 일시정지 버튼):**
  - 계속, 다시 시작, 측정 결과, 설계로 돌아가기, 설정, 타이틀로
- **레이스 결과 화면:** 순위, 랩타임, 최고 랩, 차 사진을 보여 준다. 다시 하기와 차고로 가기 버튼을 둔다.
- **설정 통합:** 지금 주행 페이지 서랍(주행, 레이스, 트랙·환경, 카메라, 그래픽, 효과, 차 상태, 소리)을 정리한다.

## 8. 결과: K1(EB110 바탕)과 E1(치수 슬라이더) (알파 0.11)
**K1: EB110 바탕**
- `core/design.ts`의 바탕이 셋이 됐다(`nsx`, `f355`, `eb110`). 코 종류에 `mass`(덩어리 범퍼), 꼬리 종류에 `capsule`(캡슐 꼬리)을 더했다. 코 3 × 앞면 2 × 꼬리 4 × 휠 3이 세 바탕 모두에서 이음매가 닫힌다(`tests/car_design.test.ts`).
  - EB110에 더한 교체: 둥근 코, 뾰족한 코, 램프가 들어간 앞면(모서리에 파묻힌 안개등), 둥근 램프 꼬리, 고정 윙. NSX·F355에 더한 교체: 덩어리 범퍼 코, 캡슐 꼬리.
- `DESIGN_EB110`은 이제 자기 바탕 위에 선다(휠베이스·폭 변경 없음). 물리 바탕값은 실차(1,620 kg, 앞 0.4, 공기 저항 면적 0.58), 엔진룸은 세로 1.52 m. 검산: 무게 1,695 / 1,695, 출력 581 / 553(+5 %), 최고 속도 350 / 342(+2.3 %).
- **윙과 디퓨저를 차체에 그린다.** 윙은 바탕과 꼬리마다 정해진 것이 붙는다(EB110 캡슐 꼬리는 능동 윙: 주행 페이지에서 달리면 올라온다). 디퓨저는 뒤 바닥 아래의 경사판과 핀이다(`render/car/kit/parts/diffuser.ts`).

**E1: 치수 슬라이더**
- 설계 형식 3: 차체에 윤거, 전고, 앞·뒤 오버행, 지상고, 캐빈 위치, 앞유리 각도를 더했다. 형식 2의 설계(저장, 링크)는 이 값이 0인 채로 그대로 열린다.
- 바탕마다 범위가 있다(`BODY_LIMITS`). 범위의 양 끝에서 모든 종류의 패널이 이음매 검사를 통과한다(치수 하나씩 끝값 × 종류 순환, 그리고 모든 치수를 함께 바꾼 무작위 설계 12대).
- 방법: 휠베이스·폭·윤거는 선 체계를 늘인다. 나머지는 다 만든 차체에 하나의 공간 변형(`makeWarp`)을 건다. 같은 점은 같은 곳으로 가므로 이음매가 열리지 않고, 각 단계가 점의 순서를 지키므로 면이 접히지 않는다. 바퀴와 엔진은 통째로 옮기고, 실내는 캐빈과 함께 옮긴다.
- 물리: 앞면적(폭, 전고, 지상고), 공기 저항(앞유리 각도, 뒤 오버행), 무게(길이·폭·높이), 무게중심(지상고, 지붕), 앞뒤 배분(캐빈 위치), 윤거. 요 관성은 주행 물리의 식(무게, 휠베이스, 윤거)을 그대로 쓴다.
- 장착 검사: 캐빈을 앞으로 옮기면 엔진룸이 그만큼 길어진다(해결 수단으로도 나온다). 윤거를 넓히면 아치 여유가 줄고, 차를 낮추면 아치 안 서스펜션 틈이 준다. 지상고 100 mm 미만은 ⚠️(바닥 닿음 위험), 70 mm 미만은 ⛔.
- 맥라렌 F1 검산 차: 전고 1,140(지붕 −30), 오버행 각 −100, 앞유리 +4°로 최고 속도 364 → 368 km/h(−5.7 % → −4.7 %).

## 10. 결과: M3 움직이는 서스펜션 (알파 0.12)
- **실제 링크 기구다.** `render/car/suspension/`에 하드포인트(차대 피벗, 업라이트 볼 조인트, mm)와 그것을 푸는 기구학을 두었다. 아래 팔은 차대 피벗 축을 돌고, 위 팔은 업라이트 길이를 지키는 자리로 가고, 타이로드(뒤는 토 링크)가 길이를 지키며 업라이트의 조향각을 정한다. 캠버와 토는 하드포인트에서 나온다(M4 물리가 같은 하드포인트를 읽는다).
  - `hardpoints.ts`: 바탕별 축 사양(`SUSPENSION`: NSX·F355·EB110 모두 앞뒤 더블 위시본, EB110 뒤는 한쪽에 코일오버 두 개) → 코너별 명시적 점(`Hardpoints`). 맥퍼슨·멀티링크·판스프링 빔 축은 종류 이름만 있고 아직 만들지 않는다.

- **그리기:** 서스펜션 부품은 차 한 대에 그리기 한 번이다. 정점마다 뼈 번호가 있고, 뼈 41개(3×4 행렬)를 셰이더에 넘긴다(`render/live/gpu.ts`의 `susp`, `renderer.ts`의 `uBone`). 바퀴는 업라이트가 데려간 자리에 그린다(캠버와 토는 링크 기구의 값). 디스크는 바퀴와 함께 돌고 캘리퍼는 돌지 않는다.
- **차고(지상고) 치수:** 차체를 올리면 바퀴가 그만큼 팔에 매달려 내려간 자세가 정지 자세가 된다.
- **빌더:** 보기 단추에 "서스펜션 보기"를 더했다. 차체와 휠 면을 떼고(타이어와 림 통은 남김) 네 바퀴가 천천히 오르내리며 앞바퀴가 좌우로 꺾인다.

## 12. 0.12 보완: 주행 카메라와 아날로그 페달 (사용자 의견)
- **"카메라 각도 너무 답답".** 주행 기본 시점을 차 뒤에서 보는 원근 추격 카메라로 바꿨다(`ui/drivecam.ts`, 렌더러에는 원근 투영과 하늘·원경 안개만 더함: `LiveView.eye/fov/near`). 넓은 화각(세로 약 62°, 세로로 든 휴대폰에서는 가로가 최소 62°가 되도록 넓힘), 차 뒤로 멀리·조금 높게, 방향과 높이는 임계 감쇠 스프링으로 늦게 따라오고, 코너에서는 요 레이트만큼 안쪽을 미리 본다. 빠를수록 화각과 거리가 조금 커진다. 땅(뱅크 경사)보다 70 cm 아래로 내려가지 않는다. 차가 화면 아래 컨트롤과 계기에 가리지 않도록 차의 화면 위치를 잰다.
- **시점.** 추격(멀리, 기본) → 추격(가까이) → 보닛 → 운전석(메시에 좌석이 있는 차만) → 시네마틱 → 위에서(기존 정사영). C 키, 화면의 C 단추, 일시정지 메뉴, 설정 → 조작에서 바꾸고 설정(`camera.view`)에 기억한다. 원근 시점에서는 화면을 끌어 차 둘레를 돌려 볼 수 있고 놓으면 돌아온다. 원근 시점에서는 화면 광선 효과(AO·반사)와 피사계 심도를 끈다(정사영 전제).
- **"쓰로틀 형식 액셀레이터".** 터치 가속·브레이크 페달을 위아래로 밀어 쓰는 아날로그 페달로 바꿨다: 손가락 높이 = 열림(아래 끝 0 %, 위 끝 100 %), 채움 막대로 보이고 떼면 0. 브레이크도 같은 방식이고, 멈춘 채 브레이크를 25 % 넘게 0.5초 누르면 후진(기존 규칙). 키보드는 그대로, Shift+↑는 반 가속. 게임패드 트리거(RT 가속, LT 브레이크)와 왼쪽 스틱 조향도 받는다.
- 시험: `tests/drivecam.test.ts`(페달 위치 → 값, 스프링, 화각·조준, 시점 순환, 눈 위치, 설정 저장). 그림: `docs/reference/drive_cam_*.png`.
