# 검토 11 — 날씨와 계절 이벤트

기획자 지시(2026-11-19)에 대한 검토다. 9장의 결정대로 적용했다(`core/weather.ts`, `data/weather/us_midwest.json`).
수치는 모두 제안하는 시작값이고, 미국 중서부의 실제 기후 통계와 대조하지 않았다.

## 1. 지시 내용

- 날씨: 맑음 / 비 / 눈.
- 계절 이벤트: 한파, 폭염, 장마 등.
- 이벤트는 방문 손님 빈도에 영향을 준다.
- 이벤트 하나는 한 달을 넘지 않는다.
- 장마는 여름에 한 번만 온다.
- 이벤트가 끝나면 1~2주 유예를 두고, 그 뒤 확률로 다음 이벤트가 시작된다.
- 지역 신문은 성향에 따라 짧은 날씨·계절 소식을 싣는다. 성향에 따라 싣지 않을 수도 있다.

## 2. 구조 제안

두 층으로 나눈다. 아래층은 매일의 날씨, 위층은 며칠~몇 주 이어지는 계절 이벤트다.

```
WeatherState { today: clear | rain | snow, event?: { kind, start, end }, graceUntil?, longRainYear? }
```

### 2-1. 매일의 날씨

- 아침에 그날 날씨를 뽑는다. 달마다 비·눈 확률이 다르고, 어제 날씨가 오늘로 이어지기 쉽다(같은 날씨일 확률에 가산).
- 이벤트가 진행 중이면 이벤트가 날씨를 정한다(한파 중에는 맑음이나 눈, 긴 비 중에는 대부분 비).

| 달 | 비 | 눈 |
|---|---|---|
| 12~2월 | 5% | 25% |
| 3월 | 20% | 10% |
| 4~5월 | 30% | 1% |
| 6~8월 | 25% | 0 |
| 9~10월 | 20% | 0 |
| 11월 | 15% | 10% |

### 2-2. 계절 이벤트

| 이벤트 | 철 | 기간 | 그동안의 날씨 | 방문 손님 |
|---|---|---|---|---|
| 한파 | 12~2월 | 4~14일 | 맑음, 가끔 눈 | ×0.5 |
| 폭설 | 12~3월 | 2~6일 | 눈 | ×0.3 |
| 긴 비 (장마) | 6~7월, 한 해에 한 번 | 10~24일 | 대부분 비 | ×0.7 |
| 폭염 | 7~8월 | 5~18일 | 맑음 | ×0.75 |
| 가뭄 | 6~9월 | 14~30일 | 맑음 | ×0.9 (농부 손님은 더 준다) |
| 맑은 가을 | 9~10월 | 7~14일 | 맑음 | ×1.15 |

- 이벤트는 한 번에 하나만 진행된다. 기간은 최대 30일이다.
- 이벤트가 끝나면 유예 7~14일을 뽑는다. 유예가 지나면 매일 그 철의 확률로 다음 이벤트가 시작된다(제안: 겨울 4%, 여름 3%, 봄·가을 1.5%).
- 긴 비는 시작한 해를 기록해 그해에는 다시 오지 않는다.
- 이 확률이면 이벤트가 있는 날은 한 해에 50~70일쯤으로 짐작한다. 실행해서 센 값은 아니다.
- 미국 중서부에는 한국식 장마가 없다. 이름은 "긴 비"로 하고, 초여름에 비가 길게 이어지는 것으로 한다. 일본을 넣을 때는 같은 틀에 "장마(梅雨)"와 "태풍"을 넣는다.

### 2-3. 방문 손님에 주는 영향

| 항목 | 제안 |
|---|---|
| 대상 | 직접 찾아오는 손님만 줄인다. 편지와 전화 문의는 그대로 둔다 |
| 평소 날씨 | 비 오는 날 ×0.8, 눈 오는 날 ×0.6 |
| 이벤트 | 위 표의 배수 |
| 다른 배수와의 관계 | 기사 효과와 함께 곱해서 0.5~1.6 제한 안에 둔다. 폭설만 예외로 0.3까지 허용한다 |
| 미뤄진 손님 | 이벤트로 줄어든 방문의 절반은 끝난 뒤 2주 동안 돌아온다 |
| 한 해 총량 | 날씨 때문에 한 해 문의가 줄지 않도록 기본 문의율을 조금 올려 맞춘다. 5년 자동 실행으로 확인한다 |

## 3. 신문의 날씨 소식

- 매체마다 "날씨 소식 성향"(0~1)을 데이터에 둔다. 읍내 주간지는 농사 고장이라 높게(0.7), 뒤에 나올 대도시 신문은 낮게(0.3), 자동차 잡지는 0으로 둔다.
- 그 주에 이벤트가 시작했거나 진행 중이거나 끝났으면, 성향 × 이벤트의 세기 확률로 1~2문장의 소식을 싣는다. 확률에서 떨어지면 싣지 않는다.
- 쓰는 사람은 이름 없는 기자다. 중요도는 1~2다.
- 큰 이벤트(폭설, 2주 넘는 한파·폭염·가뭄)는 기존 주제 "날씨 피해"와 "철 따라"의 3단계 이상 기사로 나온다.

| 소식 | 예 |
|---|---|
| 시작 | "주초부터 수은주가 뚝 떨어졌다. 노인들은 당분간 풀리지 않을 것으로 본다." |
| 진행 | "비가 열흘째다. 장터 길은 수레도 다니기 어렵다." |
| 끝 | "더위가 한풀 꺾였다. 읍내 거리에 다시 사람이 나왔다." |

## 4. 같이 풀리는 문제

지금 가상 기사는 날씨 낱말을 철과 상관없이 뽑는다. 3월 신문에 "한파", 7월 신문에 "폭설"이 나올 수 있다.
날씨 시스템이 생기면 기사의 날씨 낱말을 실제로 진행 중인 날씨에서 가져온다. 날씨가 평범한 주에는 날씨 피해 기사가 나오지 않는다.

## 5. 다른 시스템과의 연결 (이번에 넣을지 결정 필요)

| 연결 | 내용 | 바탕 |
|---|---|---|
| 도장 공정 | 비 오는 날은 도장을 못 한다 | 01 문서 12장에 이미 적혀 있다 |
| 납품 | 폭설 중에는 공급사 납기가 늘어난다 | 지속 조건의 납기 배수를 쓴다 |
| 원하는 차 | 한파 중에는 닫힌 지붕, 맑은 가을에는 접이식 지붕을 원하는 손님이 는다 | 지속 조건의 "원하는 차의 성격"을 쓴다 |
| 길 | 긴 비 뒤에는 "길 사정 악화" 기사가 나오기 쉽다 | 등록부의 도로 |
| 공과금 | 한파 중에는 난방비가 더 든다 | 지속 조건의 공과금 배수 |
| 농가 | 가뭄은 그해 풍작 기사를 막고 농부 손님을 줄인다 | 지속 조건의 고객 유형별 문의 |
| 화면 | 공방 창밖의 하늘과 빛, 달력의 날씨 그림 | 화면 단계에서 |

## 6. 검토 의견

| 항목 | 의견 |
|---|---|
| 필요성 | 높다. 하루하루가 달라 보이고, 기사·손님·공정이 한 원인으로 묶인다 |
| 날씨를 3가지로 두는 것 | 충분하다. "흐림"은 효과가 없어 넣지 않는다 |
| 유예 1~2주 | 좋다. 이벤트가 겹치거나 연달아 오는 것을 막는다. 다만 겨울에는 한파와 폭설이 번갈아 와도 자연스러우므로 겨울만 유예를 5~10일로 줄이는 것을 제안한다 |
| 방문 손님만 줄이는 것 | 권한다. 편지 문의까지 줄이면 겨울 석 달이 통째로 비어 초반 자금이 버티지 못한다 |
| 미뤄진 손님 | 권한다. 날씨가 손님을 없애지 않고 시기를 옮기는 것이 실제와 가깝고, 밸런스 영향이 작다 |
| 신문 성향 | 매체 데이터에 숫자 하나를 더하면 된다. 다른 매체에도 그대로 쓴다 |
| 실제 기상 사건 | 1930년 가뭄, 1934·1936년 폭염, 1936년 2월 한파, 1937년 오하이오강 홍수가 있었다. 현실 기사와 묶어 그 시기에 이벤트를 강제로 일으킬 수 있다. 날짜는 기억에 따른 것이라 현실 기사 검증 때 함께 확인해야 한다 |
| 재현성 | 하나의 난수로 뽑으므로 같은 씨앗이면 같은 날씨다. 저장에는 오늘 날씨와 진행 중인 이벤트만 넣는다 |
| 위험 | 연결을 한꺼번에 다 넣으면 밸런스 원인을 가려내기 어렵다. 1차는 날씨·이벤트·방문 손님·신문·기사 낱말까지만 넣고, 5장의 연결은 다음에 넣는 것을 권한다 |

## 7. 넣는 순서 제안

1. 날씨 데이터와 매일의 날씨, 계절 이벤트(유예, 긴 비 한 번 규칙), 저장과 시험
2. 방문 손님 배수와 미뤄진 손님, 5년 자동 실행으로 총량 맞추기
3. 신문의 날씨 소식(성향)과 기사 날씨 낱말 연결
4. 5장의 연결 중 고른 것

## 8. 결정이 필요한 것

1. 날씨가 줄이는 대상을 "직접 찾아오는 손님만"으로 할지, 모든 문의로 할지.
2. 이벤트를 6가지(한파, 폭설, 긴 비, 폭염, 가뭄, 맑은 가을)로 할지, 지시한 3가지(한파, 폭염, 긴 비)만 할지.
3. 미뤄진 손님(이벤트가 끝난 뒤 절반이 돌아옴)을 넣을지.
4. 겨울의 유예를 5~10일로 줄일지, 모두 7~14일로 둘지.
5. 5장의 연결 가운데 이번에 넣을 것(도장 공정, 납품, 원하는 차, 길, 공과금, 농가).
6. 실제 기상 사건을 그 시기에 강제로 일으킬지(검증은 현실 기사 검증 때 함께).

## 9. 결정과 적용 결과 (2026-11-19)

| 번호 | 결정 |
|---|---|
| 1 | 직접 찾아오는 손님만 줄인다 |
| 2 | 이벤트는 6가지로 한다 |
| 3 | 이벤트가 막은 방문의 절반은 끝난 뒤 14일 안에 돌아온다 |
| 4 | 겨울만 유예를 5~10일로 줄인다 |
| 5 | 이번에는 방문 손님, 신문 소식, 기사의 날씨 낱말까지만 넣는다. 5장의 연결은 되도록 빨리 이어서 넣는다 |
| 6 | 실제 기상 사건은 현실 기사 검증 때 함께 넣는다 |

적용하면서 정한 것:
- 날씨 배수는 기사 효과의 배수와 따로 걸린다. 날씨는 방문에만, 기사 효과는 전체 문의에 걸리기 때문이다. 날씨 배수 자체는 0.3~1.6으로 자른다.
- 날씨 때문에 한 해 문의가 약 10% 줄어, 기본 문의율을 약 10% 올렸다. 5년 자동 실행 60회: 문의 122건, 파산 9회, 끝 현금 약 13,900달러(날씨 넣기 전 115건, 9회, 약 14,100달러).
- 읍내 주간지의 날씨 소식 성향은 0.7, 자동차 잡지는 0이다.
- "날씨 피해"와 "철 따라" 주제는 날씨가 평범한 주에는 나오지 않는다. 다만 제목에 날씨 낱말이 없는 틀("대홍수" 등)은 아직 철을 가리지 않는다.
